各产品职责清楚分开。Web AI 负责规划；Cloudflare 提供稳定公网 MCP/OAuth 入口；herdr-mcp 负责本机访问边界；Herdr 保存持续运行的现场；浏览器扩展只在需要连续工作时补回程通道。

推理

继续用你已经在用的 Web AI

ChatGPT 保持主要规划入口，不需要为了本机执行把所有任务再转交给另一套模型或 Agent 循环。

持续

对话结束，开发现场继续

仓库、worktree、终端、服务和 Agent 可以继续运行，之后从另一个会话或设备重新接回。

并行

小任务直接做，大任务再派 Agent

读取、Patch、Git、测试直接调用确定性工具；独立或长任务再分给可替换的本机 Coding Agent。

推荐安装方式

把一句话发给 Coding Agent。

Agent 会先读完整安装协议，再安装 Herdr 与原生 runtime、部署 Cloudflare Edge 和 Link。只有登录、Token、ChatGPT 授权这类必须本人完成的身份步骤才交给你。

请帮我安装并配置 Herdr 和 herdr-mcp。先完整阅读并严格执行 https://raw.githubusercontent.com/whshang/herdr-mcp/main/docs/i18n/zh-CN/agent-install.md 。本机 herdr-mcp runtime 使用 GitHub Releases，不要 git clone。只在 Cloudflare 登录/API Token，以及 ChatGPT 添加 herdr 应用/Connector 授权这两类必须我本人操作的步骤暂停，其余步骤自动完成并验证。

生态与架构

已经有 Coding MCP、远程 Worker、tmux、ACP 和 Codex Bridge，为什么还要 Herdr-MCP？

它们解决的入口和状态模型不同。Herdr-MCP 专注 Web-first planner + 持久、可观察、可人工接管的真实开发现场。
