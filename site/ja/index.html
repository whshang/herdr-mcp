Web AI が計画 · ローカル現場は永続 · ブラウザ経路は任意

考える場所はブラウザに。作業はあなたのコンピュータに。

Herdr-MCP は ChatGPT などの Web AI に、実在するファイル、Git、コマンド、ターミナル、coding Agent への境界付きアクセスを与えます。Herdr は会話、デバイス、長時間タスクをまたいで開発現場を生かし続けます。

プロダクトの境界は明示したままにします。Web AI が計画し、Cloudflare が安定した公開 MCP/OAuth 入口を提供し、herdr-mcp がワークステーションのアクセス境界を強制し、Herdr が永続 runtime 状態を所有します。拡張はブラウザ連続性が有用なときだけ戻り経路を追加します。

推論の再利用

すでに使っている Web AI をそのまま使う

ChatGPT を主要な planning surface として維持し、ローカル実行のためだけに別のローカルモデルや Agent ループへ全タスクを通す必要はありません。

永続性

会話が終わっても現場は残る

リポジトリ、worktree、ターミナル、サービス、Agent は会話が終わっても、別のデバイスが引き継いでも動き続けます。

並列性

小さな作業は直接ツール、大きな作業は Agent

読み取り、patch、Git、テストは直接実行します。独立した作業や長時間の作業は交換可能なローカル coding Agent に任せます。

推奨セットアップ

coding Agent に一文を渡すだけ。

Agent が権威あるインストールプロトコルを読み、Herdr とネイティブ runtime をインストールし、Cloudflare Edge と Link をデプロイします。停止するのは、あなた自身の操作が必要な identity 手順だけです。

Herdr と herdr-mcp をインストールして設定してください。まず https://raw.githubusercontent.com/whshang/herdr-mcp/main/docs/i18n/ja/agent-install.md を最初から最後まで読み、そのとおりに実行してください。ローカルの herdr-mcp runtime は GitHub Releases からインストールし、git clone は使いません。私自身が Cloudflare へサインインして API Token を作成する場面と、ChatGPT に herdr Connector/アプリを追加する場面だけ停止してください。それ以外はすべて自動化して検証してください。

アーキテクチャの風景

Coding MCP、リモート Worker、tmux、ACP、Codex Bridge があるのに、なぜ Herdr-MCP なのか？

それぞれが最適化している入口と状態モデルが違います。Herdr-MCP は Web-first の planning と、永続・観測可能・人間が引き継げる実際のワークステーションの組み合わせに集中します。
