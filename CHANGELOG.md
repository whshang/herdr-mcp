# Changelog

- Rust runtime **0.4.2** closes the release-blocking control-plane reliability work from the 0.4.1 dogfood incident. Local and CI release validation now share one environment-scrubbed gate; the Herdr dependency supervisor distinguishes missing/unhealthy sockets and performs bounded self-healing; request-owned subprocesses are bounded/reaped; macOS doctor separates Documents/TCC diagnostics from Herdr transport health; tagged macOS publishing is fail-closed on the stable Developer ID identity instead of treating ad-hoc development signatures as production evidence.
- Rust runtime **0.4.2** keeps measured execution improvements narrow. Capability deep-probe cache misses use bounded parallelism while warm paths remain unchanged; direct Git/ripgrep paths stay direct because measured latency did not justify a broad rewrite; progressive Skills remain opt-in because changing the default would change the frozen epoch-2 public response contract.
- Rust runtime **0.4.2** adds explicit Store/Dev browser-extension ownership without widening Native Messaging trust. Store and one unpacked Dev extension may coexist in Chrome, while the managed manifest always authorizes exactly one exact active origin. `native-host dev enable [PATH]`, `native-host use store|dev`, and `native-host dev disable` switch the active owner transactionally and preserve rollback evidence; an existing 0.4.1 Dev identity is retained through upgrade instead of being silently replaced.
- Rust runtime **0.4.2** also hardens the real `0.4.1 -> 0.4.2` updater transition for that Dev identity. A pre-dual-mode Rust wrapper that lacks the remembered Dev-origin line is migrated only when the wrapper already targets the managed binary, its active origin exactly matches the structurally-owned manifests, the cohort is complete, and no recovery transaction is pending. The migration rewrites only the wrapper identity contract, preserves manifest bytes and existing Native Host rollback evidence, then synchronizes the active runtime binary; foreign, partial, conflicting, or already-incompatible cohorts fail closed instead of being silently treated as “not installed”.
- Documentation for **0.4.2** separates active product truth from historical evidence, trims the architecture roadmap, and replaces locale-entry redirects with real `/docs/en/` and `/docs/zh-CN/` product homepages. The new docs IA leads with Agent-assisted install, the Cloudflare and ChatGPT Connector handoff points, optional browser continuity, safety boundaries, search, same-slug language switching, and a separate history/evidence lane.
- Browser extension source **0.1.76** adds the coexistence-side owner gate required by the 0.4.2 Native Messaging lifecycle. The inactive sibling build is rejected by Chromium's exact-origin admission and exits before page listeners, Queue ownership, HUD, or shared-stream side effects; a cold MV3 owner probe retries boundedly and then fails closed. This does **not** rewrite the already-submitted Chrome Web Store **0.1.75** candidate, whose review/install lifecycle remains independent.
- Browser extension **0.1.73** completes the first trusted Browser Control Plane action path behind Issue #57. Side Panel `Prompt Agent` now executes through Native Messaging and an extension-only Unix-socket route, reusing Rust `agent.prompt` target fencing, persistent idempotency, delivery evidence, and explicit uncertain outcomes. `Steer Session` is a real provider-steer request/probe but never disguises Prompt as steer: Codex currently reports `session_not_resolved` until Herdr can prove the pane's app-server endpoint, `threadId`, and active `expectedTurnId`. `/push/state` and pane lifecycle events now carry runtime-authoritative `target_revision` plus control capabilities. Arbitrary Herdr methods and raw Terminal Input remain preview-only. The same release documents the already-shipped reliability layer: shared SSE, request dedupe, MutationObserver/render coalescing, bounded output/memory pressure signals, 429 backoff, evidence-first timeout recovery, and durable force-reload cooldowns that prevent reload loops.

- Browser extension **0.1.72** moves Manual handoff into the page HUD, matching its current-web-conversation scope, and removes the duplicate Side Panel action. Handoff remains available with Auto on when its safety gates are satisfied. The normal path still asks the current web model for the continuity packet, while hard conversation-limit signals, failed submissions, or a settled primary-summary timeout fall back to the configured OpenAI-compatible LLM using a bounded source transcript; the existing packet validation, target creation, binding migration, and continuity commit remain unchanged.


- Rust runtime **0.4.1** adds evidence-backed `herdr-mcp scan` inventory for delegation without duplicating Herdr's live-agent detector. The scan unions Herdr `agent.list`, loaded `server.agent_manifests`, and the installed Herdr CLI's own start-kind declaration, then records local executable/version/headless evidence with explicit source/authority metadata. `herdr_inspect.capability_inventory.available_agents` exposes only locally startable kinds permitted by the existing Agent visibility policy.
- Rust runtime **0.4.1** also makes Chrome Web Store Native Messaging identity Store-first without hard-coding the Store ID in Rust. `contracts/browser-extension-store.json` is the single machine-readable identity SSOT embedded and validated by the binary; normal `native-host install` uses it, unpacked development requires an explicit `HERDR_EXTENSION_PATH`, and an existing herdr-mcp-owned development origin migrates transactionally with rollback evidence.

Runtime GitHub Releases no longer attach an extension ZIP, stale `~/.config/herdr-mcp/extension` / checkout paths no longer auto-select a development identity, and `bin/herdr-extension-host` is now only a compatibility delegate to the Rust `native-host` / `extension-host` commands. ## 0.3.32 — 2026-08-24

- Browser extension **0.1.61** dynamically owns the tab title as `status-workspace-conversation` for ChatGPT, z.ai and DeepSeek, refreshing both the runtime state/workspace prefix and the site's native conversation name without recursively rewriting its own title. Saved `Auto on` is now distinct from effective automation: every automatic wake/progress/LLM-continue and automatic handoff stage performs a fresh local Herdr runtime check, the HUD/title reports `offline` when `127.0.0.1:8772` is unavailable, and all full-auto continuation/recovery actions fail closed until the runtime is reachable again. The saved Auto preference is preserved so automation can resume after recovery; the existing explicit manual-handoff path remains independent.
- Browser extension **0.1.60** bounds long-conversation browser work: ChatGPT streaming no longer drives a full turn scan on every `characterData` mutation, mutation bursts are coalesced through a tested scheduler, hidden tabs suspend route/health/HUD/turn sampling until visible again, and the persistent permission watcher no longer reacts to arbitrary `style` churn. The turn watcher now caches the latest user/assistant elements, performs one combined history rediscovery only after structural changes, and reuses the just-settled turn for incremental context-pressure accounting instead of rescanning the whole mounted conversation at every turn end. A fixed-window O(1) `ui_pressure` meter records mutation rate, sampler rate and timer drift (with optional Long Tasks as diagnostics only) without changing rollover correctness yet. After a handoff is durably committed, an inactive retired source tab is best-effort discarded (never closed) so Chromium can reclaim its page runtime without making memory reclamation part of continuity correctness.
- Browser extension **0.1.59** makes ChatGPT workspace binding Project-scoped instead of conversation-scoped. A workspace can now be bound directly from `https://chatgpt.com/g/<project>/project` before any `/c/<id>` exists; the stable `project_id` owns the persistent binding while `active_conv_key` identifies only the current delivery target. Visiting another conversation in the same Project does not steal that target unless its tab is actually active, and handoff keeps the same Project binding/`continuity_id` while switching only the confirmed target conversation. `https://chatgpt.com/` also supports a tab-scoped pending binding that migrates once when that tab first enters a concrete Project or conversation. Conversation-only recovery/LLM/rollover watchers remain disabled on root and Project-home pages.
- Browser extension **0.1.58** makes handoff preserve the source automation state instead of forcing an Auto-off workflow. Manual handoff remains available on bound ChatGPT Project and persisted z.ai conversations whether Auto is on or off; the transfer snapshots the effective source Auto state, suppresses automatic source wakes while summary/seed cutover is active, and commits the target binding plus inherited Auto state together after seed confirmation. ChatGPT Project handoff therefore preserves the shared Project state, while z.ai copies the conversation-scoped Auto preference into the new chat.
- Browser extension **0.1.57** makes manual ChatGPT Project handoff delivery-aware. A controlled-editor `insert-failed` / `submit-failed` result is no longer treated as proof that the seed was never delivered: the extension probes the target tab for the exact transfer marker (including a complete `HERDR_HANDOFF_V1` packet), commits immediately when the target conversation already materialized, and otherwise records `seed_uncertain` instead of discarding the transfer. Older failed seed transfers can resume in place, and if the user provisionally rebound the exact same workspace set on the target while recovery was pending, the confirmed transfer atomically adopts that target slot, restores the original `continuity_id`, records `handoff_from`, and removes the source binding instead of opening a third conversation.
- Browser extension **0.1.56** recognizes ChatGPT's in-stream disconnect placeholder (for example, `连接已中断。正在等待完整回复` / `connection interrupted`) as a bounded recovery signal. The turn watcher no longer refreshes `last_assistant_progress_at` merely because the Stop/generating control remains visible; only real assistant text growth or signature changes count as progress. If the explicit disconnect placeholder remains unchanged for the assistant-stall budget, Auto performs at most one safety-gated page reload while deliberately ignoring the stale streaming flag, because reload reconciles the existing server-side turn and never resubmits the user's potentially side-effecting request. If that reload does not recover the stream, the extension does not blindly send another user turn.
- Browser extension **0.1.55** fixes a ChatGPT handoff-summary race found by live rollover UAT. Submitting the handoff user message can briefly emit a synthetic `turn_ended` while the page still exposes the previous assistant body; older builds treated that stale body as the new summary and failed the transfer with `handoff_packet_invalid` before the real marked packet arrived. The transfer now stores only a short fingerprint of the pre-handoff assistant body, ignores that stale notification, and still rejects a genuinely new malformed summary. A failed `handoff_packet_invalid` transfer can also recover in place when its correctly marked packet arrived late, avoiding a duplicate summary request or replaying the preceding 50+ turns.
- Browser extension **0.1.54** fixes two continuity gaps. Long-conversation rollover now survives ChatGPT history virtualization: the page may keep only a handful of user/assistant nodes mounted while retaining absolute `data-testid="conversation-turn-N"` indices, so the extension persists the highest observed index as a monotonic `message_count_floor`; `40 / 46 / 50` messages prepare / recommend / require Auto rollover, and visible-text thresholds are conservatively reserved at `56k / 64k / 72k / 80k / 92k` for warning / prepare / recommend / auto / high-risk. Post-turn Auto continue also no longer terminally deduplicates an assistant fingerprint before a nudge is actually delivered: ambiguous judge results are retried, failed sends remain retryable, only explicit done or a confirmed wake seals the fingerprint, one judge/send attempt is allowed per conversation at a time, and strong assistant self-declarations such as `下一步，我会继续...` override a contradictory `done` verdict. The known legacy default judge prompt missing punctuation between `好的` and `若还有` is migrated to the corrected localized default without replacing real user-customized prompts.
- Browser extension **0.1.53** recognizes ChatGPT's explicit thread-send timeout card (`regenerate-thread-error-button`) as a first-class recovery state instead of waiting for the generic reply timer. With Auto enabled it checks the live conversation `current_node` first: if the server already has an assistant node it performs one safety-gated reload instead of retrying potentially side-effecting work; if the server still ends on the user node it uses ChatGPT's own Retry once, then reloads once if that retry never starts. Unknown delivery also prefers one safe reload, and the explicit error suppresses generic recovery-message submission so a second user turn is not created blindly.
- Browser extension **0.1.52** makes automation toggle acknowledgements independent from cross-tab refresh broadcasts. Once a Project/conversation preference is persisted, the initiating HUD is released immediately; stale or suspended tabs cannot leave the Auto button permanently disabled. The content-side toggle also clears its busy state in `finally`, so transport/UI exceptions cannot strand the control.

- Browser extension **0.1.50** fixes z.ai / DeepSeek JSON-bridge continuity. Tool execution no longer stops after 12 rounds merely because the task is long; 12 rounds is now only an event-loop yield checkpoint, and the bridge continues until the assistant returns a normal non-tool answer. After page/script recovery, a last assistant message that is still Herdr tool-call JSON is recognized as unfinished when the preceding conversation contains Herdr bridge context, and execution resumes automatically. Internal JSON messages are folded on initial/history load as well as during active runs. The fold control now sits outside the site's flex message root and toggles the whole message, preventing expanded z.ai messages from being squeezed into a vertical strip.
- Browser extension **0.1.49** removes Herdr bearer credentials from the browser entirely. The MV3 service worker sends bounded request/stream messages to the origin-restricted Chrome Native Messaging host, which talks to the runtime over `~/.config/herdr-mcp/extension.sock` (mode `0600`). `/mcp` and `/push/*` accept bearer-free traffic only on that trusted Unix-domain socket; anonymous TCP localhost remains denied. The host keeps an authenticated loopback fallback for older runtimes, and the server keeps the 0.1.48 `/extension/session` path only for older installed extension builds. Current Options no longer exposes or stores `HERDR_MCP_TOKEN` and no extension credential expires.
- Browser extension **0.1.48** can authenticate to localhost without asking the user to copy `HERDR_MCP_TOKEN`. `bin/herdr-extension-host install` derives Chromium's stable unpacked-extension id from the reported `<repo>/extension` path and registers a Chrome Native Messaging broker restricted to that exact extension origin, preserving existing unpacked-extension identity/storage. Anonymous localhost requests remain denied, the short-lived bearer cannot mint another bearer, and the old Options token remains an explicit compatibility fallback.
- Browser extension **0.1.48** fixes the z.ai / DeepSeek conversation `Auto on/off` switch looking clickable but failing with `conversation-unbound`.
