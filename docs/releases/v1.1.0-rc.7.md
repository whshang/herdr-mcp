# Herdr MCP v1.1.0-rc.7

v1.1.0-rc.7 是 1.1 的第七个预发布，仅面向 **preview** 更新通道。它继续收敛 MacBook Pro PROD 验收（[#728](https://github.com/whshang/herdr-mcp/issues/728)）中 WebChat 派发的父会话绑定问题：更宽的来源轮次规范化与未绑定诊断日志（[#777](https://github.com/whshang/herdr-mcp/issues/777)）、`herdr_prompt` 绑定结果与 `source_session_not_registered`（[#770](https://github.com/whshang/herdr-mcp/issues/770) / [#771](https://github.com/whshang/herdr-mcp/issues/771)）、标记承载调用方浏览器的设备（[#774](https://github.com/whshang/herdr-mcp/issues/774)），并加入一次调用完成的 spawn-and-dispatch（[#776](https://github.com/whshang/herdr-mcp/issues/776)）与 doctor 的 herdr-core 警告 / WebChat 授权状态（[#765](https://github.com/whshang/herdr-mcp/issues/765) / [#772](https://github.com/whshang/herdr-mcp/issues/772)）。这是**预发布**，stable 用户继续留在 1.0.x。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.7（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。

从 v1.0.x（epoch 4）出发的路径为 v1.0.4 → v1.0.5 → v1.1.0：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，stable 通道，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16，必须先通过 stable 通道的 `herdr-mcp update` 到达 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)。正式 v1.1.0 发布前，本 RC 仅用于 preview 验证。

**浏览器扩展升级顺序：** 扩展仍为 **0.1.229**（本版本无扩展变更）。先确认扩展为 0.1.229（或更新），再切换 Runtime。Runtime 自更新不会更新扩展。

**⚠️ 状态库迁移不可降级：** 从 schema 15 首次启动 rc.7 会迁移到 schema **16**（rc.6 引入，rc.7 无新迁移）；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.7、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **来源轮次规范化覆盖更多 App 芯片渲染 + 未绑定诊断日志（#777）：** 唯一的规范化器 `canonical_source_turn_text` 现在按最长 Herdr token 判断边界（`@herdr-mcp用…` 不再被误切成 `mcp用…`），并识别前导 Markdown / prompt 链接 `[name](target)`、`<@name>` / `<$name>`、`Herdr MCP` 显示名，全局去除零宽与 bidi 控制字符，解开整体包裹的中英文引号，丢弃无配对的残留反引号；仍是确定性且幂等的精确哈希，无模糊匹配。每次未绑定的 `agent.task.dispatch` 在 `server.log` 写一行只含原因、摘要前缀与字符数的诊断，不记录用户文本。扩展无需变更。 [PR #780](https://github.com/whshang/herdr-mcp/pull/780)
- **一次调用完成 spawn-and-dispatch（#776）：** `herdr_mcp.agent.task.dispatch` 新增可选 `spawn` 对象（与 `target` 互斥，要求 `idempotency_key`），一次 `herdr_call` 即可创建任务专属 pane（默认新 tab，`split_from` 时分屏并沿用宽度守卫）、启动 Agent、等待就绪并派发；失败返回 `failed_step` 与已创建资源，不自动关闭；幂等重放不会重复创建 pane / Agent。本地 CLI `herdr-mcp agent dispatch --spawn-kind …` 同步支持，Skill 指引改为首选该形式。方法名不变，Edge 授权投影与来源轮次绑定不受影响。 [PR #781](https://github.com/whshang/herdr-mcp/pull/781)
- **`herdr_prompt` 报告绑定结果 + `source_session_not_registered`（#770、#771）：** WebChat `herdr_prompt` 结果总是带 `parent_session`：复用已有映射时 `bound:true`，否则 `bound:false, reason:"tool_does_not_bind"` 并提示改用 `agent.task.dispatch` + `current_user_message`，从不改变 `ok`。扩展 `source_turn.observe` 因会话未注册被拒时，Runtime 在有界内存中记录摘要，匹配的派发返回可操作的 `source_session_not_registered`（仅诊断，从不绑定）。 [PR #785](https://github.com/whshang/herdr-mcp/pull/785)
- **WebChat 派发标记承载调用方浏览器的设备（#774）：** Edge 依据调用方自己的 `webchat_control` / Page Assist grant 的 `device_id`，在 `herdr_devices` 对应设备上输出只读 `hosts_caller_browser: true`（无 grant 时字段缺席，绝不输出 `false`）。带 `current_user_message` 的派发被路由到其他设备时，Runtime 直接返回 `parent_session: {bound:false, reason:"caller_browser_on_other_device"}`，不再误报 `source_turn_not_found`；该事实永不使派发失败。 [PR #788](https://github.com/whshang/herdr-mcp/pull/788)
- **doctor / status 显示 herdr-core 警告与 WebChat 授权状态（#765、#772）：** 只读探测 herdr-core / Herdr app，检测到时输出非致命 WARN `herdr_core_unsupported`；只读显示 Edge `webchat_control` grant 证据（`present` / `absent` / `unknown`）与扩展 consent 标志并区分两者。`doctor --json` 新增 `herdr_core`、`warnings`、`webchat_grants` 键；绝不输出 token 或完整 grant。 [PR #782](https://github.com/whshang/herdr-mcp/pull/782)
- **文档：只支持 Herdr TUI。** herdr-mcp 只驱动 Herdr TUI；Herdr app 与 herdr-core（`hc`）为独立运行时，v1.1 不支持。Herdr 文档链接改为 `https://herdr.dev/tui/docs/`，平台支持矩阵新增「Herdr 运行时支持」。 [PR #764](https://github.com/whshang/herdr-mcp/pull/764)
- **Skill 指引：WebChat 绑定派发。** 需要绑定 WebChat 会话的派发使用 `herdr_call` → `herdr_mcp.agent.task.dispatch` 并传 `current_user_message`，`herdr_prompt` 从不绑定（[PR #769](https://github.com/whshang/herdr-mcp/pull/769)）；绑定只在承载该聊天浏览器的设备上生效，需派发到该设备（[PR #773](https://github.com/whshang/herdr-mcp/pull/773)）。
- **v1.1.0 发布说明核对：** `docs/releases/v1.1.0.md` 与 CHANGELOG 按 v1.0.4...main 核对，state schema 更正为 16，写明 v1.0.5 bridge 路径与仍开放的 1.1 阻塞项。仅文档变更。 [PR #778](https://github.com/whshang/herdr-mcp/pull/778)

## 已知限制

- 本版本是预发布，仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 MacBook Pro PROD 升级/回滚验收（#728）。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持，rc.7 只给出明确的 `caller_browser_on_other_device` 原因（#775）；完整的 late-binding 推迟到 1.1.x（#771）。
- 升级前按旧规范形式记录的来源轮次摘要，在新规则下可能不再匹配；升级后在会话中重新发送一轮消息后再 dispatch（旧行 24 小时内过期）。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- 设备重新注册后旧 device id 的过期 browser endpoint 仍可能导致 `browser_canonical_url_ambiguous`（1.1.x，#734）。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展。
