# Herdr MCP v1.1.0-rc.9

v1.1.0-rc.9 是 1.1 的第九个预发布，仅面向 **preview** 更新通道。它修复 MacBook Pro PROD 升级验收（[#728](https://github.com/whshang/herdr-mcp/issues/728)）中 `herdr-mcp update apply` 在无人值守场景阻塞数分钟的问题：Runtime 更新成功后不再串联 Cloudflare Worker 更新（[#796](https://github.com/whshang/herdr-mcp/issues/796)）。这是**预发布**，stable 用户继续留在 1.0.x。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 / v1.1.0-rc.7 / v1.1.0-rc.8 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.9（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。

从 v1.0.x（epoch 4）出发的路径为 v1.0.4 → v1.0.5 → v1.1.0：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，stable 通道，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16，必须先通过 stable 通道的 `herdr-mcp update` 到达 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)。正式 v1.1.0 发布前，本 RC 仅用于 preview 验证。

**浏览器扩展升级顺序：** 扩展仍为 **0.1.229**（本版本无扩展变更）。先确认扩展为 0.1.229（或更新），再切换 Runtime。Runtime 自更新不会更新扩展。

**⚠️ 状态库迁移不可降级：** 从 schema 15 首次启动 rc.9 会迁移到 schema **16**（rc.6 引入，rc.7 / rc.8 / rc.9 无新迁移）；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

**Worker 更新是独立步骤：** `herdr-mcp update` / `update apply` / `update auto` 只更新 Runtime。Worker 落后时保留成功的 Runtime 结果并输出非致命提示，下一步是单独执行 `herdr-mcp worker update`（需要交互式 Cloudflare 授权）；更新过程本身不会启动 Worker 更新、wrangler、设备授权或浏览器。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.9、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **`update apply` 只更新 Runtime，绝不再串联 Worker 更新（#796）：** 同 contract 的 Runtime 更新成功提交后不再自动执行 Cloudflare Worker reconcile（也不再启动 wrangler、Cloudflare device login 或浏览器弹窗），因此 detached、`nohup`、CI 等无人值守升级不会再因为等待交互授权而阻塞数分钟，也不会再以 `update_succeeded_worker_update_required` 结束。Worker 落后时改为非致命提示：Runtime 更新成功时 `code` 恒为 `update_succeeded` 且退出码为成功，另有 `worker_update_required: true`、`notices[].code: worker_update_required`（`severity: notice`、`fatal: false`）与 `next_action: herdr-mcp worker update` 指明独立命令。新增显式开关 `update apply --with-worker`：仅当 stdin 与 stdout 都是交互式终端时才串联 Worker 更新，否则在任何更新动作之前以 `code: with_worker_requires_interactive_tty` 拒绝（`ok: false`，退出码 1）。`update check|status|auto` 同样只报告 Worker drift，不再有隐式 Worker mutation。 [PR #797](https://github.com/whshang/herdr-mcp/pull/797)

## 已知限制

- 本版本是预发布，仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 MacBook Pro PROD 升级/回滚验收（#728）。
- Runtime 更新不再执行 Worker 更新；Worker 落后时只报告 `worker_update_required` 提示，必须由操作员单独执行 `herdr-mcp worker update`（该步骤需要交互式授权）。
- doctor 的 WebChat grant 状态仍只基于本地证据（Edge 没有可读的 grant 列表接口），`absent_locally` 不代表 Edge 侧一定没有 grant。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持，只给出明确的 `caller_browser_on_other_device` 原因（#775）；完整的 late-binding 推迟到 1.1.x（#771）。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- 设备重新注册后旧 device id 的过期 browser endpoint 仍可能导致 `browser_canonical_url_ambiguous`（1.1.x，#734）。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**（`contracts/` 未修改）。
- First-party Public Edge contract：epoch **8 / 19 actions**。发版 PR 只改变 Edge 报告的 MCP server 版本字符串。
- Durable Runtime state：schema **16**（rc.9 无新迁移）。
- 浏览器扩展：0.1.229。Runtime 自更新不更新 Browser Extension。
