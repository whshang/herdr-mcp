# Herdr MCP v1.1.0-rc.2

v1.1.0-rc.2 是 1.1 的第二个预发布，仅面向 **preview** 更新通道。本 RC 在 rc.1 的 Browser Adapter Platform 基础上包含 N → N+1 跨 epoch updater（PR #605）和迁移文档（PR #607）。stable 用户继续留在 1.0.x。

## 升级

已处于 epoch 5 的 v1.1.0-rc.1 用户，在 preview 通道使用 `herdr-mcp update` 升级到 v1.1.0-rc.2。

从 v1.0.x（epoch 4）出发的路径分两步，必须等待 bridge 和本 RC 正式发布后执行：

```text
v1.0.x（epoch 4）
  → v1.0.4 bridge（epoch 4，同一 contract identity）
  → v1.1.0-rc.2（epoch 5，签名清单声明 contract_migration）
```

- 先通过 stable 通道的 `herdr-mcp update` 到达 v1.0.4 bridge。v1.0.0–v1.0.3 的 updater 要求 contract identity 完全相同，无法直接更新到本 RC；切换 preview 通道也无法绕过该检查。
- 再在 preview 通道执行 `herdr-mcp update`。目标签名发布清单中的 `contract_migration.from` 必须精确匹配 bridge 的 epoch 4 identity，`state_schema_from` 必须匹配本机 schema，目标 state schema 必须保持相同。一次只接纳 N → N+1。
- 发布清单的 `contract_migration` 纳入签名证明所覆盖的清单摘要。缺失或非法声明、来源 hash/tool count 不匹配、跨多个 epoch、降 epoch、schema 不同均在安装前拒绝。
- 本次 PR 只准备版本和发布文档，不创建 tag 或 Release；准备完成不代表已有可安装的 bridge/RC。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.2、Runtime contract epoch 5 / 18 tools、state schema 15，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- 实现 N → N+1 跨 epoch updater 与签名清单 `contract_migration` 接纳规则；保持相同 state schema、精确来源 identity 和安装前拒绝检查。重新注册保留已存储的 WebChat 显式拒绝授权，回滚到 epoch 4 时不扩大权限。 [PR #605](https://github.com/whshang/herdr-mcp/pull/605)
- 补充跨 epoch discovery/admission、v1.0.4 bridge 两步路径、拒绝条件和平台回滚边界的迁移文档。 [PR #607](https://github.com/whshang/herdr-mcp/pull/607)

## 已知限制

- 本版本仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 PROD 升级/回滚验收。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS：重新校验并激活上一份已安装 generation。Linux 不写入成功后的 service rollback 记录，不承诺此回滚路径。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展，1.1 浏览器功能需要兼容的 DEV 扩展或后续扩展发布。
- rc.1 已记录的 ChatGPT 归档后标签页偶尔残留限制仍适用；Windows x86_64 / ARM64 仍属于 Candidate 支持。
- ChatGPT `session.create` 时设置的会话标题（`display_label` 标题投影）可能在首个助手回复后被 ChatGPT 自动生成的标题覆盖；创建后的标题重新应用计划在 1.1.x 跟进。`session.create` 响应中的 `title_projection` 仅反映创建时的投影结果（未上报时为 `unobserved`）。新增诊断响应字段 `classification_reason`：当 runtime 将 `session.create` 的首次证据判定为 uncertain 时，会在响应中报告原因。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**；v1.0.4 bridge 保持 epoch **4**。从 1.0.x 到本 RC 必须经过 bridge 与签名 `contract_migration`，不支持直接更新。
- First-party Public Edge contract：epoch **8 / 19 actions**。Edge 与 Runtime 是独立发布和回滚范围。
- Durable Runtime state：schema **15**。跨 epoch 更新保持 schema 相同；macOS 成功后的 service 回滚不恢复数据库，不撤销更新后写入的持久状态。
- `browser_dispatches.message_canonical_digest` 是可空的新增列，epoch-4 binary 忽略该列；重新注册保留显式拒绝授权。
- Runtime 自更新不更新 Browser Extension；本 RC 不扩大已有平台支持声明。
