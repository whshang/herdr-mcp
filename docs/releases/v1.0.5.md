# Herdr MCP v1.0.5

v1.0.5 是 1.0 稳定线的 **state-schema 迁移桥（state-schema migration bridge）**，回移主线 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)。Runtime 自身仍是 schema 15 / Runtime Execution Contract epoch 4 / 18 tools，Edge contract、Edge `MCP_SERVER_VERSION` 与 Browser Extension 与 v1.0.4 完全一致；唯一的 Runtime 变更是 updater——它现在可以安全安装**在发布清单里声明了单次前向 schema 迁移**的发布。

v1.0.4 的 updater 要求发布清单 `state_schema` 与本机 schema 完全相等（15）。第一个 schema-16 的 v1.1 发布（[v1.1.0-rc.6](https://github.com/whshang/herdr-mcp/releases/tag/v1.1.0-rc.6)，清单携带 `state_schema: 16`、`state_schema_migration: {from: 15, to: 16, reversible: false}`、`contract_migration.state_schema_from: 15`、contract epoch 5）因此会在准入阶段被拒绝。本版本补齐这条桥，**自身不把 schema 提升到 16**：迁移由被 staged 的 v1.1 候选二进制执行，v1.0.5 负责准入校验、迁移前状态备份与失败回滚。

## 升级

### v1.0.4：普通更新（主路线）

```bash
herdr-mcp update
```

v1.0.4 与本版本同为 schema 15 且契约同为 epoch 4 / 18 tools，属于同契约 patch 更新，走普通前台更新路径；macOS 驻留调度器（`dev.herdr-mcp.auto-update` 定时执行 `update auto`）同样可以完成这一步。已发布的 v1.0.0–v1.0.3 继续通过 `herdr-mcp version` 末尾带标签的 `legacy probe compat` 兼容标记走普通 `herdr-mcp update`，因此它们也能先到达本桥接版本。

备用路线（仅当普通 update 不可用时）：从 v1.0.5 GitHub Release 下载本平台二进制 `herdr-mcp-1.0.5-<target>`，校验 sha256 与同一 Release 内 `runtime-manifest.json` 为该资产声明的 `sha256` 完全一致，执行 `gh attestation verify <下载的文件> -R whshang/herdr-mcp`，再在独立终端（不在任何受管 `herdr_exec` 会话内）执行 `<下载二进制的绝对路径> install`。

### v1.0.5 → schema-16 发布（v1.1）

```bash
herdr-mcp update check      # 迁移与警告会同时出现在人类可读输出和 JSON
herdr-mcp update apply      # 必须显式执行
```

- 目标 schema 等于本机（15）：普通更新，不迁移。
- 目标 schema 低于本机：拒绝（不支持降级）。
- 目标 schema 高于本机一步以上：拒绝。
- 目标 schema 恰好为本机 +1：要求清单携带精确三键 `state_schema_migration`（`from` = 本机 schema、`to` = 清单 `state_schema`、`reversible` = `false`），否则在下载/安装任何内容之前拒绝。
- 跨 epoch 路径（epoch 4 → 5）仍需清单声明 `contract_migration`，其中 `state_schema_from` 必须等于本机 schema；本版本不再要求清单 `state_schema` 等于本机 schema。

`update auto`（无人值守的 macOS 驻留调度器）**拒绝**任何 state-schema 迁移并提示改用显式 `herdr-mcp update apply`；迁移是不可逆的运维决策，必须由操作者显式执行。前台在确认迁移计划后，先探测候选二进制（期望 `state schema 16`），再停止服务、对 live `state.db` 取快照、写入回滚记录，然后才拉起 installer worker。升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

迁移成功后应看到 v1.1 版本号、contract epoch 5 / 18 tools、schema 16，service / local MCP 健康、Link 在线；`~/.config/herdr-mcp/major-upgrade/` 下保留 `state-schema-15-before-16.db` 与 `rollback.json` 作为迁移前证据。回滚需要恢复该备份，`herdr-mcp update major-rollback` 会先恢复 schema 15 再启动原运行时；本版本自身的 `herdr-mcp rollback` 语义不变。

## 主要变更

- updater 准入新增声明的单次前向 state-schema 迁移：目标 schema 等于本机时不迁移；低于本机为降级、直接拒绝；高于本机一步以上拒绝；恰好 +1 时必须在清单里声明精确三键 `state_schema_migration`（`from` = 本机 schema、`to` = 清单 `state_schema`、`reversible` = `false`），否则在安装任何内容之前拒绝。所有 schema 相关拒绝都在下载与安装之前发生。跨 epoch 路径仍要求 `contract_migration.state_schema_from` 等于本机 schema，但不再要求清单 `state_schema` 等于本机 schema；被接纳的迁移由 `ReleasePlan` 携带，并出现在 `update check` / `update apply` 的人类可读（`⚠️ … cannot be downgraded`）与 JSON（`state_schema_migration`、`warning`）输出中。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 迁移执行安全性：迁移计划下 candidate probe 期望的是目标 schema（`state schema 16`）而非本机 schema，因此被 staged 的 v1.1 候选不会被误判；`update auto` 在下载之前拒绝任何 state-schema 迁移并提示显式 `herdr-mcp update apply`；前台在 worker 激活前（服务已停止、候选已探测、job 已落库）对 live `state.db` 取快照并写入私有回滚记录（`state-schema-{source}-before-{target}.db`，记录与 `job_id` 绑定），worker 拉起失败时立即重启原服务并归还回滚材料；worker 侧只对同一 `job_id` 与 schema pair 的迁移记录做恢复或丢弃，普通更新永不消费别的更新留下的回滚证据；回滚记录校验只接受 schema 5 → 15（major migration）与 15 → 16（本桥）两对。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- update job 存储升级到 schema 3，新增 `state_schema_source` / `state_schema_target` 两列（`INTEGER NOT NULL DEFAULT 15`）。`update worker --job` 运行在**被 staged 的候选二进制**内，因此这套库格式与回滚记录格式是 v1.0.5 → v1.1.0 的跨版本磁盘契约：v1.0.5 前台必须按 v1.1 worker 读取的形状写入 15/16 与记录，否则候选会以 schema 15 自检失败或跳过备份恢复。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 版本号提升至 1.0.5（Rust Runtime `Cargo.toml` / `Cargo.lock`、npm 包 `package.json` / `package-lock.json`）。本版本不改 Edge 代码与 Edge contract，`edge/cloudflare/src/version.ts` 的 `MCP_SERVER_VERSION` 保持 1.0.4（Edge 未重新部署）；Browser Extension 继续独立版本化。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)

## 已知限制

- 本版本自身**不是** schema-16 运行时：它保持 schema 15 / contract epoch 4 / 18 tools，只负责把已声明 15 → 16 迁移的发布安全地交给自己 staged 的候选 installer。schema 16 的运行时能力由 v1.1 发布提供。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 一旦 v1.0.5 前台打开过 update store，该库即为 **schema 3**；v1.0.4 及更早的二进制会以 "update state schema version 3 is newer than this binary supports (1)" 拒绝它。这是前向桥的预期代价：请勿在 v1.0.5 与 v1.0.4 之间来回切换 update 命令。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 迁移不可逆：`reversible` 必须为 `false`，v1.1 之后回到 v1.0.x 需要恢复 `major-upgrade/state-schema-15-before-16.db`（`herdr-mcp update major-rollback` 会先恢复备份再启动原运行时），迁移之后写入的持久状态不会回退。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 无人值守通道不迁移：`update auto`（macOS 驻留调度器）会拒绝 state-schema 迁移并提示显式执行 `herdr-mcp update apply`；Linux 没有驻留调度器，按惯例在维护窗口手动执行。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 版本平面：本版本 npm 包与 Rust Runtime 同为 1.0.5，但 Edge `MCP_SERVER_VERSION` 仍为 1.0.4（未重新部署 Edge），因此 `tests/public-contract-identity.integration.mjs` 的 `MCP_SERVER_VERSION === packageJson.version` 断言会失败；这是本次"不改 Edge"约束下的已知不一致，需要 Edge 侧下一次发布把 `edge/cloudflare/src/version.ts` 的 `MCP_SERVER_VERSION` 提升到 1.0.5（一行常量）后恢复。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- `herdr-mcp rollback` 的 post-success 回滚记录保证目前仅 macOS 成立（Linux 没有成功安装后的 rollback record）；此为 v1.0.4 已有的限制，本版本未改变。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)

## 兼容性

- Workstation Runtime Execution Contract：epoch **4 / 18 tools**（`sha256:1f4d272c…`，与 v1.0.4 一致）。本版本只新增"恰好跨一个 epoch 且清单声明合法 `contract_migration`"的前向准入的 schema 维度，不放宽 epoch 规则。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- Durable Runtime state：本版本运行时 schema **15**；可安装声明 `state_schema_migration {from: 15, to: 16, reversible: false}` 的发布。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- First-party DEV/PROD Public Edge contract：epoch **7 / 19 actions**，Edge `MCP_SERVER_VERSION` 保持 1.0.4（未变更，未重新部署）；`tests/public-contract-identity.integration.mjs` 中 `MCP_SERVER_VERSION === packageJson.version` 一项因此与 1.0.5 不一致，将在 Edge 侧下一次发布时对齐。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- 发布目标继续为 macOS Apple Silicon、Linux x86_64/ARM64 musl、Windows x86_64/ARM64；Windows 仍属于 Candidate 支持。Browser Extension 继续独立版本化，本次 Runtime patch 不升级扩展。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- Worker public origin、设备身份、OAuth/Connector identity、v0.4.9 migration bridge 选择语义、`update major-apply` 均保持不变；`update major-rollback` 额外接受 15 → 16 的迁移记录以便桥接回滚。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
