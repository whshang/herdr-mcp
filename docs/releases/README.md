# Runtime release notes

Every runtime tag must ship authored release notes. GitHub's autogenerated PR list is not a substitute for an upgrade log.

Before creating `vX.Y.Z`, add `docs/releases/vX.Y.Z.md` in the exact source commit that will be tagged. The Rust Release workflow validates this file and publishes it with `gh release create --notes-file`; release publication must not fall back to `--generate-notes`.

Required structure:

```markdown
# Herdr MCP vX.Y.Z

## Upgrade from vA.B.C

Describe the exact command existing users run, any version-boundary exception, what state is preserved, and verification commands including:

herdr-mcp version
herdr-mcp status

## Main changes

### Product area

- User-visible change. [PR #123](https://github.com/whshang/herdr-mcp/pull/123)
- Change spanning several implementation slices. [PR #124](https://github.com/whshang/herdr-mcp/pull/124), [PR #125](https://github.com/whshang/herdr-mcp/pull/125)

## Known issues

- None known.

## Compatibility

State runtime/Edge/Connector/schema/platform compatibility and any migration boundary.
```

Rules:

- Every `Main changes` bullet links at least one implementation PR. If one user-facing change spans several PRs, link all materially relevant PRs.
- `Upgrade` names the version boundary and exact command. If an older installed binary interprets a command differently, say so explicitly.
- Include `herdr-mcp version` and `herdr-mcp status` as the minimum post-upgrade verification surface. Add service/Link checks when the release changes those planes.
- Always include `Known issue` or `Known issues`. Use `- None known.` when there is nothing to report. A fix merged after the tag belongs here as a known issue/follow-up, not in the tagged release's `Main changes`.
- `Compatibility` distinguishes workstation Runtime Execution Contract, public Edge contract, state schema, Connector behavior, and supported platform changes when relevant.
- Published stable tags and assets are immutable evidence. Never replace a binary under an existing stable tag to fold in a later fix; publish a new maintenance version when a later fix merits distribution.

Run locally before tagging:

```bash
node scripts/validate-release-notes.mjs vX.Y.Z
```
