# Herdr MCP v0.4.9

v0.4.9 是专门给现有 v0.4.8 用户使用的一次性 major-upgrade bridge。它本身不是长期生产基线，也不会把 1.x 功能反向带入 0.4.x service。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

## 从 v0.4.8 升级

普通用户只需要： [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

```bash
herdr-mcp update
```

不要手工下载或长期运行 v0.4.9。v0.4.8 updater 会验证 v0.4.9 manifest / artifact，然后只把它作为同一个 durable update job 的 bridge worker 启动。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

bridge 会验证目标 stable 1.x 的 schema 15、Runtime epoch 4 / 18 tools、contract hash、manifest、SHA-256 和 GitHub/Sigstore attestation，再调用目标 Runtime 自己的 `update major-apply`。原 v0.4.8 binary 和 schema-5 SQLite snapshot 会保留为 rollback source。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

迁移成功后，同一个 update job 会继续执行 `worker update`，原 Worker、public origin、Durable Objects、secrets、enrolled devices、OAuth issuer 和 Connector identity 都保留。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

升级完成后验证最终 active Runtime，而不是期待 v0.4.9 成为生产版本： [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

## 主要变更

- 增加一次性 0.4.x migration worker，把 schema migration 委托给已验证的最终 1.x Runtime，而不是把 v0.4.9 安装为生产服务。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
- bridge 固定到已资格验证的 schema 15 / Runtime epoch 4 / 18 tools 边界，未来不兼容 schema/contract 不会被静默跨越。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
- bridge 自身继续沿用 v0.4.8 的 manifest / artifact SHA-256 / GitHub attestation 校验，并独立验证最终 Runtime。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
- 原 v0.4.8 update job 继续作为唯一用户可见事务，migration 与 Cloudflare reconciliation 都回写同一个 job。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

## 已知限制

- 一键 major migration 仅覆盖已资格验证的 macOS / Linux 路径；Windows 不走这条 schema-5 bridge。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
- v0.4.9 必须与一个已发布且带 `runtime-manifest.json` 的 stable 1.x Runtime 配合使用。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)

## 兼容性

- bridge binary 自身保持 Workstation Runtime Execution Contract epoch **2 / 18 tools**。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
- bridge 不会被安装为生产服务，因此不会单独改变用户的 Public Edge / Worker。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
- Durable state 在最终 Runtime 执行 `major-apply` 前保持 schema **5**，成功后进入 schema **15**。 [PR #534](https://github.com/whshang/herdr-mcp/pull/534)
