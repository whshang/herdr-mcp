# Herdr MCP v0.4.7

> Historical note: the v0.4.7 GitHub Release/tag was withdrawn after real ChatGPT acceptance showed that Connector authorization still could not complete reliably. This document is retained as provenance for the maintenance work that followed v0.4.6; it is not a currently published stable release note.

v0.4.7 was a maintenance patch candidate for the v0.4.6 stabilization line. It addressed Connector/OAuth approval completion and inventory correctness, made long-running workstation execution queryable after a client timeout, improved route/target preflight, made update availability checks more resilient on slow networks, and trimmed the native release binary without changing runtime semantics. It did not add 1.0 feature work or expand the public MCP tool contracts.

## Upgrade

From v0.4.6:

```bash
herdr-mcp update check
herdr-mcp update
```

`update check` and `update` use the same release-metadata path. A transient metadata timeout/connect failure gets one bounded retry; if the check still cannot reach the metadata, it now reports that update availability is unknown rather than implying that no update exists.

Then verify:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

The expected runtime version is v0.4.7.

## Main changes

- Connector approval no longer depends on a one-shot browser poll. The same request-bound resume token may observe the approved result repeatedly until its TTL expires, so a background tab cannot consume the result before the visible tab. Poll transport failures become visible after a bounded retry count, approval pages explicitly warn against refresh while pending, and the CSP permits the page's same-origin script/fetch path. `herdr-mcp connector cancel <approval-request-id>` provides a recovery path for pending or approved-but-never-used requests; cancellation refuses once credentials have actually been issued. Expired unused approvals clean their orphan `conn_*` record, and legacy shared-secret fleet approval is attributed to the canonical enrolled device rather than `legacy-link:*`. Existing issued OAuth credentials are not invalidated by these changes. [Issue #327](https://github.com/whshang/herdr-mcp/issues/327) [PR #330](https://github.com/whshang/herdr-mcp/pull/330)
- Connector inventory now accounts for active token-backed credentials even when older metadata does not have a current Connector/client record. Residual access/refresh-token ownership is represented explicitly so the per-record active-token counts reconcile with aggregate `token_counts`, making operator cleanup/revocation decisions inspectable instead of silently omitting live grants. [Issue #328](https://github.com/whshang/herdr-mcp/issues/328) [PR #330](https://github.com/whshang/herdr-mcp/pull/330)
- `herdr_exec` now uses the existing durable `ExecRegistry` session/spool path instead of scraping reusable utility-pane history with sentinels. Each accepted command has operation-owned stdout/stderr and a durable `session_id`/`op_id`; if the synchronous client wait expires, `herdr_exec_read` can continue observing that exact operation through final exit without replaying the command. Reused utility panes are no longer closed on successful completion. `herdr_methods` now exposes workstation method route/target-kind metadata, public Edge can preflight exact private `herdr_mcp.*` routes as `edge_local`, `workstation_routed`, or `unsupported` without first making a failing delivery, and `agent.read` against a utility pane fails before socket delivery with `target_kind_mismatch` and `correct_method=pane.read`. Existing schema limits such as `timeout_ms <= 60000` remain visible and unchanged. [Issue #329](https://github.com/whshang/herdr-mcp/issues/329) [PR #330](https://github.com/whshang/herdr-mcp/pull/330)
- Release metadata fetches use the same bounded client path for `update check` and `update`, with one retry for transient timeout/connect failures and a 45-second request timeout. A failed `update check` now says that availability could not be determined and points to `herdr-mcp update` for an explicit retry instead of looking like a successful no-update result. [Issue #324](https://github.com/whshang/herdr-mcp/issues/324) [PR #330](https://github.com/whshang/herdr-mcp/pull/330)
- Native release builds now use Thin LTO, one codegen unit, and symbol stripping while retaining Cargo's normal optimized release code generation and panic-unwind behavior. On the v0.4.7 reference macOS arm64 build this reduces `herdr-mcp` from 20,940,368 bytes to 15,498,400 bytes (about 26%) without removing runtime features or changing the public contract. Exact artifact size varies by target platform. [PR #330](https://github.com/whshang/herdr-mcp/pull/330)

## Known issues

- [Issue #302](https://github.com/whshang/herdr-mcp/issues/302) remains a separate first-owner installation/qualification tracking item from v0.4.6. v0.4.7 does not broaden first-Worker bootstrap scope; its closure should be based on the dedicated clean-install acceptance evidence rather than this maintenance patch.

## Compatibility

- Workstation Runtime Execution Contract remains epoch 2 / 18 public tools.
- Public ChatGPT/Edge contract remains epoch 3 / 19 actions; the new `connector cancel` recovery is an enrolled-device/operator HTTP/CLI control action and does not add a public MCP tool.
- SQLite state schema remains v8.
- Existing v0.4.6 Worker/device credentials, Connector registrations, pre-v0.4.6 legacy OAuth credentials, Link configuration, Custom Domain, Native Messaging integration, browser extension installation, and local runtime configuration remain compatible.
- Browser extension versioning remains independent; v0.4.7 does not require an extension update.
