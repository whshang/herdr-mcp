# Herdr MCP v1.1.0-rc.12

v1.1.0-rc.12（2026-11-02）是 1.1 的第十二个预发布，仅面向 **preview** 更新通道。相对 rc.11，它只合入两项 updater 修复：没有显式 `--with-worker` 时更新从不串联 Worker 更新，且 `update status` 把 pre-rc.9 updater 已完成 Runtime 切换、仅 Worker 步骤失败的旧任务报告为 Runtime 成功并附 Worker 提示（#828/#830，含三语 `runtime-self-upgrade` 文档）；定时 `update auto` 在 Stable 发布的版本 / contract epoch / state schema 比本机旧时，于 contract identity 接纳检查之前以 exit 0 跳过（#829/#831）。本版本没有新的 state 迁移（schema 16），Runtime contract epoch 5 / 18 tools、Edge epoch 8 / 19 actions、扩展版本字符串 0.1.229 与 Herdr TUI 固定版本 0.9.5 均不变。这是**预发布**，stable 用户继续留在 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 – v1.1.0-rc.11 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.12（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。

从 v1.0.x（epoch 4）出发的路径为 v1.0.4 → v1.0.5 → v1.1.0：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，stable 通道，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16，必须先通过 stable 通道的 `herdr-mcp update` 到达 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)。正式 v1.1.0 发布前，本 RC 仅用于 preview 验证。

**浏览器扩展：** 本 RC 没有任何 `extension/**` 改动，版本字符串仍是 **0.1.229**。从 rc.10 或更早升级、且尚未按 rc.11 说明从 standalone current 目录重载扩展的机器，仍需重载一次（Runtime 自更新从不更新或重载扩展）。

**⚠️ 状态库迁移不可降级：** 从 schema 15 首次启动 rc.6 及以上会迁移到 schema **16**（rc.6 引入；rc.7 – rc.12 无新迁移）；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

**Worker 更新是独立步骤：** `herdr-mcp update` / `update apply` / `update auto` 只更新 Runtime；只有在交互式终端显式传 `update apply --with-worker` 才会串联 Worker 更新。Worker 落后时保留成功的 Runtime 结果并输出非致命提示，下一步是单独执行 `herdr-mcp worker update`（需要交互式 Cloudflare 授权）。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
herdr-mcp update status
```

确认 Runtime 为 1.1.0-rc.12、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **没有 `--with-worker` 时更新从不串联 Worker；pre-rc.9 updater 的旧任务按 Runtime 成功报告（#828）：** 审计确认任何路径（stable / preview 通道与 `update apply --manifest`）都只在交互式终端显式传 `--with-worker` 时才会调用 fleet Worker 更新：`apply_inner` 在任何网络或服务操作前一次性决定 `WorkerChain`，非 TTY 下 `--with-worker` 以 `with_worker_requires_interactive_tty` 拒绝；`auto()` 固定 `with_worker=false`；Runtime 成功结果总是 `ok: true` / exit 0，Worker 落后只是非致命 `worker_update_required` 提示。#828 报告的 `update_succeeded_worker_update_required` / `ok:false` / exit 1 来自 rc.6 – rc.8 的旧 updater。本 PR 修复剩余缺口：`update status` 过去只在记录状态为 `succeeded` 时才宽恕带串联 Worker 代码的旧任务；现在当已安装 Runtime 版本等于任务目标版本（切换已提交）时，即使记录为非成功状态也报告 `runtime_outcome: succeeded`，附 `worker_update_failed_legacy` 提示，并以 `recorded_runtime_state` 保留原始状态；目标版本未安装的任务仍是失败，真正的 Runtime 失败不会被宽恕。三语 `runtime-self-upgrade` 文档说明 pre-`v1.1.0-rc.9` updater 仍可能尝试该 Worker 步骤、该尝试对 Runtime 非致命且 Runtime 已更新。 [PR #830](https://github.com/whshang/herdr-mcp/pull/830)
- **定时 `update auto` 在 Stable 更旧时先于 contract 接纳检查跳过（#829，#824 后续）：** rc 安装上 stable 通道的定时 `update auto` 过去在「Stable 比当前旧」跳过之前先撞到 contract identity / state schema 降级检查而 exit 1。现在发现阶段在 contract 接纳之前就把版本、contract epoch 或 state schema 更旧的清单归类为旧发布（`OlderRelease`），定时路径输出 `{"ok": true, "code": "auto_update_skipped", "reason": "stable_older_than_current"}` 并以 0 退出，`reason_detail` 为 `older_contract_epoch` / `older_state_schema` / `older_contract_epoch_and_state_schema`，同时带 `release_contract_epoch` / `release_state_schema`、`provenance_verified: false`、`update_queued: false`，不下载或校验任何产物。只有严格向后（epoch 与 schema 都不向前）的 identity 才被归类，向前的不匹配仍在 `parse_release_plan` 中 fail-closed；`update check` 与交互式 `update apply` 继续以规范错误拒绝降级。 [PR #831](https://github.com/whshang/herdr-mcp/pull/831)

- `update status`（#828/#830）：在曾由 rc.6 – rc.8 updater 执行过、留有串联 Worker 失败记录的机器上，确认 `update status` 报告 `runtime_outcome: succeeded`、`worker_update_failed_legacy` 提示与 `recorded_runtime_state`。
- 非交互升级（#828）：确认 `herdr-mcp update` / `update apply --manifest …` 在非 TTY 下不会启动 wrangler、Cloudflare 设备登录或浏览器，Worker 落后时只给出 `worker_update_required` 提示。
- 重跑 `herdr-mcp doctor`，确认 service / Link / local MCP 全绿。

## 已知限制

- 本版本是预发布，仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。本 RC 自身的 PROD 复验仍需执行。
- `update status` 的旧任务宽恕只在已安装版本等于任务目标版本时生效；其后又切换到其它 generation 的机器会把该旧任务继续显示为失败。
- 定时 `update auto` 的跳过只在单元/注入测试中验证；真实 PROD LaunchAgent 与已安装 generation 未在本 RC 触碰，仍需人工验证。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展包。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持，只给出 `caller_browser_on_other_device` 原因（#775）。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- Runtime 更新不执行 Worker 更新；Worker 落后时只报告 `worker_update_required`，必须由操作员单独执行 `herdr-mcp worker update`。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
