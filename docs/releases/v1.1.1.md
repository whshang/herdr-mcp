# Herdr MCP v1.1.1

v1.1.1（2026-11-11）是 1.1 稳定线的首个批量维护版本，集中修复 v1.1.0 发布后归档的 9 项 1.1.x 体验与卫生问题（`#881`–`#889`）、Fleet Worker 版本对齐与原地更新兼容（`#891`），以及实机验收新捕获的 Claude 流式 `stop` 控件适配问题（`#901`）。浏览器扩展版本从 `0.1.243` 升至 **`0.1.248`**；Runtime state schema（**16**）、Workstation Runtime Execution Contract（**epoch 5 / 18 tools**）、Public Edge Contract（**epoch 8 / 19 actions**）、macOS TCC broker 兼容修订号（**5**）与 Herdr TUI 固定版本（**0.9.5**）均保持不变。

## 升级

已处于 v1.1.0（或 schema 16 的 v1.1.0-rc.6 – v1.1.0-rc.15）的用户直接执行标准更新命令升级到 v1.1.1（同 schema 验证更新，无新的状态库迁移）：

```bash
herdr-mcp update
```

也可先执行 `herdr-mcp update check` 查看目标版本，再执行 `herdr-mcp update apply` 应用更新；源码 dogfood 环境若处于 `dev` 通道，请先切回生产快照或使用受支持的通道切换命令后再执行 `herdr-mcp update`。

- **从 v1.0.x（epoch 4）升级的用户**仍沿用两步路径：先通过 `herdr-mcp update` 升级到 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5) bridge，再在前台执行 `herdr-mcp update` 经签名清单 `contract_migration`（schema 15 → 16，前向不可降级）升级到 v1.1.1。
- **v1.1.0-rc.1 – rc.5（schema 15）**的旧 updater 不接纳 schema 迁移，仍需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步使用已验证二进制的 `install` 命令手动安装。
- **⚠️ 浏览器扩展（`0.1.243` → `0.1.248`）：升级后请重载扩展。** 本版本包含 Claude、Grok、豆包与 ChatGPT 扩展脚本修复。已安装 Standalone 扩展的机器在 `herdr-mcp update` 期间会自动将本地暂存目录刷新为 **0.1.248**（保留既有 manifest `key` 与扩展 ID）；升级完成后请在 `chrome://extensions` 对 Herdr MCP 点击「重新加载（Reload）」（或等待空闲自动重载），使 `herdr-mcp doctor` 中的扩展状态从 `reload_pending` 收敛为 `current`。Chrome Web Store 渠道扩展待商店审核通过后自动推送更新。
- **Fleet Worker 更新保持独立：** `herdr-mcp update` 只更新本机 Runtime；部署自有 Cloudflare Fleet Worker 的用户在看到 `herdr-mcp update status` 提示 Worker 版本落后时，单独执行 `herdr-mcp worker update`（需本人完成交互式 Cloudflare 授权，原地更新不改变 Worker 域名、OAuth、设备配对与 Connector 身份）。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
herdr-mcp update status
```

确认 Runtime 为 `1.1.1`、contract epoch `5` / `18` tools、state schema `16`，service / local MCP 健康且 Link 在线；重载扩展后 `doctor` 的 standalone 扩展检查为 `current`。

## 主要变更

### WebChat 与浏览器适配器修复

- **Claude 后台/锁屏回合对账与残留自动化草稿自愈（`#889`）。** 在后台标签页或锁屏状态下提交的 Claude 派发可通过持久化的 `message_canonical_digest` 对账已落地的用户与助手轮次，使 `uncertain` 派发收敛为已验证结果；自动化长文提交失败滞留在 composer 的同摘要草稿可被安全清理/覆盖而不再陷入 `browser_dispatch_composer_busy` 死循环，同时继续严格保护用户手写草稿。 [PR #895](https://github.com/whshang/herdr-mcp/pull/895)
- **Claude 流式生成期间的 `stop` 控件识别修复（`#901`）。** 适配 Claude 新版 composer 的 `data-testid="chat-input-stop"` / `chat-input-send`、中英文停止按钮 `aria-label`/`title`（如 `停止回应` / `Stop response`）以及 composer 内 `sr-only` 停止按钮，修复流式回复过程中调用 `herdr_mcp.browser_dispatch.stop` 误报 `browser_dispatch_stop_control_missing` 的问题。 [PR #902](https://github.com/whshang/herdr-mcp/pull/902)
- **Grok 已开标签页重载恢复、`/bot/<uuid>` 路由与 `combobox` 输入框支持（`#886`）。** 扩展启动或重载时自动扫描并恢复已打开的受支持 WebChat 标签页注入（无需手动刷新已打开的 `grok.com` 标签页），会话定位器新增识别 `/bot/<uuid>` 会话路径，并兼容 Grok 的 `role="combobox"` 输入框与提交面。 [PR #896](https://github.com/whshang/herdr-mcp/pull/896)
- **豆包「AI 创作」生图入口与 TipTap 编辑器适配（`#887`）。** 更新豆包生图模式选择器以支持技能栏及侧边栏「AI 创作」图像生成入口与 TipTap 富文本输入框，修复已登录会话页上 `doubao.image.generate` 因旧版 composer 邻近选择器失效而报 `doubao_image_mode_unavailable` 的问题。 [PR #897](https://github.com/whshang/herdr-mcp/pull/897)
- **ChatGPT ProseMirror 裸 URL 链接比对、新开页 15s 加载栅栏错误码与限流双提交面诊断（`#883`、`#884`、`#888`）。** 归一化比对 ChatGPT ProseMirror 将裸 `https://` 自动改写为链接节点后的已提交消息文本，消除带裸 URL 创建会话时的 `browser_create_submit_failed` 误报（`#888`）；将新标签页超过 15s 加载栅栏的超时错误码从误导性的 `browser_page_storage_unavailable` 更正为 `browser_page_load_timeout`（`#883`）；补齐 provider 限流窗内 `create` 与 `send` 两条独立提交面的结构化诊断说明（`#884`）。 [PR #899](https://github.com/whshang/herdr-mcp/pull/899)

### Fleet Worker、Connector 授权卫生与本机诊断

- **Fleet Worker 生产版本对齐与已登记设备 `worker update` 兼容（`#891`）。** 对齐 `edge/cloudflare/wrangler.prod.toml` 的 `EDGE_VERSION` 与仓库发布版本并在发布门禁测试中强制一致；允许已登记 `edge_device_id` 的 fleet 成员对保留 `DEFAULT_WORKSTATION_ID` 的现代自有 Worker 执行 `herdr-mcp worker update` 原地升级，同时对未登记/无权属证明的调用方保持 fail-closed。 [PR #893](https://github.com/whshang/herdr-mcp/pull/893)
- **陈旧 DEV Connector 路由清理、`page-assist` 通配授权披露/孤儿行收敛与 `extension_stale` 精准判定（`#881`、`#882`、`#885`）。** 支持识别并清理陈旧失效的 DEV/历史 Connector 路由记录以消除路由噪声（`#881`）；明确披露 `page-assist` 派生的 `*` 授权语义并在 Connector 指针轮换时收敛历史孤儿授权行记账（`#882`）；当 Runtime 升级未改动 `extension/` 内容树时，`herdr-mcp doctor` 对字节等价的已暂存 standalone 扩展不再误报 `extension_stale`（`#885`）。 [PR #898](https://github.com/whshang/herdr-mcp/pull/898)
- **v1.1.0 发布后文档回填与设备状态勘误。** 回填 v1.1.0 发布后全设备升级与四联验收声明，并修正 `docs/releases/1.1-feature-list.md` 与 `docs/releases/v1.1.0.md` 中过时的设备升级与 Worker 版本描述。 [PR #892](https://github.com/whshang/herdr-mcp/pull/892), [PR #894](https://github.com/whshang/herdr-mcp/pull/894)

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**（与 v1.1.0 一致；从 v1.0.x 升级仍必须先经过 v1.0.5 bridge 与签名清单 `contract_migration`）。
- First-party Public Edge contract：epoch **8 / 19 actions**。Edge 与 Runtime 保持独立发布与回滚边界。
- Durable Runtime state：schema **16**（相对 v1.1.0 无数据库迁移，支持 v1.1.0 ↔ v1.1.1 服务级回滚；schema 16 仍不可降级回 schema 15 / v1.0.x，跨 schema 回退必须先恢复迁移前状态备份）。
- macOS TCC Broker：`BROKER_COMPAT_REVISION` **5**（与 v1.1.0 一致）。
- 浏览器扩展：**0.1.248**（自 v1.1.0 的 `0.1.243` 升级；协议与 v1.1.0 / v1.1.1 Runtime 双向兼容，但本版本修复的适配器行为需扩展重载到 `0.1.248` 后生效）。
- Herdr：只支持 Herdr TUI（`herdr` CLI 与 `herdr server`；CI 和 release gate 固定 `0.9.5`）。新的独立 Herdr app 与 `herdr-core`（`hc`）与 TUI 不共享 Agent，本版本不支持。详见[平台支持矩阵](../i18n/zh-CN/platform-support-matrix.md)。
