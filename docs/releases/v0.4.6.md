# Herdr MCP v0.4.6

v0.4.6 is the final stable release before 1.0; there is no 0.5.0 release line. It closes installation/configuration friction, authentication and authorization gaps, runtime performance/stability defects, and missing Connector/device/credential management so the ordinary one-conversation + one-project workflow is dependable before 1.0 feature work begins. It does not add new public workstation tools, and it deliberately does not include the separate 1.0 fleet-control-kernel or WebChat work.

Scope classes in this release: connector/OAuth authority and revocation; first-owner onboarding and readiness reporting; runtime CPU and resident-process behavior; planner-facing tool result integrity.

## Upgrade

From v0.4.5:

```bash
herdr-mcp update --check
herdr-mcp update
```

Then verify:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

The expected runtime version is v0.4.6.

Unlike v0.4.5, this tag is cut from the `release/v0.4.6-auth-hotfix-20260904` release branch rather than from a `main` merge commit. The 1.0 fleet control kernel ([PR #305](https://github.com/whshang/herdr-mcp/pull/305)) had already merged into `main` while this release was being qualified, and a stabilization release must not carry 1.0 feature work. The release branch merges back into `main` after publication, so `git log main` not showing this tag is expected and not an error.

## Main changes

- New MCP/OAuth Connectors no longer receive an authorization grant merely by completing client registration and PKCE. A new Connector enters a short-lived pending state and must be explicitly approved from an enrolled device with `herdr-mcp connector approve <approval-request-id>`. Each approved authorization instance receives its own immutable `conn_*` identity and can be revoked independently. Approved WebChat Connectors remain ordinary MCP principals and never gain fleet-administration authority; enrolled devices and Worker operator credentials own fleet administration. Pre-v0.4.6 OAuth tokens that never went through explicit approval retain ordinary MCP compatibility until an operator explicitly revokes their client grant. [PR #303](https://github.com/whshang/herdr-mcp/pull/303) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Connector approval is bound to the request, client, redirect URI, resource, scope, and PKCE challenge; the six-digit approval code is attempt-bounded and its durable verifier is protected with the deployment secret rather than a snapshot-brute-forceable plain digest. The code is entered interactively and is never accepted on CLI argv. [PR #303](https://github.com/whshang/herdr-mcp/pull/303)
- Connector instances can be inspected with `herdr-mcp connector list` and independently revoked with `herdr-mcp connector revoke <connector-id> --confirm` (`connector-id` begins with `conn_`). Instance revocation fences that Connector's already-issued access/refresh credentials without killing sibling `conn_*` instances created from the same OAuth client. A separate operator-only client kill-switch creates a durable tombstone for pre-v0.4.6 clients and fences every Connector instance sharing that legacy `client_id`. [PR #303](https://github.com/whshang/herdr-mcp/pull/303) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- GitLab CI and other unattended MCP callers now have a first-class Automation Client credential instead of relying on one fleet-wide static bearer. Each project/environment can have its own named `svc_...` client created with `herdr-mcp automation create --name <name> --device <device-id-or-unique-name>`, inspected with `automation list`, rotated with `automation rotate <client-id> --confirm`, and terminated with `automation revoke <client-id> --confirm`. The Worker resolves one immutable bound device, returns the long-lived `client_secret` once, and issues short-lived `client_credentials` access tokens (maximum one hour, no refresh token). Omitting `device` during MCP use routes to the bound device; selecting or referring to another device fails closed. Automation Clients have ordinary MCP access but never fleet-admin authority and cannot discover the rest of the fleet. [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- First-device setup now has a guided `herdr-mcp worker bootstrap` path. A release-matched Edge bundle is built once in release CI, published with SHA-256/attestation metadata, verified against the exact runtime source identity, and uploaded directly with Cloudflare Worker APIs. Ordinary users no longer need a source checkout, Node.js/npm, `wrangler.user.toml`, or a local Wrangler download. The core path keeps R2 off, deploys the Worker code once, enrolls the canonical `dev_<ULID>` device, reconciles the production Link, and resumes verified partial bootstrap state instead of creating duplicate resources. `worker pair` on a genuinely fresh machine still fails with the semantic existing-fleet guidance, while a new computer joining an existing fleet uses `worker connect`. [PR #319](https://github.com/whshang/herdr-mcp/pull/319) [Issue #302](https://github.com/whshang/herdr-mcp/issues/302)
- Event-cache stream EOF is no longer treated like an ordinary empty poll. A closed subscription transitions to a failed/disconnected state, backs off and resubscribes instead of spinning at high CPU, and `doctor` no longer reports the dead stream as healthy. [Issue #308](https://github.com/whshang/herdr-mcp/issues/308) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Repository grep now fails explicitly when it cannot complete a scan instead of returning a plausible successful empty result. Known matches are returned normally; incomplete/unscannable cases surface a bounded error such as `grep_timeout` so an Agent cannot silently conclude that text is absent. On macOS Herdr-managed linked worktrees, path validation and grep stay target-scoped so unrelated TCC-protected Git metadata cannot stall the requested search. [Issue #309](https://github.com/whshang/herdr-mcp/issues/309) [PR #304](https://github.com/whshang/herdr-mcp/pull/304) [PR #319](https://github.com/whshang/herdr-mcp/pull/319)
- Mutating `herdr_call` requests fail closed on unknown or misspelled parameters before reaching the Herdr socket. A typo can no longer fall through to a focused/default workspace and create or modify the wrong resource. [Issue #310](https://github.com/whshang/herdr-mcp/issues/310) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Named validation instances are now observable and reclaimable: `instance list` distinguishes the default instance from named instances and reports their job/port/config/age state, while guarded named-instance reap removes only that validation instance and never the default instance or immutable runtime releases. [Issue #311](https://github.com/whshang/herdr-mcp/issues/311) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Device, Connector, and Automation inventories now expose bounded lifecycle facts such as creation time/age and last-used or never-used state, including explicit legacy distinctions where exact issuance history is unavailable. The metadata is operational only: request contents, IP history, and secrets are not recorded for this purpose. [Issue #313](https://github.com/whshang/herdr-mcp/issues/313) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Maintainer qualification can now fence automatic runtime replacement while an RC is being measured, and generation transitions/cursor resets carry enough trigger/source identity to attribute a switch instead of treating it as unexplained test noise. This lock is a qualification aid, not a new user-facing update mode. [Issue #314](https://github.com/whshang/herdr-mcp/issues/314) [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Link recovery is more observable and less prone to false offline reports. Status carries reconnect start/recovery/duration/count evidence ([commit `6a7d8af`](https://github.com/whshang/herdr-mcp/commit/6a7d8af)); a stale launchd-loaded production Link generation is reloaded and readiness stays false until it matches the active runtime ([commit `f3fbd9f`](https://github.com/whshang/herdr-mcp/commit/f3fbd9f)); and Edge now allows 15 seconds rather than 2 seconds for an ordinary Link reconnect/handshake before declaring the workstation offline ([commit `b075069`](https://github.com/whshang/herdr-mcp/commit/b075069)). [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Routine Runtime/Link/Edge interruptions remain an automatic-recovery concern rather than an operator task. Transient relay errors identify themselves with `requires_human=false`; `delivery_uncertain` and ambiguous timeouts require the planner to inspect request/Git/runtime/resource evidence before any mutation replay. A bounded reconnect probe window is not, by itself, a reason to ask the user to restart Herdr; human intervention is reserved for actual permission/login/approval boundaries, irreversible confirmations, or evidence that supervised recovery is genuinely exhausted. [PR #319](https://github.com/whshang/herdr-mcp/pull/319)
- Fresh-install/runtime readiness is less ambiguous. Link ownership reconciles `local-mcp-active` to the exact active `rust-*` generation, ordinary install health reports `operational_ready` independently of maintainer-only cutover sealing, and `outside_managed_roots` failures include an actionable managed-root hint. These changes close the concrete first-use failures tracked in Issues #306 and #307. [PR #304](https://github.com/whshang/herdr-mcp/pull/304) [Issue #306](https://github.com/whshang/herdr-mcp/issues/306) [Issue #307](https://github.com/whshang/herdr-mcp/issues/307)
- The Connector approval page is now a responsive light/dark UI with a prominent six-digit code, a copy button for the exact `herdr-mcp connector approve <request-id>` command, live approval status, and an explicit version hint when the local CLI predates v0.4.6. First-install documentation defaults to the common new-Worker path, starts Cloudflare Token creation in parallel with download/install, uses `workers.dev` when no active Cloudflare-hosted zone exists, and offers a Custom Domain only from active zones in the selected Cloudflare account. On macOS the managed supervisor keeps `herdr server` available; ordinary users are not asked to start it manually. [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Local authentication boundaries are now documented explicitly: the loopback TCP endpoint `http://127.0.0.1:8772/mcp` remains bearer-authenticated, while the official browser extension never receives that bearer and uses the origin-checked Native Messaging → mode-`0600` Unix socket trusted IPC path instead. [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Remote-planner Agent supervision now treats obvious repeated-output loops as a fault: after bounded confirmation of repeated/near-identical output with no new command, diff, or task evidence, the planner interrupts the Agent, verifies Git/task state to avoid duplicate mutations, and restarts unfinished work in a fresh Agent session. Work already captured/integrated is stopped rather than replayed; a second loop is reassigned or taken back by the main planner. [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- Transient gateway/backpressure handling is now delivery-aware across the Connector path. Non-JSON `429`/`5xx` responses such as Cloudflare `502` and `524` no longer degrade to a generic invalid-response error. Known reads get a short bounded retry with a fresh request id and respect `Retry-After`; mutating calls are never replayed after an ambiguous gateway response and return `delivery_unknown` until state is verified. Edge capacity `429` now explicitly reports `delivery_state=not_delivered` plus a 1-second backpressure hint, and runtime-catalog `524` is classified as retryable. Existing browser `429` cooldown and Link reconnect backoff remain bounded and unchanged. [PR #304](https://github.com/whshang/herdr-mcp/pull/304)
- `herdr_fs_patch` still fails closed when a hunk matches more than one location, but ambiguous-context errors now include bounded candidate line numbers and a direct retry hint so an Agent can add the right surrounding context without another blind patch attempt. [PR #304](https://github.com/whshang/herdr-mcp/pull/304)

## Known issues

- [Issue #302](https://github.com/whshang/herdr-mcp/issues/302) ships within a deliberate automation boundary: `worker bootstrap` covers the Herdr-controlled download, Worker deployment/configuration, device enrollment, Link reconciliation, resume, and verification steps. Human Cloudflare/browser actions that cannot be delegated safely still remain human, including account/sign-in or token authorization when required; ChatGPT Developer Mode/Connector creation and browser OAuth/Herdr approval also remain explicit user authorization steps.
- Zero-to-first-device qualification used an isolated Debian/aarch64 zero-state simulation plus candidate verification on an existing macOS host. No third pristine Mac was available for this RC, so those two evidence sets must not be described as equivalent to a completely untouched physical Mac installation.
- Until the final v0.4.6 production Edge deployment is performed, the production Worker can still be running the older script. Connector/Automation management routes returning HTTP 404 during qualification are therefore an expected old-Edge boundary and are not evidence that the v0.4.6 candidate was deployed or that its management implementation failed.

## Compatibility

- Workstation Runtime Execution Contract remains epoch 2 / 18 public tools.
- Public ChatGPT contract remains epoch 3 / 19 actions. Connector approval/revoke and Automation administration are enrolled-device/operator control-plane actions; they do not add public MCP tools and approved WebChat Connectors are not fleet administrators.
- Existing v0.4.5 Worker/device credentials, Link configuration, Custom Domain, Native Messaging integration, browser extension installation, and local runtime configuration remain compatible.
- Browser extension versioning remains independent; v0.4.6 does not require an extension update.
