# Herdr MCP v0.4.6

v0.4.6 is a focused authentication and onboarding security hotfix. It does not add new public workstation tools and does not include the separate 1.0/WebChat work.

## Upgrade

From v0.4.5:

```bash
herdr-mcp update
```

Then verify:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

The expected runtime version is v0.4.6.

## Main changes

- New MCP/OAuth Connectors no longer receive an authorization grant merely by completing client registration and PKCE. A new Connector enters a short-lived pending state and must be explicitly approved by an already trusted Herdr owner. Exact owner-device credentials can approve locally with `herdr-mcp connector approve <approval-request-id>`; an already-approved Connector may approve through the existing private `herdr_call` method. Generic MCP/operator bearer tokens and ordinary joined-device credentials cannot bootstrap this authority. [PR #303](https://github.com/whshang/herdr-mcp/pull/303)
- Connector approval is bound to the request, client, redirect URI, resource, scope, and PKCE challenge; the six-digit approval code is attempt-bounded and its durable verifier is protected with the deployment secret rather than a snapshot-brute-forceable plain digest. The code is entered interactively and is never accepted on CLI argv. [PR #303](https://github.com/whshang/herdr-mcp/pull/303)
- Connector grants can be explicitly revoked. Revocation leaves a durable grant tombstone, fences already-issued v0.4.6 access/refresh credentials, and deletes matching stored token records. Pre-v0.4.6 clients without a grant record retain ordinary MCP compatibility but do not inherit Connector-administration authority. [PR #303](https://github.com/whshang/herdr-mcp/pull/303)
- `herdr-mcp worker pair` now fails closed with a semantic enrollment error on a genuinely fresh machine instead of leaking a missing `dev.herdr-mcp.link-prod.plist` / `Io(NotFound)` failure. Pairing creation remains an already-enrolled owner fallback; a new machine joining an existing fleet uses `worker connect`, while a first machine follows the first-owner bootstrap path. Existing config-based enrollment and legacy Link-plist owners remain compatible. This fixes the low-level failure reported in Issue #302, while the broader one-command first-owner bootstrap request remains open. [PR #303](https://github.com/whshang/herdr-mcp/pull/303) [Issue #302](https://github.com/whshang/herdr-mcp/issues/302)

## Compatibility

- Workstation Runtime Execution Contract remains epoch 2 / 18 public tools.
- Public ChatGPT contract remains epoch 3 / 19 actions; Connector administration uses private methods under the existing `herdr_call` surface.
- Existing v0.4.5 Worker/device credentials, Link ownership, Custom Domain, Native Messaging integration, browser extension installation, and local runtime configuration remain compatible.
- Browser extension versioning remains independent; v0.4.6 does not require an extension update.
