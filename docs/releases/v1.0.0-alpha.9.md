# Herdr MCP v1.0.0-alpha.9

This is a superseding 1.0 prerelease, not the 1.0 GA declaration. It replaces the alpha.8 acceptance candidate with the final closeout source after Linux Link readiness, runtime/Edge contract metadata, protected-worktree execution, delivery-evidence, dependency, and current-documentation fixes. The immutable v1.0.0-alpha.8 release remains historical and is not rewritten.

## Upgrade from v1.0.0-alpha.8 or v0.4.8

An installed v1.0.0-alpha.8 runtime already uses durable state schema 15, so alpha.8 → alpha.9 is a same-schema prerelease update through the normal verified updater:

```bash
herdr-mcp update check
herdr-mcp update apply
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
herdr-mcp doctor
```

v0.4.8 uses durable state schema 5. Its ordinary `herdr-mcp update apply` path must not cross directly to this schema-15 prerelease. After verifying the downloaded v1.0.0-alpha.9 binary against `release-manifest.json` and its attestation, run `herdr-mcp update major-apply` from an independent terminal, then verify the same status commands above and confirm the intended device from the same remote Connector. N-1 recovery remains `herdr-mcp update major-rollback` using the preserved source binary and schema-5 snapshot.

Service-changing update commands must not run from a managed `herdr_exec` session.

## Platform qualification

- **macOS Apple Silicon — Production:** final-source DEV activation, service/Link generation reconciliation, stable TCC broker revision-4 authorization, protected linked-worktree Git access, and live utility-pane contention/recovery have passed on the physical maintainer Mac. Exact STANDALONE/STORE browser-package acceptance remains an independent browser release plane.
- **Linux x86_64 — Production:** the static `x86_64-unknown-linux-musl` release target remains part of the authoritative five-target release matrix.
- **Linux ARM64 / aarch64 — Production:** the Linux-native Link readiness fix was rebuilt and exercised on the physical NanoPi R5C before integration; final physical UAT also verifies that `doctor` consumes the same native Linux Link ownership/readiness projection as `link status`, rather than the macOS launchd model. The static `aarch64-unknown-linux-musl` target remains in the authoritative release matrix.
- **Windows x86_64 — Candidate:** hosted build/lifecycle/recovery qualification passes; physical Windows UAT is still open.
- **Windows ARM64 / aarch64 — Candidate:** native `windows-11-arm` release qualification covers `aarch64-pc-windows-msvc`; physical Windows ARM64 qualification remains open.
- **WSL — Unsupported.**

## Known issues

- 1.0 GA still requires the remaining real signed-in WebChat and cross-provider acceptance in [#399](https://github.com/whshang/herdr-mcp/issues/399). Registry/capability visibility is not a substitute for live browser mutation delivery.
- Windows remains Candidate pending physical qualification in [#394](https://github.com/whshang/herdr-mcp/issues/394).

This Runtime prerelease does not itself load an unpacked browser package, publish the Chrome Web Store build, refresh a frozen ChatGPT action snapshot, or deploy Edge.
- A green source/CI run does not substitute for published-asset hash/attestation verification or the physical/browser UAT explicitly called out above.

## Compatibility

- Workstation Runtime Execution Contract: epoch **4**, **18** tools. First-party DEV/PROD Public Edge contract: epoch **7**, **19** actions. Runtime epochs 2/3 and Public Edge epoch 3 remain bounded compatibility/rollback identities rather than the current first-party contract.
- Durable runtime state: schema **15**. v0.4.8 schema 5 requires the explicit major-upgrade path; same-schema 1.0 prerelease updates use the normal verified updater.
- Published Runtime targets remain `aarch64-apple-darwin`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-pc-windows-msvc`, and `aarch64-pc-windows-msvc`.
- MCP/OAuth origin and enrolled-device identity are retained across a successful install/update. Browser control, Tool Bridge, workstation mutation and Planner authority remain distinct permissions.
- macOS Apple Silicon and native Debian-class Linux x86_64/ARM64 are Production. Windows x86_64/ARM64 are Candidate. WSL is Unsupported.
