# Herdr MCP v1.1.0-rc.4

v1.1.0-rc.4 是 1.1 的第四个预发布，仅面向 **preview** 更新通道。它是 MacBook Pro PROD 升级/回滚验收（[#728](https://github.com/whshang/herdr-mcp/issues/728)）使用的候选版本，源码与 Gate-6B（[#729](https://github.com/whshang/herdr-mcp/issues/729)）通过后的 main 一致。stable 用户继续留在 1.0.x。

## 升级

已处于 epoch 5 的 v1.1.0-rc.1 / rc.2 / rc.3 用户，在 preview 通道使用 `herdr-mcp update` 升级到 v1.1.0-rc.4。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

从 v1.0.x（epoch 4）出发的路径仍为两步（与 rc.3 相同）：

```text
v1.0.x（epoch 4）
  → v1.0.4 bridge（epoch 4，stable 通道，同一 contract identity）
  → v1.1.0-rc.4（epoch 5，preview 通道，签名清单声明 contract_migration）
```

**浏览器扩展升级顺序：** 先升级或重载浏览器扩展到 **0.1.227**（或更新），再切换 Runtime。本 RC 修复的 ChatGPT 来源轮次捕获在扩展中，Runtime 自更新不会更新扩展。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.4、Runtime contract epoch 5 / 18 tools、state schema 15，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 已知限制

- 本版本仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 MacBook Pro PROD 升级/回滚验收（#728）。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- 设备重新注册后，旧 device id 的过期 browser endpoint 无法被正式退役，同一会话 URL 可能持续 `browser_canonical_url_ambiguous`；换新会话可规避（1.1.x，#734）。
- 设备级 WebChat 授权（#713 / #730）推迟到 1.1.x。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展。

- Durable Runtime state：schema **15**。
- 浏览器扩展：0.1.227。Runtime 自更新不更新 Browser Extension。
