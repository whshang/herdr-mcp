# Herdr MCP v1.1.0-rc.11

v1.1.0-rc.11（2026-11-02）是 1.1 的第十一个预发布，仅面向 **preview** 更新通道。相对 rc.10，它合入 WebChat 来源轮次绑定在设备重新注册后按观测端点解析（#734）、新 ChatGPT 会话首条消息的迟绑定（#786）、ChatGPT continuity 不可用时「接力」的解释与闸门（#811）、浏览器端点离线与完成超时的区分性分类、端点生命周期日志与 native host 连接日志（#629）、updater 的 ETXTBSY 执行重试（#738）、可选 GitHub token / 限流错误（#739）与定时 `update auto` 在 rc 安装上的跳过修复（#824）、Rust Link 空闲 WebSocket ping 频率减半（#809）、Node Link 空闲应用心跳由 15s 改为 30s 且静默看门狗同步放宽到 90s（#808）、Node Link 守护进程的本地 MCP contract epoch 对齐（#819）、新增可重复的旧↔新 Runtime/扩展兼容与回滚检查（#586），以及 docs #807 / #810 / #818（含 herdr-core 探测 spike 结论）与仅测试/CI 的 Edge → Runtime 集成 harness（#613/#820）。本版本没有新的 state 迁移（schema 16），Runtime contract epoch 5 / 18 tools、Edge epoch 8 / 19 actions、扩展版本字符串 0.1.229 与 Herdr TUI 固定版本 0.9.5 均不变。这是**预发布**，stable 用户继续留在 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 / v1.1.0-rc.7 / v1.1.0-rc.8 / v1.1.0-rc.9 / v1.1.0-rc.10 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.11（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。

从 v1.0.x（epoch 4）出发的路径为 v1.0.4 → v1.0.5 → v1.1.0：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，stable 通道，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16，必须先通过 stable 通道的 `herdr-mcp update` 到达 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)。正式 v1.1.0 发布前，本 RC 仅用于 preview 验证。

**浏览器扩展：源码变了，版本号没变。** 本 RC 的扩展侧改动（#812 / #815 / #816 中的 `extension/**` 部分）都没有提升版本号，`extension/manifest.json` 仍是 **0.1.229**。Runtime 自更新从不更新 Browser Extension，也不会因为版本号未提升而重载它：必须在安装/升级后从 standalone 的 current 目录重新加载（或重装）扩展，见下文「人工 UAT」。仅看版本号不能证明修复已生效。

**N-1 兼容（新扩展 + 旧 Runtime）：** 新扩展向后兼容 rc.10 及更早的 Runtime。当旧 Runtime 以 `browser_registry_params_invalid` 拒绝 #815 新增的 `profile_seed` / `endpoint_ref` 时，扩展立即用同一份证据（同文本、同 `observed_at`）重发旧的四字段 `source_turn.observe` payload（`operation` / `canonical_url` / `user_text` / `observed_at`）一次，并在该 service worker 生命周期内记住这台 Runtime 不支持 provenance，后续轮次直接发旧 payload。其它错误码不重试，fail-closed 语义不变。反向（旧扩展 + 新 Runtime）不需要改动：`profile_seed` / `endpoint_ref` 都是可选参数。

**新的 `server.log` `event=` 行（#629 Runtime 部分）：** 受管服务把 Runtime 的 stderr 收进 `server.log`，现在会写入内容无误的端点生命周期行：endpoint 注册、`/push/events` 流打开与关闭（含时长）、online → stale 的拒绝、以及每次待处理命令超时。只包含 id、枚举码、毫秒年龄与时长，不含页面文本、profile 内容或凭据。

**可选 `GH_TOKEN` / `GITHUB_TOKEN`（#739）：** 不设置 token 时 `herdr-mcp update` 行为逐字节不变。设置后只在 origin 恰为 `https://api.github.com` 的请求上发送 `Authorization: Bearer`（`GH_TOKEN` 优先，取第一个非空），该请求头被标记为敏感值；配置了 token 时，任何离开 api.github.com 的重定向都会被拒绝，凭据不会到达 release 资产或仿冒主机。403/429 且 `x-ratelimit-remaining: 0`（或 429，或带 `retry-after`）现在映射为稳定错误 `github_rate_limited`，附带 UTC RFC3339 的 `x-ratelimit-reset` 与「设置 GH_TOKEN / GITHUB_TOKEN 或稍后重试」提示；其它 403 保持原错误文本。

**⚠️ 状态库迁移不可降级：** 从 schema 15 首次启动 rc.6 及以上会迁移到 schema **16**（rc.6 引入；rc.7 – rc.11 无新迁移）；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

**Worker 更新是独立步骤：** `herdr-mcp update` / `update apply` / `update auto` 只更新 Runtime。Worker 落后时保留成功的 Runtime 结果并输出非致命提示，下一步是单独执行 `herdr-mcp worker update`（需要交互式 Cloudflare 授权）；更新过程本身不会启动 Worker 更新、wrangler、设备授权或浏览器。

**macOS TCC 提示：** 首次访问 `~/Documents`/`~/Desktop`/`~/Downloads` 仍可能弹一次性授权窗口；rc.10 起受保护目录判定已改为纯词法比较，不会挂起整条控制链路，但弹窗仍需人工点一次。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.11、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线；并单独确认浏览器扩展已从本 RC 的 standalone 目录重载（版本字符串仍是 0.1.229）。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **设备重新注册后，WebChat 来源轮次在本观测端点内解析（#734）：** `source_turn.observe` 新增可选 `profile_seed` / `endpoint_ref`，作用域由本 Runtime 自己的 device identity 加 profile seed 重新推导（不取自调用方；不属于本 device+profile 的 ref 以 `browser_endpoint_ref_mismatch` 拒绝），并新增按端点限定的当前代际查询：恰好一个在范围内会话胜出，零个回落到原有全局查找（保留其歧义错误与 #771 的未注册来源分类），多于一个仍是 `browser_canonical_url_ambiguous`。不删除或退役任何 endpoint / session / locator，无 schema 迁移。用户可见效果：重新注册后仍在 state 里的旧 device id endpoint 不再让该会话的每个派发都报 `source_turn_not_found`。 [PR #815](https://github.com/whshang/herdr-mcp/pull/815)
- **新 ChatGPT 会话的第一条消息不再丢父会话绑定（#786）：** 扩展对每个 tab+conversation 只在内存里保留至多一条未记录的轮次（仅对 `browser_source_session_not_found`，5 分钟过期，上限 32 条，更新的提交替换旧证据而不排队），在该会话经 `h2w_register` 注册后原样重放一次（同规范 URL、同去空白文本、同提交时间），重放从不向 ChatGPT 发送任何内容；其它错误码立即清除保留并保持 fail-closed；`h2w_register` 现在显式拒绝临时 ChatGPT 身份（`provisional_conversation_identity`）而不是为它注册会话。用户可见效果：新会话发送后即使会话在数分钟后才注册，第一轮的父会话绑定仍能在 5 分钟内补上。 [PR #816](https://github.com/whshang/herdr-mcp/pull/816)
- **ChatGPT continuity 不可用时「接力」改为解释 + 闸门（#811）：** HUD 用既有只读 `POST /extension/continuity/resolve` 探测 durable 可用性（1.5s 截止，45s 就绪/不可用缓存、5s unknown 缓存，绑定/解绑与 durable journal ack 时失效）；只有明确 404 `continuity_not_found` 才置 `can_handoff:false` 与 `handoff_unavailable_reason:"continuity_unavailable"`，超时、传输失败与 5xx 保持原状（可点击、点击后 fail-closed）。新增 zh/en/ja 文案 `hud_handoff_continuity_unavailable` 说明「未绑定/无本地 continuity 记录、当前会话未被修改、先绑定再对话一轮后重试」，不再回显裸 `continuity_unavailable`。同时删除 `startHandoffForTab` 中不可达的手动 Project 回落分支（它会导航源标签页，无法满足不修改源会话的不变式）。`source_preserved:true` 与「无 transfer 行」语义不变。 [PR #812](https://github.com/whshang/herdr-mcp/pull/812)
- **浏览器端点离线与完成超时被区分，并新增端点生命周期日志（#629 Runtime 部分）：** `browser_page_unavailable` 不再对「端点从未轮询 `/push/events`」和「命令已交给扩展 SSE 但无完成」都报 `delivery_state=not_delivered`。分类现在来自 actuation broker 的停止位置，沿用既有 `not_delivered` / `delivery_unknown` 词汇（没有新增 delivery_state）：端点从未进入存活窗口 → `not_delivered` + `reason: endpoint_offline`（此前轮询过时附 `endpoint_last_seen_age_ms`）；已入队但从未被取走、在截止点被原子移出 → `not_delivered` + `reason: queued_untaken_at_timeout`（可安全重试）；已由 `take_next_for_extension` 交付但无完成 → `delivery_unknown` + `reason: completion_timeout`、`retryable: false`（绝不盲目重试）。`browser_page_unavailable` / `browser_page_delivery_unknown` 错误码不变，只新增/更正字段，无公共 MCP 工具、epoch 或 schema 变更。 [PR #817](https://github.com/whshang/herdr-mcp/pull/817)
- **native host 新增有界、轮转、无内容的连接日志（#629 的 native host 部分）：** Chrome 每次 `chrome.runtime.connectNative` 都会起一个 `herdr-mcp extension-host` 进程，此前从未连到 Runtime 的 host（扩展 id 不对、IPC socket 已死、帧过大、流被关）不留任何证据——`server.log` 只有 Runtime 参与后才存在。现在 `native_host::run` 是 `serve()` 的薄 stdio 包装，每个 host 进程生命周期记一条 `connect`、一条 `disconnect`，每次本地端口/流失败记一条 `io_error`；写到 `<config dir>/native-host/native-host.log`（`0600` 文件 / `0700` 目录，沿用 `RuntimePaths::discover()` 的 config root，不引入新根），1 MiB 轮转并保留两份备份，用非阻塞 `flock` 串行化写入者。日志尽力而为：目录不可创建、文件不可写或锁竞争时丢弃该事件，host 路径从不传播日志错误。永不记录消息正文、页面内容、标签标题、URL 与查询串、请求头、token、cookie、凭据或产物字节；origin / message type / 错误码走白名单（否则 `-` / `other` / `host_error`），字段被净化以防伪造额外日志行。删除 `<config dir>/native-host` 即移除该产物。三语 `local-agent-webchat-control` 同步一条说明。 [PR #825](https://github.com/whshang/herdr-mcp/pull/825)
- **updater 支持可选 GitHub token 并给出清晰的限流错误（#739）：** 匿名调用 `api.github.com` 在共享或耗尽出口 IP 上会撞 60/h 配额，此前只表现为笼统的 `release download returned HTTP 403`；现在可选 `GH_TOKEN` / `GITHUB_TOKEN`，并把限流响应映射为稳定错误 `github_rate_limited`（含 UTC RFC3339 的 `x-ratelimit-reset` 与下一步提示）。三语 troubleshooting 文档同步补充症状与 token 选项。 [PR #814](https://github.com/whshang/herdr-mcp/pull/814)
- **updater 不再因 ETXTBSY 执行暂存二进制失败（#738）：** Linux 定时更新验收曾出现 `cannot execute staged update binary: Text file busy (os error 26)`：`execve` 在仍有进程持有写描述符时返回 ETXTBSY，而并发 fork 的子进程可能短暂继承 staging 写描述符。现在 `download_asset` 在 chmod/rename 之前先关闭（drop）staging 写描述符，使候选路径以已关闭的 inode 发布；`probe_candidate_binary` 与 `spawn_worker` 通过有界重试（10 次 × 20ms，仅重试 ETXTBSY，`cfg(unix)` 门控）执行暂存候选。任何校验、attestation、identity 或 sha256 检查都没有被削弱、重排或跳过。 [PR #813](https://github.com/whshang/herdr-mcp/pull/813)
- **定时 `update auto` 不再在 rc 安装上每天失败，且 generation 切换后重新注册调度器（#824）：** ① `apply_inner` 过去把「Stable 比当前旧」当成拒绝降级（exit 1），导致 rc 安装上每天的定时运行都失败；在定时/自动路径（`channel_override.is_some()`）现在输出 `{"ok": true, "code": "auto_update_skipped", "reason": "stable_older_than_current", "network_checked": true}` 并以 0 退出，不 staging 候选、不创建更新任务、不激活；手动 `update apply` 仍以 `release <v> is older than current <v>; refusing downgrade` 拒绝降级。② generation 切换后生成的 plist 字节不变（`ProgramArguments` 经 `runtime/current/herdr-mcp` 解析），已加载的 job 可能保留过期的 LWCR/BTM 注册并在二进制启动前以 `EX_CONFIG`（78）失败；`reconcile_after_service_install` 的「plist 未变」分支现在尽力执行 `launchctl bootout` + `bootstrap`，失败只记录并写进结果，绝不当成安装/更新错误。③ 生成的 plist 把 `StandardOutPath` / `StandardErrorPath` 指向 `<config-dir>/auto-update.launchd.out.log` / `auto-update.launchd.err.log`；ownership 校验容忍没有这些键的旧 plist（既有 agent 仍可升级），但拒绝本实例之外的路径。三语 `cli-reference` 的 `update auto` 段落同步更新。 [PR #826](https://github.com/whshang/herdr-mcp/pull/826)
- **Rust Link 空闲 WebSocket ping 频率减半（#809）：** Link 守护进程的传输层 ping 间隔由 15s 改为 30s，最大静默阈值由 60s 改为 90s（与 30s pong 节奏配套），应用层心跳仍保持稀疏的 5 分钟。用户可见效果：空闲工作站的 Edge Durable Object 唤醒次数更少。这是传输参数调整，不改 wire schema、协议或持久化状态。 [PR #809](https://github.com/whshang/herdr-mcp/pull/809)
- **Node Link 守护进程恢复可启动，本地 MCP contract epoch 对齐（#819）：** `LOCAL_MCP_CONTRACT_EPOCH` 从过期的 2 改为 5，与 `PUBLIC_CONTRACT_EPOCH` 及 Rust 侧 `crates/herdr-mcp/src/link/local_mcp.rs` 的 `LOCAL_MCP_CONTRACT_EPOCH` 一致，使 `runtime.contract_epoch` 与传输层广告的 contract hash 相匹配；`readLinkDaemonConfig` 现在只接纳当前 runtime execution pair（epoch 5 / v5 hash），并在构造管理器之前就以带所需 epoch 的消息拒绝冻结的 epoch-1 rollback pair（回滚改为激活上一个二进制，与 Rust `run_link_daemon` 对齐）。用户可见效果：Node Link（legacy/dev canary）此前在任何被 `readLinkDaemonConfig` 接受的配置下都无法启动、报 `runtime-generation: contract epoch must remain 2 for this build`，现在可以正常启动。 [PR #822](https://github.com/whshang/herdr-mcp/pull/822)
- **Node Link 空闲应用心跳减半（#808）：** Node 生产 Link 的应用层心跳间隔由 15s 改为 30s，静默看门狗同步由 60s 放宽到 90s。放宽是必要的：Edge 对心跳的状态回复最多每 `EDGE_STATUS_REPLY_INTERVAL_MS`（30s）一次，30s 心跳下略微抖动的到达可能刚好错过节流窗口，使入站帧间隔接近 60s，60s 看门狗会把健康连接回收；90s 与 `LINK_DEFAULT_MAX_SILENCE_MS` 及 Rust Link（#809）一致。无 wire 协议、Edge 部署或 Rust Link 变更。用户可见效果：空闲 Node Link 的心跳与唤醒次数减半，同时不会因为回复节流被误判为静默断线。 [PR #808](https://github.com/whshang/herdr-mcp/pull/808)
- **新增可重复的旧↔新 Runtime/扩展兼容与回滚检查（#586）：** `scripts/check-compat-rollback.mjs` 是单入口的 13 项检查，从**已发布 tag 自身**（`git show v1.1.0-rc.10:…`）读取旧 peer 的 registry allow-list、能力词汇与 `SCHEMA_VERSION`/`MIGRATIONS`，而不是会漂移的手写 fixture；`tests/compat-runtime-extension-negotiation.test.mjs` 用该 allow-list 驱动真实 `extension/background.js` 的来源轮次路径，把 #815 的 N-1 回退钉在它声称支持的发布上；同时新增 Rust 测试确认 rc.10 的 payload（`endpoint.register`、`endpoint.consent`、rc.10 能力文档、四字段 `source_turn.observe`）仍被接纳、更新的 `adapter_protocol_version` 被承认。检查在隔离的临时 HOME/XDG 树里运行并前后快照 `~/.config/herdr-mcp`，证明真实配置未被触碰。用户可见效果：本 RC 的行为没有因为该 PR 改变，但「新扩展 + 旧 Runtime」和「state 可回滚」这两条升级声明从此有可复跑的检查；一旦新增 migration 17，检查会立刻失败并要求走 `major-rollback` 备份路径与发布说明。 [PR #821](https://github.com/whshang/herdr-mcp/pull/821)
- **Skill/方法文案：空 stdout 不是 Agent 失败（docs，#810）：** 执行 Skill 明确一次 exec 结果只描述一条命令，按自身 `ok`/`exit_code`、phase、session_id（失败路径上还有 `delivery_state`）判定，打印不出东西仍是 `ok:true`；派发 Skill 与 `agent.task.dispatch` 方法描述明确派发结论来自 `ok`、`delivery_state`、resolve/submit 失败与 worker 的 task/inbox 生命周期或报告，`herdr_exec` / `herdr_exec_read` 输出不是派发证据，尚无终端输出的 worker 仍是非终态。无运行时分支、wire schema 或 contract identity 变化。 [PR #810](https://github.com/whshang/herdr-mcp/pull/810)
- **发布文档对齐 rc.10 之后的 GA 声明（docs，#807）：** 更正 v1.1.0 发布说明与 1.1 功能清单：Edge 已部署并审计设备级（`scope:"device"`，`*/*/*`）WebChat grants 与仅 owner 可用的 `platform_account` 标签，但 Runtime 目前会丢弃 `*/*/*` 行、尚不为 WebChat 派发消费它们，1.1 合格路径仍是 endpoint + provider grants；升级路径表述更新到 rc.10。仅文档变更。 [PR #807](https://github.com/whshang/herdr-mcp/pull/807)
- **herdr-core（hc）探测 spike 结论（docs，#767）：** 在已运行的 herdr-core 0.1.14 上按时限验证 socket/认证模型、18 工具映射（3 等价 / 9 部分 / 6 无，其中 `herdr_skill` 与运行时无关）、OSC 7501 状态协议、`machine add` 的 core-to-core 拨号模型与 OpenRPC schema；结论是**不能**作为 18 工具契约背后的直接后端，只有在显式运行时选择且无回落的窄适配器场景才有条件可行。仅文档（`docs/_wip`），不改 Runtime、服务或配置。 [PR #818](https://github.com/whshang/herdr-mcp/pull/818)

## 已知限制

- 本版本是预发布，仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。MacBook Pro PROD 升级/回滚/再次升级验收已于 2026-11-01 完成（[#728](https://github.com/whshang/herdr-mcp/issues/728) 已关闭），但本 RC 自身的 PROD 复验仍需执行。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展包，且扩展源码改动没有提升版本号（仍是 0.1.229），必须手工重载才能生效。
- native host 日志是尽力而为的有界实现：1 MiB 轮转 × 3 份、锁竞争或不可写时直接丢弃事件；没有多日轮转 soak，也未在 Windows/macOS 上实跑过 host 进程的日志路径（#825）。
- 定时 `update auto` 的跳过与调度器重注册只在注入的 launchctl runner 下测过；真实 PROD LaunchAgent、launchd `gui` 域与已安装 generation 未在本 RC 触碰，仍需人工验证（#824）。
- #786 的待重放轮次只存在于 service worker 内存：MV3 休眠/重启会丢弃该轮次（不落盘、不排队）。
- #811 的闸门只在明确的 404 `continuity_not_found` 时关闭接力；超时、传输失败与 5xx 仍显示为可用，点击后 fail-closed。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持，只给出 `caller_browser_on_other_device` 原因（#775）。
- 设备级 `*/*/*` WebChat grants 已由 Edge 部署与审计，但 Runtime 仍丢弃它们、不用于派发；1.1 合格路径是 endpoint + provider grants。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- Runtime 更新不执行 Worker 更新；Worker 落后时只报告 `worker_update_required`，必须由操作员单独执行 `herdr-mcp worker update`。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- doctor 的 WebChat grant 状态仍只基于本地证据（Edge 没有可读的 grant 列表接口），`absent_locally` 不代表 Edge 侧一定没有 grant。
- herdr-core / Herdr app 仍不受支持：v1.1 只支持 Herdr TUI，#818 记录的探测结论是不能作为 18 工具契约的直接后端。
- ETXTBSY 重试是有界的（10 次 × 20ms）：持续被写描述符占用的候选仍会失败，只是不再偶发。
- 未配置 `GH_TOKEN` / `GITHUB_TOKEN` 时仍受匿名 60/h 配额限制，#739 只改善限流错误的信息量。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**（`contracts/` 未修改）。
- First-party Public Edge contract：epoch **8 / 19 actions**（未修改；#807 只更正发布文档措辞）。
- Durable Runtime state：schema **16**（本 RC 无新迁移）。
- 浏览器扩展：版本字符串 **0.1.229**（#812 / #815 / #816 只改源码）。新扩展对 rc.10 及更早的 Runtime 有 N-1 回退：`browser_registry_params_invalid` 时重发旧四字段 `source_turn.observe` 一次并记住该结果；旧扩展连新 Runtime 无需改动。
- Link 传输：传输层 ping 30s、最大静默 90s、应用心跳 300s（#809）。这是传输参数而非 wire schema/协议变更，不与 Edge 做版本协商。

- 旧↔新兼容证据：13 项可重复检查（#821）覆盖「新扩展 + rc.10 Runtime」的 N-1 回退、rc.10 payload 仍被当前 Runtime 接纳、schema 16 与迁移数量两侧相等。未覆盖 live `update`/`major-rollback`/generation 激活、Windows/Linux service-manager 回滚与真实 Chrome UAT，这些仍由 #728/#800 与「人工 UAT」拥有。
- native host 日志（#825）：新增 `<config dir>/native-host/native-host.log`（1 MiB 轮转、2 份备份、`0600` 文件 / `0700` 目录、非阻塞 `flock`），不改变 Native Messaging 协议、contract 或 state schema；删除该目录即移除产物。
- CI / release gate 固定 Herdr TUI：**0.9.5**（未变）。
- Edge → Runtime 集成 harness（#820）只新增 `edge/cloudflare/tests/**` 与一个 Rust job CI 步骤（外加 `edge/cloudflare/README.md` 说明），不修改 Runtime/Edge 生产代码、wire schema、contract 或 state schema，也不改变任何用户可见行为。
