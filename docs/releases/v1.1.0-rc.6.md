# Herdr MCP v1.1.0-rc.6

v1.1.0-rc.6 是 1.1 的第六个预发布，仅面向 **preview** 更新通道。它加入多 Agent 编排能力（显式父会话绑定、worker 合约、决策闸门、角色目标与并发上限，[#748](https://github.com/whshang/herdr-mcp/issues/748)–[#751](https://github.com/whshang/herdr-mcp/issues/751)），并修复 MacBook Pro PROD 验收（[#728](https://github.com/whshang/herdr-mcp/issues/728)）中 `@herdr-mcp` 提及时仍出现的 `source_turn_not_found`（[#754](https://github.com/whshang/herdr-mcp/issues/754)、[#759](https://github.com/whshang/herdr-mcp/issues/759)）。stable 用户继续留在 1.0.x。

## 升级

已处于 epoch 5 的 v1.1.0-rc.1 – rc.5 用户，在 preview 通道使用 `herdr-mcp update` 升级到 v1.1.0-rc.6。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

从 v1.0.x（epoch 4）出发的路径仍为两步（与 rc.5 相同）：

```text
v1.0.x（epoch 4）
  → v1.0.4 bridge（epoch 4，stable 通道，同一 contract identity）
  → v1.1.0-rc.6（epoch 5，preview 通道，签名清单声明 contract_migration）
```

**浏览器扩展升级顺序：** 先升级或重载浏览器扩展到 **0.1.229**（或更新），再切换 Runtime。Runtime 自更新不会更新扩展。

**⚠️ 状态库迁移 16（不可降级）：** 首次启动 rc.6 会把 Runtime state 从 schema 15 迁移到 schema **16**（新增决策闸门表）。迁移后 rc.5 及更早的二进制会拒绝打开该数据库。升级前请备份 Runtime state 目录；如需回退到 rc.5，必须先恢复迁移前的 state 备份，再回滚二进制。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.6、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **显式任务身份与父会话绑定（#748）：** `agent.task.dispatch` 可选 `inject_task_identity`（把 task id 注入 worker 提示）与 `parent_session_ref`。WebChat 调用方只能绑定**自己已持有的**持久 caller-session 映射且必须与该 ref 完全一致；无映射时返回 `explicit_parent_session_caller_session_unmapped` 且不回退到其他证据，显式 ref 永不新建映射，杜绝认领他人会话。 [PR #752](https://github.com/whshang/herdr-mcp/pull/752)
- **Worker 合约：心跳、完成报告与卡住检测（#749）：** 新增仅限受信本地 IPC 的 `task_report`（`heartbeat` / `worker_done`，同一任务只接受一次 `worker_done`）；任务状态与 inbox 暴露基于 `updated_at_ms` 与 `stall_after_ms`（默认 20 分钟，范围 1–120 分钟）的 liveness / `stall_suspected`；`wait` 超时改为 `outcome:checkpoint` 的成功快照而非失败。新增字段均可选，旧任务记录可直接读取。 [PR #753](https://github.com/whshang/herdr-mcp/pull/753)
- **人类专属决策闸门（#750）：** 任务可携带一个阻塞式决策闸门（create / status / cancel 按父会话限定作用域）；闸门打开时任务不可 ack、不可完成。任何 MCP / 受信 IPC / WebChat / 浏览器 / Agent 路径调用 `agent.task.gate.resolve` 一律返回 `gate_resolution_requires_human`；唯一的解决途径是本地交互式 CLI `herdr-mcp agent gate resolve`（要求前台受控 TTY、精确重输选项，并拒绝在受管 pane / exec 内运行）。这是尽力而为的本地人工确认，不是强身份证明。引入 state schema 迁移 16。 [PR #756](https://github.com/whshang/herdr-mcp/pull/756)
- **角色目标与并发上限（#751）：** dispatch 目标支持 `@idle`、`@<kind>`、`@<kind>:idle`，按实时快照顺序选择第一个空闲 pane（可用 `workspace_id` 限定，排除调用方自身并沿用委派守卫）；`@all` 与未知语法直接拒绝。`max_concurrent`（1–16）按父会话 / 父目标 / 全局作用域统计同一选择器的未结束任务（含打开闸门），并发提交在注册前串行化。幂等重放返回原始解析结果。 [PR #757](https://github.com/whshang/herdr-mcp/pull/757)
- **来源轮次规范化覆盖所有前导提及形式 + 未绑定诊断（#759）：** Runtime 规范化时去掉前导的 `@name` / `$name` / 裸 `name`（`herdr`、`herdr-mcp`、`herdr_mcp`，不区分大小写，后接空白、换行、`:`、`：`、`,`、`，`、`-`、`—` 或结尾），并解开整体包裹的单反引号或三反引号代码块；文中裸 `herdr` 仍为用户文本。绑定仍只按精确哈希，无模糊或时间窗回退。未绑定时 `parent_session.diagnostic` 只给出规范文本前 24 字符、12 位摘要前缀，以及调用方自身会话最新来源轮次的 12 位摘要前缀。 [PR #760](https://github.com/whshang/herdr-mcp/pull/760)
- **浏览器扩展 0.1.229（#754）：** 手动 `@herdr-mcp` 发送重新记录来源轮次。提交-气泡校验增加去除 App 提及后的规范比较，识别已接受气泡中的 `data-prompt-link-href=app://…` 提及芯片，并在发给 Runtime 的来源文本中省略 Herdr 提及。 [PR #755](https://github.com/whshang/herdr-mcp/pull/755)

## 已知限制

- 本版本仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 MacBook Pro PROD 升级/回滚验收（#728）。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- 决策闸门的人工确认是尽力而为的本地交互检查（前台 TTY + 精确重输），不是强人类身份证明；Bot / Agent 的批准永远不算人工批准。
- 升级前按旧规范形式记录的来源轮次摘要，在新规则下可能不再匹配；升级后在会话中重新发送一轮消息后再 dispatch（旧行 24 小时内过期）。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- 设备重新注册后旧 device id 的过期 browser endpoint 仍可能导致 `browser_canonical_url_ambiguous`（1.1.x，#734）。
- 设备级 WebChat 授权（#713 / #730）推迟到 1.1.x。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**（新能力为现有工具的方法与可选参数）。
- First-party Public Edge contract：epoch **8 / 19 actions**。发版 PR 只改变 Edge 报告的 MCP server 版本字符串。
- Durable Runtime state：schema **16**（编号迁移，前向不可降级）。
- 浏览器扩展：0.1.229。Runtime 自更新不更新 Browser Extension。
