# Herdr MCP v1.0.0

Herdr MCP 1.0 is the first stable release of the multi-device Web AI ↔ workstation control plane. ChatGPT is the reference WebChat provider; Claude and Grok remain compatibility providers with signed-in dispatch/result support, while Gemini is outside the stable 1.0 support claim.

The release keeps the existing enrolled Worker, OAuth/Connector identity, devices, durable state, and rollback boundaries. Browser-extension delivery remains a separate release plane from the Runtime.

## Upgrade from v0.4.8 / v0.4.9

For an ordinary installed v0.4.8 or v0.4.9 user, the stable upgrade command is:

```bash
herdr-mcp update
```

A v0.4.8 installation uses the published v0.4.9 migration bridge automatically to cross durable state schema 5 → 15. The bridge is not installed as the production service: it verifies the final v1.0.0 Runtime, delegates to the qualified major migration, preserves the exact v0.4.8 binary/database snapshot for N-1 rollback, and then reconciles the existing Cloudflare Worker in place. Existing Worker public origin, Durable Objects, secrets, OAuth issuer, devices, Connectors, and known optional bindings remain intact. Users do not recreate the Worker, re-pair devices, or re-add ChatGPT.

Cloudflare browser authorization may open while the existing Worker is reconciled. If more than one accessible Cloudflare account contains the same proven Worker identity, the update fails closed until the account is disambiguated.

After upgrade, verify:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
herdr-mcp doctor
```

For the v0.4.8 major migration boundary only, the qualified N-1 recovery command is:

```bash
herdr-mcp update major-rollback
```

Rollback restores the preserved v0.4.8 binary and schema-5 snapshot and intentionally discards durable state created after the migration.

## Main changes

- **Direct WebChat control and reliable ChatGPT handoff.** 1.0 can create/open supported WebChat conversations, dispatch work, observe durable provider settlement, archive task-owned sessions, and continue one durable Continuity chain without blind replay. Fresh ChatGPT Project creation now has explicit cleanup/retry semantics and the final App-identity / bounded-submit invariants are regression-pinned. [PR #517](https://github.com/whshang/herdr-mcp/pull/517) [PR #537](https://github.com/whshang/herdr-mcp/pull/537) [PR #538](https://github.com/whshang/herdr-mcp/pull/538)
- **Durable asynchronous Agent tasks.** Parent planners can submit child work once, receive stable task/dispatch identity immediately, continue independent work, and consume durable terminal/inbox evidence later instead of blocking on a worker's global state. Delivery uncertainty remains terminal evidence and is never replayed automatically. [PR #530](https://github.com/whshang/herdr-mcp/pull/530)
- **Semantic/Jev assistance without a new authority.** Browser Auto and planner/task boundaries can use the provider-neutral semantic route pool for typed evaluation or chat judgment, while permissions, delivery, idempotency, account identity, cleanup safety, and required validation remain deterministic. Missing or failed semantic configuration preserves existing behavior. [PR #499](https://github.com/whshang/herdr-mcp/pull/499)
- **Safer model-visible MCP results and simpler planner contracts.** Herdr-generated advisory prose is removed from model-visible tool metadata while factual delivery/status fields and caller-owned stdout/stderr remain intact. The bundled remote-planner Skill is substantially smaller and puts the high-risk connected-tool call shapes up front. [PR #539](https://github.com/whshang/herdr-mcp/pull/539) [PR #540](https://github.com/whshang/herdr-mcp/pull/540) [PR #541](https://github.com/whshang/herdr-mcp/pull/541)
- **Multi-device routing and fresher fleet health.** Device identity remains explicit and fail-closed across enrolled workstations, while Edge now refreshes runtime health immediately after a validated Link reconnect instead of presenting stale offline health as current state. [PR #542](https://github.com/whshang/herdr-mcp/pull/542)
- **Stable 1.0 upgrade/rollback boundary.** Runtime schema 15, Runtime Execution epoch 4, first-party Public Edge epoch 7, the v0.4.8 → v1.0 migration bridge, transactional installed generations, and published-artifact verification form one release lifecycle rather than requiring manual binary replacement. [PR #409](https://github.com/whshang/herdr-mcp/pull/409) [PR #417](https://github.com/whshang/herdr-mcp/pull/417)

## Platform qualification

- **macOS Apple Silicon — Production.** Native Runtime, production Link, updater/rollback, stable TCC broker, Native Messaging, browser control and protected-root operation have physical-machine qualification.
- **Linux x86_64 — Production.** Native systemd/user-process lifecycle and static `x86_64-unknown-linux-musl` release artifact are supported.
- **Linux ARM64 / aarch64 — Production.** Physical NanoPi R5C qualification covers the native Linux Link/lifecycle path and the static `aarch64-unknown-linux-musl` artifact.
- **Windows x86_64 — Candidate.** Physical installation/recovery and real Connector use have been exercised successfully, but the support matrix keeps the formal Production promotion separate until the exact-current-main #394 promotion record is closed.
- **Windows ARM64 / aarch64 — Candidate.** Native release build qualification exists; physical ARM64 UAT is still open.
- **WSL — Unsupported.**

## Known issues

- Windows x86_64 and ARM64 remain **Candidate** support in the published matrix until their separate Production-promotion records are complete.
- Browser-extension DEV / STANDALONE / Chrome Web Store distribution is versioned and published independently from the Runtime. The Runtime v1.0.0 GitHub Release does not imply that a Chrome Web Store review has completed.
- ChatGPT is the 1.0 reference provider. Claude and Grok are compatibility providers and are not claimed to have ChatGPT-equivalent automation/Planner behavior. Gemini is outside the stable 1.0 provider scope.

## Compatibility

- Workstation Runtime Execution Contract: epoch **4**, **18 tools**.
- First-party DEV/PROD Public Edge contract: epoch **7**, **19 actions**.
- Durable Runtime state: schema **15**; stable v0.4.8 uses schema 5 and upgrades through the v0.4.9 bridge.
- Published Runtime targets: `aarch64-apple-darwin`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-pc-windows-msvc`, and `aarch64-pc-windows-msvc`.
- MCP/OAuth origin, enrolled-device identity, approved Connector identity, and existing Worker public origin are retained across a successful upgrade.
- Browser control, Tool Bridge, workstation mutation, and Planner authority remain separate consent/capability boundaries.
