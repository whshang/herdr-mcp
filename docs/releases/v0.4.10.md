# Herdr MCP v0.4.10

v0.4.10 is a bounded recovery bridge for machines that already run v0.4.9 as their production Runtime. It stays on the frozen v0.4.x Runtime Execution Contract and durable state schema 5. It does not backport 1.x product behavior.

## Upgrade from v0.4.9

After stable v1.0.3 is published, the ordinary user action remains:

```bash
herdr-mcp update
```

The immutable v0.4.9 updater can discover v0.4.10 because this maintenance release still publishes the legacy `release-manifest.json` with schema 5 and Runtime epoch 2 identity. v0.4.10 then runs the existing detached migration bridge and accepts only an attested stable final Runtime at **v1.0.3 or newer** that also matches the frozen qualified schema-15 / Runtime epoch-4 / 18-tool contract.

The active schema-5 source Runtime remains authoritative until the final Runtime passes `update major-apply`. Rollback material records the exact source binary and schema-5 snapshot, whether that source is v0.4.8 or v0.4.9.

After the update completes, verify the final active Runtime:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
herdr-mcp doctor
```

## Main changes

- Restore the ordinary update path for production v0.4.9 installations with a legacy-manifest maintenance bridge, and fence the final Runtime to v1.0.3+ while retaining the existing schema/contract/provenance checks. [PR #568](https://github.com/whshang/herdr-mcp/pull/568)

## Known issues

- Publish stable v1.0.3 before publishing v0.4.10. The bridge intentionally refuses v1.0.0-v1.0.2 because those releases do not contain the complete field upgrade fixes.
- The schema-5 major migration bridge remains supported only on macOS and Linux; Windows stays outside this 0.4.x bridge path.
- Final published-artifact acceptance still requires a real v0.4.9 machine and the immutable GitHub Release artifacts; source qualification alone does not replace that field UAT.

## Compatibility

- Bridge Runtime Execution Contract remains **epoch 2 / 18 public tools**.
- Bridge durable state remains **schema 5**.
- The bridge itself continues to use legacy `release-manifest.json`.
- Browser Extension, public Edge contract, Worker OAuth/device/Connector identities, and user Worker deployment are unchanged by the bridge release itself.
- Successful migration lands on the already-published stable v1.0.3-or-newer Runtime, where the 1.x upgrade fixes are owned.
