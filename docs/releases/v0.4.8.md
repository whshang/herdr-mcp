# Herdr MCP v0.4.8

## Upgrade from v0.4.5

v0.4.6 and v0.4.7 were withdrawn and are not stable upgrade bases. The supported stable upgrade base for v0.4.8 is v0.4.5; an existing v0.4.5 installation upgrades through the normal release-metadata path:

```bash
herdr-mcp update check
herdr-mcp update
```

A machine that previously installed a withdrawn v0.4.6/v0.4.7 candidate uses the same command. The runtime update preserves the local configuration and enrolled-device identity; it does not require re-pairing a healthy device merely because the runtime version changes.

Then verify:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

`herdr-mcp doctor` reports layered service/local-auth/remote-auth evidence. Exit 0 means no known failure was found in the layers that were actually probed; use `DOCTOR_JSON.overall` to determine whether end-to-end readiness was proved.

## Main changes

### ChatGPT Connector authorization and lifecycle

- Fresh ChatGPT authorization requests no longer inherit approval from the shared public `https://chatgpt.com/oauth/client.json` client id. Distinct state/PKCE requests require independent owner approval, while an exact request-bound retry remains idempotent. This prevents one ChatGPT account or a genuinely new connection from silently reusing another account's approval. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Fix the approval completion path that could stop polling after a pending HTTP 202 response even though the CLI later approved the request. The approval page now continues polling correctly and retains an explicit **Continue to ChatGPT** navigation fallback after approval. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- `connector revoke <conn_...>` now remains an instance-scoped revoke and fences only credentials attributed to that Connector. `connector revoke-client <client-id>` remains the explicit client-wide kill switch. Fresh token issuance also fences older refresh/access credentials belonging to the same logical Connector without touching sibling Connectors. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- OAuth discovery now advertises an RFC 7009 `/oauth/revoke` endpoint. Revocation authenticates the OAuth client, resolves the presented access/refresh credential to its exact Connector instance, and retires only that instance; unknown or wrong-owner tokens do not become a shared-client revoke. Real ChatGPT UAT confirmed that ChatGPT's current Disconnect/remove UI does not reliably call this endpoint, so provider-side Disconnect is not treated as proof of server-side revocation. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Connector inventory retains a stable `connector_name`, authorization time, and throttled last real MCP-use time. Operators keep exact instance cleanup through `connector revoke <conn_...> --confirm`, while the existing Worker cron performs a bounded inactivity sweep once per day: an active Connector with no Connector activity for 30 days is revoked with reason `inactive_30d`, only that instance's access/refresh credentials are deleted, and its non-secret audit row is retained. Real MCP use persists `last_used_at_ms` immediately on first use and at most once per 24 hours thereafter to bound Durable Object writes. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Fresh ChatGPT authorization now fails before owner approval when ChatGPT was configured with the Worker site root instead of the MCP endpoint. The error page tells the user to use the full `https://<host>/mcp` server URL and creates no approval or Connector grant, avoiding the otherwise-late ChatGPT callback `424` / `Resource not found` failure. Existing Connector tokens and legacy resource normalization at the token endpoint are unchanged. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- `connector list` defaults to actionable/current records and `connector list --all` includes revoked/history. Inventory now distinguishes all-stored token counts from counts attributable to the displayed rows so filtered views cannot silently disagree with their summary. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)

### Runtime reliability and diagnostics

- `herdr_git diff` surfaces bounded metadata for untracked files instead of silently omitting them. Secret-like paths remain hidden, staged diffs remain staged-only, binary/large-file classification is bounded, symlinks are not followed for sampling, and truncated porcelain output never manufactures a partial path. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Add regression coverage for repeated stateful `initialize`, stale-session recovery, stateless ChatGPT/OpenAI reconnect behavior, and restart recovery without expanding the frozen MCP contract. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- `doctor` separates service health, authenticated local MCP, and authenticated remote MCP readiness. An unauthenticated public `/mcp` or metadata probe can no longer be presented as proof that the user's real Connector path is ready. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Utility-pane contention errors now carry explicit conflict/retry/delivery metadata, and CLI output handles a downstream Broken pipe without turning a successful command into a panic failure. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Live Herdr schema reflection now resolves managed `~/.local/bin/herdr` (plus explicit/fixed install locations) instead of assuming `herdr` is present in the service PATH. This keeps Debian `systemd --user` installs with a minimal PATH from reporting a false `validated Herdr RPC` failure, and `doctor` now distinguishes the live Herdr schema from the local progressive-method fallback. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Linux generation reconciliation now updates the exact plain `runtime-control.json` / `runtime-status.json` files consumed by the native Linux Link instead of allowing the historical macOS `*-prod.json` siblings to take precedence. This prevents a `systemd --user` Link restart from following stale `desired_active` state after an install or update. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Herdr 0.9 endpoint capabilities are now surfaced by `herdr_inspect` as `herdr_capabilities` plus `endpoint_protocol_generation`, while older Herdr servers remain compatible with null capability fields. Saved Herdr SSH machines and herdr-mcp Edge devices remain separate identity namespaces even when both control paths reach the same physical workstation: shared pane/agent/filesystem state may be observed from either path, but bare workspace/pane ids are never treated as globally unique and an uncertain Edge mutation is never silently replayed over SSH. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)

### Qualification and release hygiene

- CI uses the reviewed `sccache` action for Rust compilation while keeping pull-request cache writes read-only. Development/test builds also reduce nonessential debuginfo and use Cargo 1.97's shared intermediate `build-dir`, while final binaries remain in each worktree's own target directory. On the qualified Apple Silicon host this reduced a clean `cargo test -p herdr-mcp --no-run` from 204.15s to 116.11s and reduced the measured cold target footprint from about 1.9 GB to 1.3 GB. The release profile is unchanged. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Historical v0.4.6/v0.4.7 release notes are marked as withdrawn candidate history, and the repository release policy now explicitly distinguishes automated qualification from real target-client UAT. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- The exact final release source passes the normal PR CI plus the non-publishing Rust Release qualification lane: authoritative verify, Windows x64, static Linux x86_64 musl, macOS arm64, Edge bundle, manifest, artifact attestation, and source-identity qualification. The exact Linux artifact is also installed on a real Debian `systemd --user` host and must converge `runtime/current`, service/Link generation, plain runtime-control state, and Edge generation before publication; the final macOS arm64 artifact receives a lightweight execution/no-regression check, and production Edge is deployed only after its own contract/root regression gate. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Restore an official x86_64 Linux release target as `x86_64-unknown-linux-musl`, with a static-artifact smoke gate and manifest/recovery coverage. v0.4.8 also closes the Debian installation loop: `herdr-mcp install` manages an immutable user runtime, prefers `systemd --user` service/Link units on normal Debian sessions, and falls back to an exact-PID/start-time-checked detached user-process backend when no user systemd manager exists. Linux stores enrolled-device credentials in a private `0700`/`0600` per-user store; first-device `worker bootstrap`, existing-fleet `worker pair`/`worker connect`, device administration, Connector owner operations, and automation administration all use the platform credential backend rather than assuming macOS Keychain. `worker connect` performs transactional pairing/activation with compensation. A Linux service generation change now also reconciles the already-running Link, preventing Edge from continuing to reserve the previous runtime generation after an in-place upgrade while preserving the enrolled device identity. The native updater now uses the same attested manifest/download/durable-job flow on Linux and activates through the transactional Linux service installer; only the resident daily scheduler remains a macOS launchd integration, so Linux uses manual `update apply`/`update auto` or an external scheduler. Runtime inspection does not apply the macOS launchd migration-cutover seal/gates to Linux, so a native Linux runtime is not mislabeled as a migration candidate after a successful install. The process fallback is intentionally not a boot/crash supervisor; long-lived hosts should still use systemd or an external container supervisor. Browser Native Messaging and macOS TCC/Keychain integration remain macOS-specific. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)

## Known issues

- Fresh ChatGPT Connector UAT passed on 2026-09-08 without DevTools intervention for the supported user path: canonical `/mcp` endpoint → independent owner approval → automatic return to ChatGPT → token issuance → actual Herdr MCP tool call → reconnect and another real tool call. The same UAT established that ChatGPT Disconnect is not a reliable OAuth-revocation signal; v0.4.8 therefore relies on exact manual instance revoke plus the 30-day inactivity GC described above instead of blocking publication on a client-side `/oauth/revoke` behavior ChatGPT does not provide. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Clean existing-fleet installation UAT passed on 2026-09-08 using the exact Apple Silicon v0.4.8 candidate on a new M-series Mac: install → Full Disk Access/TCC verification → short-lived `worker connect` → immutable device enrollment → service/Link/generation/credential checks → `doctor` → an actual ChatGPT Herdr request explicitly routed to the new device. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)
- Issue #302 clean first-Worker bootstrap and the normal published-release `update apply` path are deliberately moved to post-release production acceptance rather than requiring another dedicated pre-release environment. Pre-publication source/artifact/service-manager qualification is complete at the boundary described above. Immediately after the stable v0.4.8 Release exists, production acceptance should exercise both a clean first-Worker bootstrap and the normal attested `update apply` path from an older installed version, verifying that service/Link generation changes preserve the immutable device identity and real MCP routing. GitHub-runner compilation remains qualification evidence, not a substitute for those production paths. [PR #344](https://github.com/whshang/herdr-mcp/pull/344)

## Compatibility

- Workstation Runtime Execution Contract remains **epoch 2 / 18 public tools**. No public runtime tool was added or removed.
- Public Edge contract remains **epoch 3 / 19 actions**. The stable MCP/OAuth resource remains `https://herdr-mcp.agentforme.cc.cd/mcp`.
- The v0.4.x maintenance runtime remains on **state schema 5**; this release does not adopt the separate 1.0 development schema.
- Pre-v0.4.6 OAuth credentials remain compatible unless explicitly revoked. New explicit Connector authorization uses request-bound owner approval and instance-scoped credential attribution.
- Device enrollment and Connector authorization remain separate control planes: one authorized ordinary Connector may route to enrolled devices according to the existing device-routing rules; authorizing a Connector does not pair or authorize a new workstation.
