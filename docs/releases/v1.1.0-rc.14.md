# Herdr MCP v1.1.0-rc.14

v1.1.0-rc.14（2026-11-03）是 1.1 的第十四个预发布，仅面向 **preview** 更新通道。相对 rc.13，它合入五项修复：每次升级只做一次有界、经 TCC broker 路由的 `~/Documents` 预检，Documents 探测不再阻塞请求路径（#844/#845）；扩展按 user-id 命名空间读取 ChatGPT 账号身份，Project 作用域的 `webchat create` 不再误报 `id_conflict_unverified_email`（#847/#849）；ChatGPT 标题投影按阶段分配超时并校验 readback，ChatGPT 自动标题后重新应用标签（#421/#850）；`--required-app` 的 App pill 在 Runtime 与扩展两侧的接受摘要中一致归一化（#848/#851）；herdr 创建的会话与隐藏的 ChatGPT 标签页记录来源轮次，使 dispatch 能绑定父会话（#846/#852）。扩展版本 0.1.240 → **0.1.243**。本版本没有新的 state 迁移（schema 16），Runtime contract epoch 5 / 18 tools、Edge epoch 8 / 19 actions 与 Herdr TUI 固定版本 0.9.5 均不变。这是**预发布**，stable 用户继续留在 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 – v1.1.0-rc.13 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.14（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。从 v1.0.x（epoch 4）出发的路径仍为 v1.0.4 → [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5) → v1.1.0。

**⚠️ macOS：本次升级会有一次性的 Documents 重新授权。** #845 为 TCC broker 增加了 `__documents-alias-probe` / `__documents-alias-ensure` 子命令，`BROKER_COMPAT_REVISION` 从 4 升到 **5**。由新下载的 rc.14 detached 更新任务在服务安装成功后按 **migrate → preflight → stage** 顺序执行：先迁移 broker（仅写配置目录，不触碰 Documents），再做唯一一次有界（2 s）的 Documents 预检，因此该提示归属于之后保留的 broker 身份。已安装 rev 4 broker 的 macOS 机器（例如受保护目录下有 STANDALONE 扩展别名的 PROD 机器）预计会看到**恰好一次** macOS「访问文稿文件夹」提示，请点击「允许」。提示未应答期间请求路径不再被阻塞：`update apply` 结果、`update status` 与 `doctor` 报告 `tcc_prompt_pending`，别名检查报告结构化的 `tcc_pending`。若迁移无法执行，更新仍然成功，别名检查报告 `broker_outdated`，下一步为 `herdr-mcp permissions setup --upgrade-broker`。

**⚠️ 浏览器扩展：升级后必须重载扩展。** 本 RC 改动了 `extension/**`，扩展版本字符串从 0.1.240 升到 **0.1.243**。已有 STANDALONE 安装的机器，`update apply` 会由新下载的 rc.14 二进制重新暂存为 0.1.243（manifest `key` 与扩展 ID 不变，目录 `0700`、文件 `0600`），但浏览器仍运行已加载的旧代码：**升级后请在 `chrome://extensions` 对 Herdr MCP 扩展点击「重新加载（Reload）」**。重载前 `herdr-mcp doctor` 显示 `reload_pending`。

**⚠️ 状态库迁移不可降级：** schema 16 由 rc.6 引入，rc.7 – rc.14 无新迁移；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录。

**Worker 更新是独立步骤：** `herdr-mcp update` / `update apply` / `update auto` 只更新 Runtime；Worker 落后时单独执行 `herdr-mcp worker update`（需要交互式 Cloudflare 授权）。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
herdr-mcp update status
```

确认 Runtime 为 1.1.0-rc.14、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线；`doctor` 的 `standalone-extension-version` 在重载扩展后应为 `current`，TCC 预检不再为 `tcc_prompt_pending`。

## 主要变更

- **每次升级一次有界、经 broker 路由的 Documents 预检（#844）：** 每次 Runtime 升级都会安装新的 ad-hoc 签名 generation，macOS 将其视为新的 `~/Documents` 客户端；过去 Documents 探测在请求路径上内联执行，一个未应答的提示（rc.13 事故中约 14.5 分钟）会让无关请求 `request_timeout`。现在 helper 与请求路径不再在进程内探测 `~/Documents`，别名的检查与创建都经已安装的稳定 broker 执行（退出码 0 ready / 66 missing / 67-68 occupied / 70-71 失败 / 77 denied，1 保留给不认识子命令的旧 broker → `broker_outdated`）；更新 worker 按 migrate → preflight → stage 顺序执行，结果持久化到 `update/tcc-broker-migration.json` 与 `update/tcc-preflight.json`，`update status` 与 `doctor` 只读这些记录而不探测。native host 不再调用 `getcwd`，受保护路径先做词法归一化与判定。 [PR #845](https://github.com/whshang/herdr-mcp/pull/845)
- **按 user-id 命名空间读取 ChatGPT 账号身份（#847）：** 身份提取过去把 `/backend-api/me` 的 user id 与 `/api/auth/session` 的顶层 workspace `id`、`user.id`、`account.id` 混为一个值，可能对同一登录账号报告冲突，使 Project 作用域的 `webchat create` 以 `browser_create_scope_unavailable` / `registry_handshake_delay` fail-closed。现在只在 user-id 命名空间内比较，`account.id` 不再被提升为用户身份。 [PR #849](https://github.com/whshang/herdr-mcp/pull/849)
- **ChatGPT 标题投影 readback 校验与自动标题后重新应用（#421）：** 过去 token 读取、基线读取、PATCH 与 readback 共用一个 3 s 截止，PATCH 实际只剩约 1 ms，导致标题已生效却报 `title_projection_timeout`。现在按阶段分配预算，复用一个短期 token，从单数会话资源读标题，被中止的 PATCH 视为「不确定」由 readback 决定；`--required-app` 的标签在观察到助手轮次结束后，仅当当前标题仍是 ChatGPT 自动标题或基线时最多重新应用一次，用户手动改名绝不被覆盖，导航到其他会话时不写入。 [PR #850](https://github.com/whshang/herdr-mcp/pull/850)
- **App pill 在接受摘要两侧一致归一化（#848）：** `webchat create --required-app` 时 provider 把 App pill 存在同一用户轮次中，Runtime 只按原始消息比较、扩展只认 `@?<slug>`，导致已送达却报 `delivery_state=uncertain` / `readback_digest_mismatch`。Runtime 新增 `browser_expected_acceptance_digests`，按请求的 App 名生成 `@name` / `name` / `$name` 各种渲染的精确摘要集合；扩展使用基于 slug 的同一归一化并识别 `app://` prompt-link 芯片；共享 JS↔Rust fixture 锁定两侧行为，不匹配检测未被削弱。 [PR #851](https://github.com/whshang/herdr-mcp/pull/851)
- **herdr 创建与隐藏标签页记录来源轮次，dispatch 可绑定（#846）：** `session.create`（`webchat create`）过去不记录自己送达的轮次，扩展在 `document.hidden` 时也不上报来源轮次，ChatGPT 侧 `agent.task.dispatch` 因此 `source_turn_not_found`，#837 的 continuity 链无法附加。Runtime 新增 `record_browser_session_create_source_turn`，以 create 自身的结算证明为栅栏在单事务内写入；扩展在隐藏标签页仅在存在新鲜提交锚点时做精确文本匹配捕获，空闲隐藏标签页不做页面工作。 [PR #852](https://github.com/whshang/herdr-mcp/pull/852)

## 人工 UAT（切 tag 后由 release owner 逐项完成）

以下步骤**没有**在写本稿时执行，本稿不声称任何实时设备验收已完成：

- TCC（#844/#845）：在 macOS PROD 机器上 `update apply` 后确认 broker 迁移到 rev 5、tccd 日志中本次升级只有一次 Documents 提示、提示未应答期间 `herdr_exec` 不超时，应答后 `doctor` 不再报告 `tcc_prompt_pending` / `broker_outdated`。
- 扩展重新暂存为 0.1.243、扩展 ID 不变，重载前 `reload_pending`、重载后 `current`。
- Project 作用域 `webchat create --space-ref`（#847/#849）成功创建，不再 `id_conflict_unverified_email`。
- 标题投影（#421/#850）报告 `readback_verified=true`，`--required-app` 最终标题为 herdr 标签而非自动标题。
- `--required-app` create（#848/#851）为 `delivery_state=applied`。
- herdr 创建 / 隐藏标签页中的会话发起 dispatch（#846/#852）为 `parent_session.bound=true`，「接力」可用。

## 已知限制

- 本版本是预发布，仅供 preview 验证；正式 v1.1.0 GA 标签需 owner 另行批准。
- macOS 上从 rc.13 或更早升级会有一次 Documents 重新授权（broker 4 → 5）；之后的升级不应再因 broker 产生提示。
- Runtime 更新只重新暂存 STANDALONE 文件，浏览器不会自动重载扩展；必须手动 Reload。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持（#775）。
