# Herdr MCP v1.1.0-rc.8

v1.1.0-rc.8 是 1.1 的第八个预发布，仅面向 **preview** 更新通道。它修复 MacBook Pro PROD 验收（[#728](https://github.com/whshang/herdr-mcp/issues/728)）中发现的两个诊断问题：`herdr-mcp doctor` 对 WebChat 授权状态的误导性判断与已退役的扩展 consent 提示（[#791](https://github.com/whshang/herdr-mcp/issues/791)），以及 `browser_session.create` 被拒时丢失扩展拒绝原因（[#792](https://github.com/whshang/herdr-mcp/issues/792)）。两项均为 Runtime 内部变更。这是**预发布**，stable 用户继续留在 1.0.x。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 / v1.1.0-rc.7 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.8（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。

从 v1.0.x（epoch 4）出发的路径为 v1.0.4 → v1.0.5 → v1.1.0：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，stable 通道，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16，必须先通过 stable 通道的 `herdr-mcp update` 到达 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)。正式 v1.1.0 发布前，本 RC 仅用于 preview 验证。

**浏览器扩展升级顺序：** 扩展仍为 **0.1.229**（本版本无扩展变更）。先确认扩展为 0.1.229（或更新），再切换 Runtime。Runtime 自更新不会更新扩展。

**⚠️ 状态库迁移不可降级：** 从 schema 15 首次启动 rc.8 会迁移到 schema **16**（rc.6 引入，rc.7 / rc.8 无新迁移）；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.8、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **doctor 不再把本地无证据误报为 WebChat 授权缺失，并移除已退役的扩展 consent 提示（#791）：** WebChat grant 状态 `absent` 更名为 `absent_locally`（state DB 可读但本地没有授权使用证据，Edge 仍可能持有 grant），输出带 `authoritative=false` 与 `source=local_evidence|unavailable`；`absent_locally` / `unknown` 时给出实际下一步 `herdr-mcp connector webchat-control allow <connector-id> <device-id> <endpoint_ref> <provider> --confirm`（及 `allow-device` 形式）。已退役的每端点 WebChat Control 开关只显示为 `webchat_control=legacy_ignored stored_webchat_control=<raw>`，Tool Bridge 标志与 `consent_revision` 保留；各语言与 JSON 中删除 “extension consent gates browser control”。`doctor --json` 的 `webchat_grants` 新增 `authoritative`、`source`、`next_step` 与每端点 `consent.webchat_control: "legacy_ignored"` / `legacy_webchat_control_allowed`。只读、离线、不读取凭据，无迁移。 [PR #793](https://github.com/whshang/herdr-mcp/pull/793)
- **`browser_session.create` 被拒时返回扩展拒绝原因（#792）：** 以前所有被拒的 create 都返回 `code: rejected, reason: null`。现在按固定白名单（14 个扩展错误码，如 `browser_create_composer_busy`、`browser_create_composer_unavailable`、`browser_adapter_not_ready`、`chat_mode_switch_failed`）把匹配的错误码填入顶层 `reason` 与 `delivery_evidence.error`；`browser_create_composer_busy` 另附白名单化的 `composer_busy_probe`（仅布尔值与上限计数，无 DOM 文本）和 `hint`（例如提示 composer 中可能有恢复的 ChatGPT 草稿，清空后重试）。非白名单字符串仍被丢弃，隐私姿态不变；首次尝试与 reconcile 两条路径一致，每次被拒写一行不含用户文本的日志。App 拒绝（`required-app-*`）词汇不变。 [PR #794](https://github.com/whshang/herdr-mcp/pull/794)

## 已知限制

- 本版本是预发布，仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 MacBook Pro PROD 升级/回滚验收（#728）。
- doctor 的 WebChat grant 状态仍只基于本地证据（Edge 没有可读的 grant 列表接口），`absent_locally` 不代表 Edge 侧一定没有 grant。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持，只给出明确的 `caller_browser_on_other_device` 原因（#775）；完整的 late-binding 推迟到 1.1.x（#771）。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- 设备重新注册后旧 device id 的过期 browser endpoint 仍可能导致 `browser_canonical_url_ambiguous`（1.1.x，#734）。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**（`contracts/` 未修改）。
- First-party Public Edge contract：epoch **8 / 19 actions**。发版 PR 只改变 Edge 报告的 MCP server 版本字符串。
- Durable Runtime state：schema **16**（rc.8 无新迁移）。
- 浏览器扩展：0.1.229。Runtime 自更新不更新 Browser Extension。
