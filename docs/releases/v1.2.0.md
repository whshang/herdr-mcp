# Herdr MCP v1.2.0

v1.2.0（2026-11-18）是 1.2 稳定线的首个正式版本，集中交付 1.2 周期全部合入切片：Node.js 版 Link/Server 正式退役、Runtime Execution Contract epoch 6 生效、S0–S7 本地传输与派发治理、HANDOFF 投影与归档、跨设备租约与持久化幂等、首台 bootstrap 恢复、文本传输与凭据目录安全加固，以及 herdr-core 后端 Phase 1/2 窄只读适配。浏览器扩展版本从 `0.1.248` 升至 **`0.1.251`**；Durable Runtime state（**schema 16**）、Public Edge Contract（**epoch 8 / 19 actions**）、macOS TCC broker 兼容修订号（**5**）与 Herdr TUI 固定版本（**0.9.5**）保持不变。Node Server/Link 源码自仓库移除，生产 Link 在所有平台唯一归属 Rust runtime。

## 升级

已处于 v1.1.1（或同 schema 16 的 v1.1.x）的用户直接执行标准更新命令升级到 v1.2.0（版本边界 `v1.1.1` → `v1.2.0`，同 schema 16，无数据库迁移）：

```bash
herdr-mcp update
```

也可先执行 `herdr-mcp update check` 查看目标版本，再执行 `herdr-mcp update apply` 应用更新；源码 dogfood 环境若处于 `dev` 通道，请先切回生产快照或使用受支持的通道切换命令后再执行 `herdr-mcp update`。

- **⚠️ 浏览器扩展（`0.1.248` → `0.1.251`）：升级后请重载扩展。** 已安装 Standalone 扩展的机器在 `herdr-mcp update` 期间会自动将本地暂存目录刷新为 **0.1.251**（保留既有 manifest `key` 与扩展 ID）；升级完成后请在 `chrome://extensions` 对 Herdr MCP 点击「重新加载（Reload）」（或等待空闲自动重载），使 `herdr-mcp doctor` 中的扩展状态从 `reload_pending` 收敛为 `current`。Chrome Web Store 渠道扩展待商店审核通过后自动推送更新。
- **Fleet Worker 必须先或同步升级至兼容 epoch 6 的版本。** 本版本 Edge 兼容契约将 `runtime-exec-v6` 注册为当前运行契约，白名单为 `[epoch 6, epoch 5, epoch 4, epoch 2]`；部署自有 Cloudflare Fleet Worker 的用户在看到 `herdr-mcp update status` 提示 Worker 版本落后时，单独执行 `herdr-mcp worker update`（需本人完成交互式 Cloudflare 授权，原地更新不改变 Worker 域名、OAuth、设备配对与 Connector 身份）。Worker 未升级前，仅当双方协商落在白名单内的旧 epoch（5/4/2）时调用仍可服务。
- **遗留 `herdr-self-update` 脚本不再能改写 Rust 管理的服务。** 当 Rust runtime 持有生产服务时，旧 Node 更新脚本对服务的写操作被拒绝；请统一改用 `herdr-mcp update`。
- **跨代升级路径如实声明：** `v1.0.x`（epoch 4）→ v1.2.0 的历史桥接路径（经 v1.0.5 bridge + 签名清单 `contract_migration` schema 15 → 16）**未在本轮重新端到端演练**，仍按 v1.1.1 发布说明记载的两步路径执行；`v1.1.0-rc.1 – rc.5`（schema 15）同样沿用安装文档第 1 步的手动安装路径。需要执行跨代升级的用户请先在非生产设备演练。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor --local
herdr-mcp update status
```

确认 Runtime 为 `1.2.0`、contract epoch `6` / `18` tools、state schema `16`，service / local MCP 健康且 Link 在线；`doctor --local` 返回白名单进程/端口/配置文件的只读元数据快照；重载扩展后 `doctor` 的 standalone 扩展检查为 `current`。

## 主要变更

### Node Link/Server 退役与服务所有权

- **Node.js 版 Link 与 Server 正式退役，生产 Link 唯一归属 Rust runtime。** N1 将 Node 独有的 relay inbound projection 与 epoch1 frozen identity 断言移植到 Rust/Edge 测试并在文档中声明退役边界；N2 删除 Node 版 Link 与 Server 服务实现（`src/link/*`、`bin/herdr-link` 等；其余 TS 辅助模块与 `bin/` CLI 入口按兼容边界保留），不再保留 Node 作为任何生产路径的兼容回退；Rust generation rollback（`ServiceRollbackRecord` 状态机）不受影响。 [PR #988](https://github.com/whshang/herdr-mcp/pull/988), [PR #992](https://github.com/whshang/herdr-mcp/pull/992)
- **遗留 `herdr-self-update` 服务写守卫与 canary 文档清理。** 当 Rust runtime 持有生产服务时，遗留 `herdr-self-update` 脚本对服务的写操作被拒绝，防止旧脚本改写 Rust 管理的服务所有权；`AGENTS.md` 与 `docs/link-production-cutover.md` 中已删除的 Node Link canary 遗留表述同步清理为 `bin/herdr-extension-host` 兼容入口。 [PR #1027](https://github.com/whshang/herdr-mcp/pull/1027), [PR #1016](https://github.com/whshang/herdr-mcp/pull/1016)

### Runtime Execution Contract epoch 6 与传输治理（S0–S7）

- **Runtime Execution Contract epoch 6 生效，Edge 兼容白名单收敛为 `[epoch 6, epoch 5, epoch 4, epoch 2]`。** `herdr_call` 的 `params` 同时接受 JSON 对象与 JSON 字符串两种形态（epoch 6，`sha256:9221eb8c46009ed68f447b00fd3581ad7c9bd02d69053bd799f541937047ba6e`）；Edge 兼容契约将 `runtime-exec-v6` 注册为当前运行契约。 [PR #951](https://github.com/whshang/herdr-mcp/pull/951), [PR #1030](https://github.com/whshang/herdr-mcp/pull/1030)
- **S0 可观测性基线与 S7 本地诊断快照。** 每个 `tools/call` 结果信封新增 `transport`/`timing_ms`/`request_id`，link 守护进程新增重连与传输状态遥测；新增只读命令 `herdr-mcp doctor --local` 输出白名单进程、回环端口与配置文件的元数据快照（不读取内容、凭据或非白名单对象）。 [PR #952](https://github.com/whshang/herdr-mcp/pull/952), [PR #954](https://github.com/whshang/herdr-mcp/pull/954)
- **S1–S2 派发一致性与写幂等。** Edge 端 `herdr_ref_` 嵌套补全并在 `tools/call` 入口统一解析（冲突 `device_ref_conflict`）；`herdr_call` 接受可选 `client_request_id` 幂等去重并新增只读 `herdr_mcp.request.status`；`agent_working` 增加 `busy_kind` 占用分类。 [PR #985](https://github.com/whshang/herdr-mcp/pull/985), [PR #953](https://github.com/whshang/herdr-mcp/pull/953), [PR #984](https://github.com/whshang/herdr-mcp/pull/984)
- **S3–S6 长操作异步化、spawn 原子性、模型别名与 Link 心跳。** 长操作异步化 + parent wake 回执词表（`still_running`/`edge_proxy_timeout`）；spawn 原子性与 inbox 治理（receipt/ready/repair/archive），`agent.task.dispatch` 增加 readonly 与 `owned_paths` 审计回执，`spawn.worktree` 派发落地；model alias 校验、early-exit 与 run bounds；Rust Link 心跳 300s→30s 对齐 Edge status-reply 节奏。 [PR #957](https://github.com/whshang/herdr-mcp/pull/957), [PR #959](https://github.com/whshang/herdr-mcp/pull/959), [PR #990](https://github.com/whshang/herdr-mcp/pull/990), [PR #998](https://github.com/whshang/herdr-mcp/pull/998), [PR #955](https://github.com/whshang/herdr-mcp/pull/955), [PR #958](https://github.com/whshang/herdr-mcp/pull/958)
- **`herdr_inspect` 增量游标与重复字段弃用。** 读取工作站快照前返回 `since_cursor`，后续增量读取经 `herdr_since` 返回窗口内事件；顶层 `semantic_judgment` 与嵌套 `workstation_info.native_migration` 正式弃用（分别改读 `semantic`/`native_migration`）；非法游标以 `invalid_params` 拒绝。 [PR #983](https://github.com/whshang/herdr-mcp/pull/983)

### HANDOFF、跨设备租约与持久化幂等

- **HANDOFF 收口：投影、去重与归档。** `work.pickup` 不再原样返回整份渲染文本：新增 `limit_per_section`/`sections[]`/`query`/`include_archived`/`include_markdown`/`max_bytes` 参数与 `projection {v:1}`/`truncated` 投影；HANDOFF.md 按内容去重免重写；关闭任务归档保留并在 `work.pickup` 返回 `archived_counts`。 [PR #982](https://github.com/whshang/herdr-mcp/pull/982), [PR #987](https://github.com/whshang/herdr-mcp/pull/987), [PR #989](https://github.com/whshang/herdr-mcp/pull/989), [PR #1000](https://github.com/whshang/herdr-mcp/pull/1000)
- **`mutation_leases` 账本与租约加固（#332 前置）。** 经 `herdr_call` 暴露 `herdr_mcp.orchestration.lease.{acquire,renew,release,list}`，mutating 执行类工具 opt-in root-lease 冲突检查并携带 fencing token；`doctor`/`status` 只读活动租约展示；token 能力、路径规范化与工具覆盖面加固。 [PR #923](https://github.com/whshang/herdr-mcp/pull/923), [PR #929](https://github.com/whshang/herdr-mcp/pull/929), [PR #933](https://github.com/whshang/herdr-mcp/pull/933)
- **#332 跨设备租约意图与 D-2 持久化幂等。** 租约增加 read/write 意图（同 root read 聚合共存、write 互斥），记录本机设备标识，前台阻塞命令观察仅持久化脱敏摘要；`client_request_id` 复用 `operations` 表与 `(kind,idempotency_key)` 唯一索引，域分离 `key_digest`、绑定 `request_hash`/`boot_id`，Rejected/NotDelivered 原子释放、Unknown 留行 `inspect_before_retry` 不重放。 [PR #972](https://github.com/whshang/herdr-mcp/pull/972), [PR #986](https://github.com/whshang/herdr-mcp/pull/986)

### 首台 bootstrap 恢复（#865）

- **首台 bootstrap 半成品恢复与拒绝出口。** 首台设备凭据持久化后激活失败保留 durable 绑定，同设备经 journal 身份认证后可恢复激活，不再重配对或轮换 fleet secret；`doctor` 新增 bootstrap-journal 只读脱敏投影；`worker bootstrap` 失败出口统一分类可恢复/硬拒绝并输出下一步提示；SecretsProvisioned 异常分支的三语 fail-closed 指引补齐（#942 Windows 实机验证仍开放）。 [PR #962](https://github.com/whshang/herdr-mcp/pull/962), [PR #974](https://github.com/whshang/herdr-mcp/pull/974), [PR #977](https://github.com/whshang/herdr-mcp/pull/977), [PR #979](https://github.com/whshang/herdr-mcp/pull/979)

### 文本传输与凭据目录安全（#938 跟踪 issue）

- **文本传输安全与凭据目录整棵拒绝。** Unix `herdr_mcp.text.read`/`write` 拒绝 `nlink != 1` 的硬链接文件（`text_transfer_hardlink_denied`），写入路径改用 pinned 目录描述符 + no-replace rename + 私有备份；凭据目录整棵子树（`.ssh`/`.aws`/`.gnupg`/`.kube`/`.docker`/`.azure`/`.password-store`/`~/.config/{gcloud,gh}`）在文本传输与托管根文件工具上统一拒绝（`secret_path_denied`），按分量大小写不敏感并作用于规范化真实路径。 [PR #949](https://github.com/whshang/herdr-mcp/pull/949)

### herdr-core 后端 Phase 1/2（#768/#935 跟踪 issue，不构成完整 Core 隔离声明）

- **Phase 1：运行时适配层与显式后端选择。** 新增 `runtime_adapter.rs`（`tui` 默认 | `herdr-core`）：`HerdrCoreClient` 以 OpenRPC 1.3.2 / JSON-RPC 2.0 协议代数 `1` 完成 Unix socket `hello` 握手并动态推导能力；显式 per-device 后端配置，零静默回退；公共工具按所选后端 fail-closed，TUI 专属路由在 `herdr-core` 下以 `runtime_capability_unsupported` 拒绝。 [PR #922](https://github.com/whshang/herdr-mcp/pull/922), [PR #924](https://github.com/whshang/herdr-mcp/pull/924), [PR #928](https://github.com/whshang/herdr-mcp/pull/928), [PR #946](https://github.com/whshang/herdr-mcp/pull/946)
- **Phase 2：窄只读路由、预握手校验与请求内一致性。** `herdr-core` 下第一批最窄公共路由（`herdr_methods`/`herdr_inspect`/只读白名单 `herdr_call`）落地，变更类路由仅凭路由表拒绝；只读路由共享同一 admitted client，`capability_projection` 为声明性非授权；`expected_core_target` 预握手目标指纹校验（对象/字符串 params 入口统一归一化），请求内 hello 协议代数/版本/core.id 一致性检查（`herdr_core_identity_changed`/`unsupported_generation`/`herdr_core_target_changed`，均 `not_delivered` 不回退 TUI）；`GET /mcp` persistent SSE、`/push/events`、`/push/state`、`/extension/control/action` 在 Core 模式下显式 409/拒绝；Core 执行类路由前置 root-lease 校验。 [PR #961](https://github.com/whshang/herdr-mcp/pull/961), [PR #971](https://github.com/whshang/herdr-mcp/pull/971), [PR #973](https://github.com/whshang/herdr-mcp/pull/973), [PR #975](https://github.com/whshang/herdr-mcp/pull/975), [PR #978](https://github.com/whshang/herdr-mcp/pull/978), [PR #943](https://github.com/whshang/herdr-mcp/pull/943), [PR #944](https://github.com/whshang/herdr-mcp/pull/944)

## 已知问题

- **#768 / #935：herdr-core 完整隔离未闭环。** 本版本仅落地 Phase 1/2 的窄只读路由与预握手校验；同 UID 伪造、Windows Core 传输、终端会话生命周期绑定、Core 重启后旧目标失效与同进程重绑仍未解决，`herdr-core` 后端下不构成完整 Core 隔离声明。
- **#938：文本传输残余边界。** macOS Keychain 文件与浏览器配置目录不在凭据目录拒绝清单内；路径 TOCTOU 与 inode 复用竞态、Windows 文件系统竞态实机验证仍未完成（Windows 保护仍为路径级，不提供等价硬链接/祖先交换防护）。
- **#942：Windows 实机恢复验证未执行。** First-Worker activation recovery 的 Windows 物理验证仍开放。
- **#775：跨设备 WebChat 父会话 Phase 2 未交付。** 本版本仅含 runtime 侧账本与 relayed source-turn 验证基础，`edge/cloudflare` 未动。

## 兼容性

- Workstation Runtime Execution Contract：**epoch 6 / 18 tools**（`sha256:9221eb8c46009ed68f447b00fd3581ad7c9bd02d69053bd799f541937047ba6e`）；Edge 兼容白名单 `[epoch 6, epoch 5, epoch 4, epoch 2]`——旧 epoch 客户端仍可协商，但新参数形态（对象 params、`client_request_id` 等）仅 epoch 6 提供。
- First-party Public Edge contract：**epoch 8 / 19 actions**。Edge 与 Runtime 保持独立发布与回滚边界。
- Durable Runtime state：**schema 16**（相对 v1.1.1 无数据库迁移；schema 16 仍不可降级回 schema 15 / v1.0.x）。
- macOS TCC Broker：`BROKER_COMPAT_REVISION` **5**（与 v1.1.1 一致）。
- 浏览器扩展：**0.1.251**（自 v1.1.1 的 `0.1.248` 升级；需扩展重载后生效）。
- Herdr：只支持 Herdr TUI（`herdr` CLI 与 `herdr server`；CI 和 release gate 固定 **0.9.5**）。`herdr-core`（`hc`）本版本仅有 Phase 1/2 窄只读适配，不构成完整后端支持声明。
- Node Server/Link：**正式移除**——不再保留 Node 作为生产路径兼容回退；遗留 `herdr-self-update` 对 Rust 管理服务的写操作被拒绝。
