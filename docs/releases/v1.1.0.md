# Herdr MCP v1.1.0

v1.1.0 是 1.1 Browser Adapter Platform 的正式版本发布说明。MacBook Pro PROD 已完成 rc.8 至 rc.9 的升级、回滚及再次升级验收（[Issue #728](https://github.com/whshang/herdr-mcp/issues/728)）。本版本 Runtime state 为 schema **16**（rc.6 引入的决策闸门迁移，前向不可降级）。已在 v1.1.0-rc.6 – rc.10 的用户可用 `herdr-mcp update` 升级；rc.1 – rc.5 的 updater 拒绝 state schema 变化的发布，需按安装文档手动安装（见下文「升级」）。v1.0.x（epoch 4）用户须先更新到 v1.0.5 bridge，再升级到本版本（见下文「升级」）。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)

## 升级

从 v1.0.x（epoch 4）出发的路径分两步，必须等待本版本正式发布后执行：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

- **v1.0.4 用户必须先更新到 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)**：通过 stable 通道的 `herdr-mcp update` 到达 v1.0.5 bridge。v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16 的本版本；v1.0.5 的 updater 只额外接纳签名清单中声明的精确一步 schema 15 → 16 迁移，迁移前备份 Runtime state，失败时自动回滚。v1.0.0–v1.0.3 的 updater 要求 contract identity 完全相同，同样先更新到 v1.0.5；切换 preview 通道也无法绕过该检查。
- 再从 v1.0.5 通过 `herdr-mcp update` 升级到本版本（前台执行；自动/定时更新拒绝 schema 迁移）。目标签名发布清单中的 `contract_migration.from` 必须精确匹配 bridge 的 epoch 4 identity，`state_schema_from` 必须匹配本机 schema，目标 state schema 必须保持相同。一次只接纳 N → N+1。
- 发布清单的 `contract_migration` 纳入签名证明所覆盖的清单摘要。缺失或非法声明、来源 hash/tool count 不匹配、跨多个 epoch、降 epoch、schema 不同均在安装前拒绝。
- 已处于 v1.1.0-rc.6 – rc.15（schema 16）的用户继续使用同一条命令：preview/stable 通道的 `herdr-mcp update`。最新已发布预发布是 [v1.1.0-rc.15](https://github.com/whshang/herdr-mcp/releases/tag/v1.1.0-rc.15)。
- v1.1.0-rc.1 – rc.5（schema 15）的 updater 只接纳与本机相同 state schema 的发布，`herdr-mcp update` 会以 `release state schema is not rollback-compatible with local schema 15` 拒绝；请按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同，见 [Issue #728](https://github.com/whshang/herdr-mcp/issues/728)）。只有带 [PR #763](https://github.com/whshang/herdr-mcp/pull/763) 的 updater（rc.6 起）才接纳签名清单中声明的单步前向 schema 迁移（15 → 16），且自动/定时更新一律拒绝 schema 迁移，只能前台执行。

**⚠️ state schema 15 → 16 与 bridge 版本：** v1.0.4 的 updater（`parse_release_plan`）要求发布清单的 `state_schema` 等于本机 schema 15，不认识 schema 迁移声明，因此不能从 v1.0.4 直接 `herdr-mcp update` 到 v1.1.0。v1.0.5 bridge 修正了这一点：只接纳 15 → 16 这一步迁移，先备份 Runtime state，迁移或启动失败时回滚到迁移前状态。

**⚠️ 状态库迁移不可降级：** 首次启动 v1.1.0 会把 schema 15 的 Runtime state 迁移到 schema 16，迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

**浏览器扩展升级顺序：** 先升级或重载浏览器扩展到 **0.1.243**（本候选未再改扩展树；rc.15 已是这个版本），再切换 Runtime。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

### 跨 epoch 更新与迁移

- 实现 N → N+1 跨 epoch updater 与签名清单 `contract_migration` 接纳规则；保持相同 state schema、精确来源 identity 和安装前拒绝检查。重新注册保留已存储的 WebChat 显式拒绝授权，回滚到 epoch 4 时不扩大权限。 [PR #605](https://github.com/whshang/herdr-mcp/pull/605)
- 补充跨 epoch discovery/admission、v1.0.4 bridge 两步路径、拒绝条件和平台回滚边界的迁移文档。 [PR #607](https://github.com/whshang/herdr-mcp/pull/607)

### Browser Adapter Platform

- 新增 1.1 通用网页控制内核：BrowserPage open/claim/observe/click/fill/expect/screenshot/release/finalize，由 Runtime 统一负责幂等与投递状态；Herdr 打开的标签页在 finalize 时关闭并验证，用户已有标签页只被 claim 不会被关闭。 [PR #570](https://github.com/whshang/herdr-mcp/pull/570), [PR #573](https://github.com/whshang/herdr-mcp/pull/573), [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 新增经过审查的参考 Adapter：Bilibili 字幕读取、X 搜索/线程读取、豆包图像生成（提交一次 + 状态对账）。 [PR #574](https://github.com/whshang/herdr-mcp/pull/574), [PR #575](https://github.com/whshang/herdr-mcp/pull/575), [PR #576](https://github.com/whshang/herdr-mcp/pull/576)
- 项目 Skill 形式的浏览器 Adapter 模型与实时生命周期验证；可选 Jev fast-path 进度校准。 [PR #577](https://github.com/whshang/herdr-mcp/pull/577), [PR #578](https://github.com/whshang/herdr-mcp/pull/578), [PR #571](https://github.com/whshang/herdr-mcp/pull/571)
- 对齐浏览器页面操作面（扩展 0.1.200：`press`、`extract_table` 等）。 [PR #592](https://github.com/whshang/herdr-mcp/pull/592)
- OpenCLI 风格的表单控件（含超过 24 个选项的下拉框与容器内滚动）和可见元素等待。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 重新测量 Jev/semantic fast-path，并合入两处 fail-closed 修复。 [PR #591](https://github.com/whshang/herdr-mcp/pull/591)

### WebChat 控制

- `browser_session.create` 拒绝时返回白名单内的真实扩展原因、受限诊断字段与操作提示；未知字符串和页面内容仍不透传。 [PR #794](https://github.com/whshang/herdr-mcp/pull/794)
- `doctor` 将本地无授权证据明确显示为 `absent_locally`，不再误报 Edge grant 缺失；旧版 WebChat Control 开关状态标记为 `legacy_ignored`。 [PR #793](https://github.com/whshang/herdr-mcp/pull/793)
- WebChat 控制授权改为按 endpoint + provider 计算，支持 `*` 通配；声明 `webchat_control.any_provider` 的 Runtime 可由 Page Assist 授权推导出全部 provider 的控制授权，Edge 对所有页面类方法转发 Page Assist 调用方授权。 [PR #589](https://github.com/whshang/herdr-mcp/pull/589), [PR #595](https://github.com/whshang/herdr-mcp/pull/595)
- ChatGPT 所有路径只提交一次（移除 Enter 兜底），JS/Rust 投递摘要一致，归档不再回退到旧会话绑定，App 候选限定在输入框且精确匹配；Grok/Claude 的 `browser_dispatch.stop` 可定位到目标会话。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- ChatGPT App 激活、显示名称投影到会话标题、严格的来源 URL 查找。 [PR #583](https://github.com/whshang/herdr-mcp/pull/583), [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- Edge relay 重放缓存按 Connector 与完整请求限定，记录不完整时 fail closed。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 固定 fail-closed 的 stop 授权：无授权、跨设备与 runtime 场景均拒绝。 [PR #611](https://github.com/whshang/herdr-mcp/pull/611)
- create 作用域握手超时与 `registry_handshake_delay`（扩展 0.1.202）。 [PR #620](https://github.com/whshang/herdr-mcp/pull/620)

### Agent 编排与上下文控制

- Web Planner 负责计划、工作树/分支/窗格所有权、集成与验收；非平凡编码交给本地执行 Agent，审议使用独立只读上下文。Agent Task Inbox 提供机械化的升级信号，这些信号仅供建议，永不自动重派。 [PR #667](https://github.com/whshang/herdr-mcp/pull/667), [PR #670](https://github.com/whshang/herdr-mcp/pull/670), [PR #671](https://github.com/whshang/herdr-mcp/pull/671)
- Agent Task 查询支持按作用域和幂等键恢复持久任务身份；Inbox 增加最多 60 秒的有界等待、compact 视图和最多 32 个 ID 的批量 ACK。 [PR #665](https://github.com/whshang/herdr-mcp/pull/665), [PR #673](https://github.com/whshang/herdr-mcp/pull/673)
- 终态任务可附带最多 2,000 字节的输出摘要（`final_excerpt`）。当同批事件已表明 Pane 被复用，或终态事件缺少任务专属的 `state_change_seq`（当前 Herdr 上游不提供该生产者序列）时，摘要被安全省略；读取前后仍核对 Pane、终态状态与序号，避免把后续任务的输出归到旧任务。 [PR #674](https://github.com/whshang/herdr-mcp/pull/674), [PR #678](https://github.com/whshang/herdr-mcp/pull/678), [PR #688](https://github.com/whshang/herdr-mcp/pull/688), [Issue #675](https://github.com/whshang/herdr-mcp/issues/675)
- Progressive Skill 可用 `expected_digests` 与 `omit_unchanged` 重新验证未变化的 Skill 而不重复返回正文；源文件读取与 digest 校验仍会执行。 [PR #672](https://github.com/whshang/herdr-mcp/pull/672)

- 同一 ChatGPT 会话只保留一个当前 locator，退役 locator 时迁移来源轮次证据，扩展只按精确 project id 推断 Project，消除 `browser_canonical_url_ambiguous` / `source_turn_ambiguous`。 [PR #740](https://github.com/whshang/herdr-mcp/pull/740), [PR #743](https://github.com/whshang/herdr-mcp/pull/743), [PR #744](https://github.com/whshang/herdr-mcp/pull/744)

### 发布与更新

- `update apply` 默认只更新 Runtime，不再自动串联 Cloudflare Worker 更新或交互授权；Worker 版本落后时返回非致命提示，显式 `--with-worker` 必须使用交互式 TTY。 [PR #797](https://github.com/whshang/herdr-mcp/pull/797)
- 发布清单声明单步前向 state schema 迁移（15 → 16）；updater 只接纳本机 schema 或本机 schema + 1，在检查/应用输出中提示不可降级，拒绝自动/定时更新执行 schema 迁移，并在激活前备份、失败时恢复。 [PR #763](https://github.com/whshang/herdr-mcp/pull/763)
- macOS 受保护目录（`~/Documents` / `~/Desktop` / `~/Downloads`）判定改为纯词法比较，新 Runtime generation 首次访问时的 TCC 授权弹窗不再挂起整条控制链路（符号链接回退解析在有界探测中执行、超时 fail closed）；`update apply` / `update queued` 输出非致命 `macos_documents_tcc_prompt` 提示。`update status` 的 `ok` 只反映 Runtime 结果：由 rc.8 或更早 updater 串联 Worker 失败留下的记录改报成功并附 `worker_update_failed_legacy` 提示（`next_action: herdr-mcp worker update`）。 [PR #802](https://github.com/whshang/herdr-mcp/pull/802), [Issue #800](https://github.com/whshang/herdr-mcp/issues/800)

## 已知限制

- `session.create` 响应中的 `title_projection` 仅反映创建时的投影结果（未上报时为 `unobserved`）；首个助手轮次后的标题重放见 rc.4（[Issue #624](https://github.com/whshang/herdr-mcp/issues/624) 已关闭）。新增诊断响应字段 `classification_reason`：当 runtime 将 `session.create` 的首次证据判定为 uncertain 时，会在响应中报告原因。
- Claude / Grok 的 WebChat 目前只支持 submit / stop / settle；create / open / archive 尚不支持（以 `unsupported` 拒绝），按 1.1.x / 1.2 跟踪，不属于 1.1 GA 范围。

- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS：重新校验并激活上一份已安装 generation。Linux 不写入成功后的 service rollback 记录，不承诺此回滚路径。
- Browser Extension 独立发布；本 Runtime 不发布 Store/Standalone 扩展，1.1 浏览器功能需要兼容的 DEV 扩展或后续扩展发布。
- `press` 发送合成键盘事件（`isTrusted=false`），浏览器默认行为（例如 Enter 提交表单）不保证触发，请改用显式 click。可信按键需要 CDP（`chrome.debugger`）路径，1.1 不采用，1.2 再评估；限制说明已在 [PR #725](https://github.com/whshang/herdr-mcp/pull/725) / [PR #727](https://github.com/whshang/herdr-mcp/pull/727) 中披露。 [Issue #617](https://github.com/whshang/herdr-mcp/issues/617)
- Herdr 的 Pane 终态事件不含任务专属 `state_change_seq`；为避免 Pane 被复用时把后一个任务的输出归给前一个任务，无法确认归属的 `final_excerpt` 被安全省略，任务终态、Inbox、通知与 ACK 不受影响。上游生产者身份与真实连续任务验收仍待完成。 [Issue #675](https://github.com/whshang/herdr-mcp/issues/675)
- ChatGPT 归档后，由会话流程打开的对话标签页在个别情况下可能残留，需要手动关闭；Windows x86_64 / ARM64 仍属于 Candidate 支持。
- 本说明里的 MacBook Pro 升级/回滚证据仍是 rc.8↔rc.9（#728）和清单中的 rc.13↔rc.15 演练。包含 #863 与 #866 的这个候选还没有安装到 PROD，也没有做过实机 MV3 中途重载。这些缺口关闭之前，本文不是 stable GO。

## 已知问题（1.1.x 跟踪）

<!-- 独立于“已知限制”维护：本段只跟踪 1.1.x 后续问题，便于不同改动并发编辑时无冲突合并。 -->

- Vercel AI Gateway 的 `decision-vercel` route 在 Vercel 免费套餐下对所有 evaluation 模型返回 403（`RestrictedModelsError`），因此 `jev-vercel` 已从默认 route pool 移除；该 protocol 仍可在已购买付费额度时显式配置，见 [semantic routing](https://github.com/whshang/herdr-mcp/blob/main/docs/semantic-routing.md)。 [Issue #621](https://github.com/whshang/herdr-mcp/issues/621)
- Edge/Link create 超过 60 秒会以请求超时结束；请使用相同的 idempotency key 重试。（无对应 issue）
- 设备重新注册后旧 device id 的过期 browser endpoint 仍可能导致 `browser_canonical_url_ambiguous`。 [Issue #734](https://github.com/whshang/herdr-mcp/issues/734)
- Edge PROD 已随 [PR #713](https://github.com/whshang/herdr-mcp/pull/713) 部署设备级 WebChat grants API（`scope: "device"`、`*/*/*`）和仅所有者可写的 `platform_account` Connector 标签；DEV 已验证授权、拒绝及清理（[Issue #730](https://github.com/whshang/herdr-mcp/issues/730)）。Edge 会存储并审计这些 grant，但当前 Rust Runtime 尚未在 WebChat 派发中采纳设备级 `*/*/*` grant（会丢弃该行，消费支持为后续工作），1.1 的已验证 WebChat 派发仍按 endpoint + provider 授权（[PR #589](https://github.com/whshang/herdr-mcp/pull/589)）；不将 Edge API 测试等同于跨设备任务授权成功。

- 跨设备来源轮次绑定尚未实现；派发到非浏览器所在设备会明确报告 `caller_browser_on_other_device`，需要改派至承载该会话的设备。 [Issue #775](https://github.com/whshang/herdr-mcp/issues/775)
- 全新 ChatGPT 对话的第一条消息仍无法绑定（`/c/<id>` 会话在发送后才注册）；rc.7 起会明确报告 `source_session_not_registered`（[Issue #771](https://github.com/whshang/herdr-mcp/issues/771) 已关闭）。延迟绑定（hold-and-replay / 临时会话）跟踪见 [Issue #786](https://github.com/whshang/herdr-mcp/issues/786)。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**；v1.0.5 bridge 保持 epoch **4**。从 1.0.x 到本版本必须先经过 v1.0.5 bridge 与签名 `contract_migration`，不支持直接更新。
- First-party Public Edge contract：epoch **8 / 19 actions**。Edge 与 Runtime 是独立发布和回滚范围。
- Durable Runtime state：schema **16**（rc.6 起，编号迁移，前向不可降级；rc.1 – rc.5 与 v1.0.x 为 15）。macOS 成功后的 service 回滚不恢复数据库，不撤销更新后写入的持久状态；回到 schema 15 的二进制必须先恢复迁移前的 state 备份。
- `browser_dispatches.message_canonical_digest` 是可空的新增列，epoch-4 binary 忽略该列；重新注册保留显式拒绝授权。
- 浏览器扩展：0.1.243（与已发布 rc.15 相同；本候选未改扩展树）。Runtime 自更新不更新 Browser Extension；本版本不扩大已有平台支持声明。
- Herdr：只支持 Herdr TUI（`herdr` CLI 与 `herdr server`；CI 和 release gate 固定 `0.9.5`）。新的 Herdr app 与 herdr-core（`hc`）是独立运行时，与 TUI 不共享 Agent，本版本不支持。详见[平台支持矩阵](../i18n/zh-CN/platform-support-matrix.md)。
