# Herdr MCP v1.0.0-alpha.8

This is a 1.0 prerelease, not the 1.0 GA declaration. It publishes the current runtime candidate and its qualified platform artifacts so macOS/Linux production paths and Windows candidates can be exercised before the remaining signed-in multi-provider acceptance closes.

## Upgrade from v0.4.8

v0.4.8 uses durable state schema 5; v1.0.0-alpha.8 uses schema 15. Ordinary `herdr-mcp update check` may inspect the prerelease, but the v0.4.8 `herdr-mcp update apply` path must not cross this incompatible schema boundary.

After verifying the downloaded v1.0.0-alpha.8 binary against `release-manifest.json` and its attestation, run the major upgrade from an independent terminal:

```bash
/path/to/verified/herdr-mcp update major-apply
```

The major-upgrade path stops the source service, snapshots the final schema-5 database, preserves an executable copy of the exact source runtime with integrity hashes, and reuses the transactional service installer to migrate and activate schema 15 while preserving configuration and enrolled-device identity. Do not run service-changing commands from a managed `herdr_exec` session.

Post-upgrade verification:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
herdr-mcp doctor
```

Also verify from the same remote Connector that `herdr_inspect` reaches the intended device and reports the expected runtime generation/version. Process exit or local health alone is not sufficient.

N-1 recovery uses `herdr-mcp update major-rollback` from an independent terminal. It verifies the recorded artifacts, stops the active service, restores the exact pre-upgrade schema-5 snapshot, and reinstalls the recorded v0.4.8 binary. Durable state created after the upgrade is intentionally discarded by this rollback.

## Platform qualification

- **macOS Apple Silicon — Production:** physical-machine runtime/TCC/Link/Connector/browser UAT is the primary maintained path.
- **Linux x86_64 — Production:** physical Debian installation/lifecycle/updater evidence plus static `x86_64-unknown-linux-musl` release qualification.
- **Linux ARM64 / aarch64 — Production:** physical NanoPi R5C / Debian 11 exact-source release build, immutable-generation install, preserved enrolled-device identity, `systemd --user` runtime/Link reconciliation and remote Edge `herdr_inspect` passed; native GitHub ARM64 release qualification builds and smokes static `aarch64-unknown-linux-musl`.
- **Windows x86_64 — Candidate:** hosted Windows CI/release build passes; physical Windows UAT is still open.
- **Windows ARM64 / aarch64 — Candidate:** native GitHub `windows-11-arm` build/qualification covers `aarch64-pc-windows-msvc`; no physical Windows ARM64 machine has been qualified yet.
- **WSL — Unsupported.**

The public README and platform support matrix carry the same tested/not-yet-tested boundary.

## Known issues

- 1.0 GA still requires the remaining real signed-in cross-provider acceptance in [#399](https://github.com/whshang/herdr-mcp/issues/399), including the provider/account isolation and handoff/delegation cases that cannot be replaced by mock coverage.
- Windows remains Candidate pending physical qualification in [#394](https://github.com/whshang/herdr-mcp/issues/394). Publishing x86_64/ARM64 Windows binaries is not a Production support claim.
- Runtime, Edge deployment and browser-extension STORE/STANDALONE distribution are independent release planes. This Runtime Release does not itself update a user's browser extension or deploy Edge.
- A green source/hosted CI run does not substitute for published-artifact verification or the physical UAT explicitly called out above.

## Compatibility

- Workstation Runtime Execution Contract: epoch **3**, **18** tools. Public Edge contract: epoch **3**, **19** actions.
- Durable runtime state: schema **15**; v0.4.8 schema 5 requires the explicit major-upgrade path. Same-schema prerelease updates use the normal verified updater path.
- Published Runtime targets: `aarch64-apple-darwin`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-pc-windows-msvc`, and `aarch64-pc-windows-msvc`.
- MCP/OAuth origin and enrolled-device identity are retained across a successful install/update. Browser control, Tool Bridge, workstation mutation and Planner authority remain distinct permissions.
- macOS Apple Silicon and native Debian-class Linux x86_64/ARM64 are Production. Windows x86_64/ARM64 are Candidate. WSL is Unsupported; see the platform support matrix.
