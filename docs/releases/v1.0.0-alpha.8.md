# Herdr MCP v1.0.0-alpha.8

Qualification draft for the current development version. This document does not authorize publication or claim that 1.0 GA acceptance has passed. The exact qualification commit and remaining gates are recorded in `docs/_wip/v1.0-status.md`.

## Upgrade from v0.4.8

v0.4.8 uses durable state schema 5; this development candidate uses schema 14. Ordinary `herdr-mcp update check` may inspect releases, but the existing v0.4.8 `herdr-mcp update apply` path must not be used to cross this incompatible schema boundary.

A representative macOS installed lifecycle has passed for this candidate (see Known issues). After the downloaded binary is verified against the release manifest and its recorded hashes, run it from an independent terminal:

```bash
/path/to/verified/herdr-mcp update major-apply
```

The major-upgrade path first stops the running source service so the final snapshot includes writes committed during shutdown, then snapshots the schema-5 database and preserves an executable copy of the exact source runtime with integrity hashes, and reuses the normal transactional service install to migrate and activate. It preserves the existing configuration and device identity. Do not run service-changing commands inside managed `herdr_exec` sessions. Maintainer source testing uses `herdr-mcp dev sync` separately; MacBook Air remains DEV and MacBook Pro remains v0.4.8 PROD until release acceptance.

After an authorized upgrade, verify:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
herdr-mcp doctor
```

Also verify the same ChatGPT Connector can inspect the intended device and reports the expected runtime source/generation. An exit code or local health check alone is insufficient.

N-1 recovery uses `herdr-mcp update major-rollback` from an independent terminal. It stops the active service, restores the exact pre-upgrade schema-5 snapshot, and reinstalls the recorded v0.4.8 binary. A migration interrupted at any schema between 5 and 14 can be rolled back from the same record. Durable state created after the upgrade is discarded by this rollback. Keep the private rollback backup and binary intact.

## Known issues

- The schema-5 → schema-14 `major-apply`/`major-rollback` lifecycle has passed a real installed macOS named-instance UAT: the published v0.4.8 asset (`sha256 c4674b730b8fd0fde25ffb2b30947673ffecfb012c90d6ab8372376b83de9777`) upgraded to the verified schema-14 candidate (source `ca75fe46`, candidate `sha256 fb1b697d4a03d1da6dc5fc9cfcaeb019a0e23e5e8d9f29dc6ac69ca39f5a18fd`), then rolled back to the exact schema-5 state and source binary, with the managed LaunchAgent healthy through all three phases, the pre-upgrade continuity chain preserved, and the named service removed afterward. This is one representative macOS run, not general fleet migration proof; release-owner target-client acceptance and non-macOS lifecycle coverage remain open. The older schema-13 wording in [#398](https://github.com/whshang/herdr-mcp/issues/398) is stale.
- Signed-in Gemini/Claude/Grok, Page Assist, two concurrent ChatGPT workers, cross-provider handoff/delegation, and the separate two-device lane scenario remain open in [#399](https://github.com/whshang/herdr-mcp/issues/399). A real signed-in ChatGPT → ChatGPT planner/worker handoff already has previous evidence and is not one of those open items; mock tests do not satisfy the remaining gates.
- PR [#416](https://github.com/whshang/herdr-mcp/pull/416) is merged as `8ac61426` and **is** part of this baseline. Open finding: in `extension/content/wake.js`, `drainPendingSelfArchives()` removes a persisted self-archive intent only when actuation returns `applied`. When the archive click is delivered but provider verification returns `uncertain`, the intent stays pending and is clicked again on a later drain, while the runtime has already reported `uncertain` to the planner. That is a mutation replay of the kind beta.1 excludes; it needs a fail-closed rule for the uncertain outcome. Tracked for a separate active chat, not fixed by this candidate.
- Windows remains Candidate pending physical qualification in [#394](https://github.com/whshang/herdr-mcp/issues/394). WSL remains Unsupported.
- A green source CI run does not qualify a published artifact, signed-in browser behavior, or the release owner's target-client acceptance.

## Compatibility

- Runtime Execution Contract: epoch 2, 18 tools. Public Edge contract: epoch 3, 19 actions.
- Durable runtime state: schema 14; v0.4.8 schema 5 requires the explicit major-upgrade path. Normal automatic updates continue to reject incompatible schemas.
- The MCP/OAuth origin and enrolled-device identity are retained. Browser control, Tool Bridge, workstation mutation, and Planner authority remain distinct permissions.
- Runtime, Edge deployment, and browser extension distribution are independent release planes. A runtime update does not update the extension or deploy Edge.
- macOS and native Linux retain their documented support boundaries. Windows is Candidate and WSL is Unsupported; see the platform support matrix.
