# Herdr MCP v1.0.4

v1.0.4 是 1.0 稳定线的 **epoch 迁移桥（migration bridge）**：Runtime Execution Contract、state schema、Edge contract 与 Browser Extension 版本全部保持不变，唯一的功能变更是 updater 获得"跨恰好一个 contract epoch"的准入能力。这样 1.0.x 用户先正常更新到本版本，之后 v1.0.4 就能以普通 `herdr-mcp update` 进入第一个在发布清单中声明 `contract_migration`（from epoch 4）的 v1.1 发布（Runtime Execution Contract epoch 5，见 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)）。

## 升级

所有受支持的旧版本继续只使用标准命令：

```bash
herdr-mcp update
```

- 已安装 v1.0.0 / v1.0.1 / v1.0.2 / v1.0.3 的用户走普通同契约 verified update 到 v1.0.4；本版本与 v1.0.3 的 contract identity、state schema 完全一致。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- v0.4.3 / v0.4.8 等 schema 5 安装仍由 updater 先进入 v0.4.9 migration bridge，再自动选择当前 stable v1.0.4 Runtime；v0.4.9 桥接的目标契约常量（epoch 4 / 18 tools / schema 15）与本版本一致。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 升级到 v1.0.4 后，后续 `herdr-mcp update` 即可进入第一个在 `runtime-manifest.json` 中声明 `contract_migration.from = epoch 4` 且 `state_schema_from = 15` 的 v1.1 发布（计划 v1.1.0-rc.2，见 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)）；未声明该字段的 v1.1 预发布无法被 v1.0.4 选中。跨 epoch 更新仍要求目标 `state_schema` 与本机一致（15），本协议不允许伴随 schema 迁移。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

成功后应看到 v1.0.4、contract epoch 4 / 18 tools、schema 15、健康的 service / local MCP，且 Link 在线。

## 主要变更

- updater 准入规则：发布清单 `contract` 与本机 identity 完全一致时按普通同契约更新；不一致时仅当目标 epoch 恰好等于本机 epoch + 1、清单声明结构合法的 `contract_migration`（`from` 的 epoch/hash/tool_count 与本机 identity 完全相等、`state_schema_from` 等于本机 schema、`contract_migration` 内不允许未知字段）、且清单 `state_schema` 仍与本机一致时才接纳。epoch 跨度大于 1、目标 epoch 更低、声明缺失或畸形、`from` 不匹配均在安装任何内容之前拒绝，错误信息会给出本机与目标 epoch，并提示用 `herdr-mcp update apply --manifest <url>` 先安装中间桥；`update auto` 适用同一规则并保持 PROD + Stable 限定。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- candidate probe 改为按清单声明的目标契约比对：下载后的候选二进制必须报告被接纳的清单契约（同契约路径即本机 identity，跨 epoch 路径即 N+1 目标），修复了历史前台 probe 遗留的 0.4.x 时代 "contract epoch 2" 硬编码；update worker（运行于候选二进制内）同样按自身 identity 自校验。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 版本号提升至 1.0.4（Runtime、Edge `MCP_SERVER_VERSION`、npm 包）。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)

## 已知限制

- 已发布的 v1.0.0–v1.0.3 前台 updater 存在历史 probe 硬编码缺陷：其候选 probe 检查 0.4.x 时代的 `contract epoch 2 / 18 tools` 字符串，会在下载完成后以 "staged update binary identity does not match release manifest" 拒绝任何 1.0.x 候选（包括 v1.0.4）。受影响的机器可从 GitHub Release 手动下载本版本二进制，在独立终端执行 `<下载的二进制> install`（`service install` 以正在执行的二进制为 payload，走完整 generation 生命周期、健康门控与回滚保护）；v1.0.4 自身已修复该 probe，此后同契约与跨一个 epoch 的更新不再受影响。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 跨 epoch 更新一次只允许恰好一个 epoch（N → N+1）；如果未来某个发布跨了两个 epoch，updater 会 fail closed 并提示先用 `herdr-mcp update apply --manifest <url>` 安装中间桥，不会静默选择更旧的发布。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- `herdr-mcp rollback` 从 v1.1 回到 v1.0.4 属执行环境回滚：两侧同为 schema 15，无需恢复数据库，但更新之后写入的持久状态不会回退。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)

## 兼容性

- Workstation Runtime Execution Contract：epoch **4 / 18 tools**（hash 不变，`sha256:1f4d272c…`）。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- Durable Runtime state：schema **15**。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- First-party DEV/PROD Public Edge contract：epoch **7 / 19 actions**。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 发布目标继续为 macOS Apple Silicon、Linux x86_64/ARM64 musl、Windows x86_64/ARM64；Windows 仍属于 Candidate 支持。Browser Extension 继续独立版本化，本次 Runtime patch 不升级扩展。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- Worker public origin、设备身份、OAuth/Connector identity、v0.4.9 migration bridge 选择语义、`update major-apply` / `major-rollback` 均保持不变。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
