# Herdr MCP v1.0.4

v1.0.4 是 1.0 稳定线的 **epoch 迁移桥（migration bridge）**：Runtime Execution Contract、state schema、Edge contract 与 Browser Extension 版本全部保持不变，唯一的功能变更是 updater 获得"跨恰好一个 contract epoch"的准入能力。已安装 v1.0.4 后，即可进入第一个在发布清单中声明 `contract_migration`（from epoch 4）的 v1.1 发布（Runtime Execution Contract epoch 5，见 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)）。

注意：已发布的 v1.0.0–v1.0.3 前台 updater **无法**以普通 `herdr-mcp update` 到达 v1.0.4（原因见"已知限制"）；这些版本以本节第一项的认证手动安装为准。

## 升级

### v1.0.0 / v1.0.1 / v1.0.2 / v1.0.3：认证手动安装（主引导路线）

普通 `herdr-mcp update` 对这些已发布版本不可用（其候选 probe 硬编码了 0.4.x 时代的 `contract epoch 2 / 18 tools` 字符串，会在下载完成后拒绝任何 1.0.x 候选，包括 v1.0.4）。请使用经过完整真实性校验的手动安装：

1. 从 v1.0.4 GitHub Release 下载本平台二进制 `herdr-mcp-1.0.4-<target>`。
2. 校验 sha256：与同一 Release 内 `runtime-manifest.json` 为该资产声明的 `sha256` 完全一致。
3. 校验构建溯源：`gh attestation verify <下载的文件> -R whshang/herdr-mcp`。
4. 在独立终端（不在任何受管 `herdr_exec` 会话内）执行 `<下载二进制的绝对路径> install`。该命令走完整 service install 生命周期：二进制进入新的不可变 generation、健康门控通过后才切换 `runtime/current`，并保留失败回滚保护。

### v0.4.3 / v0.4.8 等 schema 5 安装（保持不变）

```bash
herdr-mcp update
```

仍由 updater 先进入 v0.4.9 migration bridge，再自动选择当前 stable v1.0.4 Runtime；v0.4.9 桥接的目标契约常量（epoch 4 / 18 tools / schema 15）与本版本一致。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)

### v1.0.4 → 后续发布

- 同契约 patch/minor（例如未来的 v1.0.5）继续普通 `herdr-mcp update`。
- 第一个声明 `contract_migration.from = epoch 4` 且 `state_schema_from = 15` 的 v1.1 发布（计划 v1.1.0-rc.2）**尚未发布**；发布后 RC 经由 Preview channel（`update_channel: preview`）或显式 `herdr-mcp update apply --manifest <runtime-manifest.json url>` 进入。跨 epoch 更新仍要求目标 `state_schema` 与本机一致（15），本协议不允许伴随 schema 迁移。
- 发现与准入是两个阶段：发现（含 Preview）只按 semver 选择最高的 channel 内 eligible 发布、不读取迁移元数据；被选中的发布若契约不可准入（例如未声明 `contract_migration`，或声明与本机 identity 不符），会在**准入阶段**失败且不会回退选择更旧的发布，需要按报错指引处理（例如用 `--manifest` 指定可准入的中间发布）。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

成功后应看到 v1.0.4、contract epoch 4 / 18 tools、schema 15、`contract hash sha256:1f4d272c…`（本版本起 `herdr-mcp version` 新增第四行）、健康的 service / local MCP，且 Link 在线。

## 主要变更

- updater 准入规则：发布清单 `contract` 与本机 identity 完全一致时按普通同契约更新；不一致时仅当目标 epoch 恰好等于本机 epoch + 1、清单声明结构合法的 `contract_migration`（`from` 的 epoch/hash/tool_count 与本机 identity 完全相等、`state_schema_from` 等于本机 schema、`contract_migration` 内不允许未知字段）、且清单 `state_schema` 仍与本机一致时才接纳。epoch 跨度大于 1、目标 epoch 更低、声明缺失或畸形、`from` 不匹配均在安装任何内容之前拒绝；**每一条**跨 epoch 拒绝消息都会报出本机与目标两侧 epoch，并提示用 `herdr-mcp update apply --manifest <url>` 先安装中间桥；`update auto` 适用同一规则并保持 PROD + Stable 限定。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- candidate probe 绑定完整契约身份：`herdr-mcp version` 自本版本起新增第四行 `contract hash <sha256:...>`，下载后的候选二进制必须报告被接纳清单契约的 epoch、tool_count 与 hash 三者——跨 epoch 路径要求第四行存在且与清单一致；同契约路径接受尚无该行的旧格式候选（epoch/tool_count 仍须一致），但任何被报告的不同 hash 一律拒绝，修复了历史前台 probe 遗留的 0.4.x 时代 "contract epoch 2" 硬编码。前台探测通过后将接纳契约持久化到 update job 目录；update worker（运行于候选二进制内）以该持久化记录而非候选自报身份完成同一校验，并额外绑定自身内嵌 identity 与接纳契约一致。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 版本号提升至 1.0.4（Runtime、Edge `MCP_SERVER_VERSION`、npm 包）。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)

## 已知限制

- 已发布的 v1.0.0–v1.0.3 前台 updater 存在历史 probe 硬编码缺陷：其候选 probe 检查 0.4.x 时代的 `contract epoch 2 / 18 tools` 字符串，会在下载完成后以 "staged update binary identity does not match release manifest" 拒绝任何 1.0.x 候选（包括 v1.0.4）。受影响的机器以"升级"一节的认证手动安装路线进入 v1.0.4（下载 Release 资产、校验 runtime-manifest.json 的 sha256 与 `gh attestation verify`、独立终端执行 `<二进制> install`）；直接执行未经校验的下载二进制不受信任。v1.0.4 自身已修复该 probe，此后同契约与跨一个 epoch 的更新不再受影响。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 跨 epoch 更新一次只允许恰好一个 epoch（N → N+1）；如果未来某个发布跨了两个 epoch，updater 会 fail closed 并提示先用 `herdr-mcp update apply --manifest <url>` 安装中间桥，不会静默选择更旧的发布。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- `herdr-mcp rollback` 从 v1.1 回到 v1.0.4 属执行环境回滚：两侧同为 schema 15，无需恢复数据库，但更新之后写入的持久状态不会回退。该回滚保证目前**仅在 macOS 上成立**：macOS 安装器在成功切换后持久化 ready rollback record；Linux 安装器仅在同步失败恢复时捕获前一指针、没有成功安装后的 rollback record，`herdr-mcp rollback` 在 Linux 上拒绝公共 service 回滚。Linux 的跨 epoch 发布资格必须先补齐成功安装后的回滚记录，才能宣称同等保证。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)

## 兼容性

- Workstation Runtime Execution Contract：epoch **4 / 18 tools**（hash 不变，`sha256:1f4d272c…`）。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- Durable Runtime state：schema **15**。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- First-party DEV/PROD Public Edge contract：epoch **7 / 19 actions**。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- 发布目标继续为 macOS Apple Silicon、Linux x86_64/ARM64 musl、Windows x86_64/ARM64；Windows 仍属于 Candidate 支持。Browser Extension 继续独立版本化，本次 Runtime patch 不升级扩展。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
- Worker public origin、设备身份、OAuth/Connector identity、v0.4.9 migration bridge 选择语义、`update major-apply` / `major-rollback` 均保持不变。 [PR #601](https://github.com/whshang/herdr-mcp/pull/601)
