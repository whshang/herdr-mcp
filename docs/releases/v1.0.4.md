# Herdr MCP v1.0.4

v1.0.4 是 1.0 稳定线的旧安装兼容性补丁，重点收口自定义域名机器从早期 workers.dev OAuth 身份迁移到 1.x 时的连续性，以及历史 Rust production Link 使用旧 runtime-control/status 路径导致恢复与 generation reconcile 超时的问题。Runtime state schema、Workstation Runtime Execution Contract 和 First-party Public Edge contract 均不变。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)

## 升级

所有受支持用户继续只使用标准命令：

```bash
herdr-mcp update
```

- v0.4.8 等 schema 5 安装仍通过已发布的 v0.4.9 migration bridge 进入当前 stable 1.x，不需要逐版本升级。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 已安装 v1.0.0–v1.0.3 的用户走同 schema verified update。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 若已有 Cloudflare Custom Domain，升级后该自定义域名成为 canonical MCP/OAuth origin；workers.dev 不再作为首选公开身份。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 若旧 Worker 的 OAuth issuer 仍是同一 Cloudflare account、同一 script 的 canonical workers.dev 地址，updater 会先通过 Cloudflare account subdomain + script identity 严格证明归属，再原位更新；不能证明归属时继续 fail-closed。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp link status
herdr-mcp doctor
```

## 主要变更

- 新 OAuth discovery、authorization/token endpoint、protected-resource metadata 和新签发 token 都以已配置的 Custom Domain 为 canonical identity。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- Cloudflare 证明过的旧 workers.dev issuer 只作为受限迁移 alias 保存，不会重新成为 primary origin。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 迁移前已经签发的 workers.dev access JWT 可在过渡期继续验证；旧 refresh token 第一次成功刷新时会原子迁移到 Custom Domain resource，之后的新 token 只使用 Custom Domain identity。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- refresh token 的 resource 不匹配不再先消费 token 后返回 `invalid_grant`；只有 canonical resource 或经过证明的 legacy resource 才允许 one-time rotation。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 历史 Rust `dev.herdr-mcp.link-prod` 若缺少 `HERDR_RUNTIME_CONTROL_PATH` / `HERDR_RUNTIME_STATUS_PATH`，generation refresh 现在会自动补齐 canonical `runtime-control-prod.json` / `runtime-status-prod.json` 路径。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 通过 Edge 调用 Herdr 的 `pane.wait_for_output` 现在按只读请求处理，并把单次远程等待限制在 20 秒以内，避免内部长等待超过外层 30 秒请求预算后被误报为“mutation outcome unknown”；需要更长等待时继续使用有界重复读取。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)
- 既有 Worker public origin、Cloudflare Durable Objects、secret bindings、device identity、`DEFAULT_WORKSTATION_ID` 和 rollback material 继续原位保留。 [PR #569](https://github.com/whshang/herdr-mcp/pull/569)

## 已知限制

- Cloudflare Worker 原位更新仍需要 Cloudflare 授权；这是控制面 mutation 的显式安全边界，不会因本补丁自动绕过。
- ChatGPT 的 App 选择按消息生效。用户手动发送的后续消息如果需要新的 Herdr 数据或动作，需要再次选择/mention Herdr App；扩展只会对 Auto、Agent 结果、恢复、handoff、Browser Actuation 等 Herdr 生成的消息通过 `required_apps` 重新选择已观察到的真实 App identity。
- 未配置 Custom Domain 的 workers.dev-only 用户继续使用原有 workers.dev canonical identity，不受本次迁移逻辑影响。
