# Herdr MCP v0.4.4

v0.4.4 is a stability, workflow, and usability release. It keeps the existing public and workstation tool surfaces unchanged while tightening multi-device routing, Agent identity, runtime truth, DEV/PROD transitions, capability evidence, and context efficiency.

## Upgrade

From v0.4.3:

```bash
herdr-mcp update
```

From v0.4.2, the one-time transition remains:

```bash
herdr-mcp update apply
```

A normal upgrade preserves the existing configuration, device credential, Worker pairing, service identity, production Link, and owned Native Messaging integration.

Verify after upgrading:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

For source-development machines, keep DEV and PROD explicit with `herdr-mcp dev status`; `dev sync` remains the source-dogfood path and `dev rollback` returns to the pinned verified PROD runtime.

## Main changes

### Multi-device routing and Agent identity

- Fixed legacy/default device routing when multiple enrolled devices are online. Explicit device selectors and device-aware refs still take priority; an unavailable default device fails closed and never silently fails over. [PR #273](https://github.com/whshang/herdr-mcp/pull/273)
- Canonical Agent identity is now projected consistently across `herdr_inspect`, `herdr_since`, and planning evidence. Addressable Agent names are kept separate from Agent kinds, and missing unique names fall back to an addressable pane identity rather than a generic kind such as `pi`. Device provenance is preserved for routed structured results and text-visible JSON without changing the epoch-2 public tool contract. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- Cross-device routing failures carry stronger selected/candidate device evidence so a caller can retry explicitly instead of guessing a workstation. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)

### Runtime, DEV/PROD, and update stability

- macOS product uninstall now waits for strongly owned launchd jobs to converge after `bootout` before deleting owned files, closing the transient false-failure seen in v0.4.3. [PR #272](https://github.com/whshang/herdr-mcp/pull/272)
- Active runtime truth is separated from historical self-update operation metadata. The live runtime reports its active channel, version, source commit, and generation from the active binary/generation manager instead of presenting an old updater target as current state. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- `dev sync` now recovers a stale DEV channel record when the machine has already been externally returned to a verified PROD runtime, and refuses to treat a `*-dev` runtime as the PROD rollback source. PROD activation also reconciles stale DEV state through the same verified transition path. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- Manual updater output now shows bounded phase/download/install progress, and release publication requires authored release notes before a tag can be published. [PR #275](https://github.com/whshang/herdr-mcp/pull/275)

### Agent capability and model evidence

- Capability inventory now distinguishes `not_scanned` from a completed scan with no usable evidence, including an explicit `needs_scan` signal instead of overloading an empty Agent list. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- Pi capability evidence can expose bounded non-secret configured-default and active-session provider/model facts. Active-session evidence wins over configured-default evidence for a running session; unknown values remain unknown rather than inferred. Relevant Pi default-model changes invalidate the scan fingerprint so stale defaults are not retained indefinitely. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- Per-launch model selection continues to use the existing native `agent.start.args` path, for example Pi `--model <provider/model>`. herdr-mcp does not own or copy Agent provider credentials. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)

### Planning and context efficiency

- `herdr_methods` now discovers the existing local `herdr_mcp.*` method schemas alongside the live Herdr socket schema. `planning.advise` no longer invents a single independent task unit when task structure was not supplied. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- `herdr_inspect` keeps recent/running exec evidence bounded and redacts command summaries; pure pane-scroll churn no longer advances activity/digest evidence used by `herdr_since`. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)
- Persistent `herdr_exec` utility-pane creation is serialized and remembers the just-created pane while snapshot/rename state converges, reducing duplicate `herdr-mcp:utility` panes without automatically closing user panes. [PR #276](https://github.com/whshang/herdr-mcp/pull/276)

## Known issues

- Agent provider/model evidence is observational. A model recorded by an older active session may later disappear from the Agent's current catalog, and a catalog entry may still fail if its provider credential or upstream route is unavailable. Before launching an override, the Agent's current local model catalog/provider configuration remains authoritative; herdr-mcp does not repair or synchronize those credentials.
- A workstation that is intentionally still in `native_migration.phase=candidate` remains candidate after upgrading. v0.4.4 reports that state accurately and does not silently promote a device to production-ready.

## Compatibility

- Workstation Runtime Execution Contract remains epoch 2 / 18 tools. v0.4.4 adds no public workstation tool and no new required parameter.
- Public ChatGPT contract remains epoch 3 / 19 actions; `herdr_devices` remains Edge-local.
- `herdr_prompt.target` semantics are unchanged.
- Existing v0.4.3 device credentials, Worker pairing, Connector configuration, browser-extension identity, and rollback evidence remain compatible.
- Default-device routing preserves legacy selector-free behavior when a unique configured legacy/default workstation can be proven; explicit device routing remains authoritative.
- No automatic cross-device failover, automatic worktree cleanup daemon, cross-device text/file-transfer API, or herdr-mcp-owned Agent credential/model registry is introduced in v0.4.4.
