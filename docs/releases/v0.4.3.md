# Herdr MCP v0.4.3

v0.4.3 is the first stable release with multi-device Worker support, safer self-upgrade, stronger macOS runtime identity, and a substantially more reliable Link/browser control path.

## Upgrade from v0.4.2

On a machine currently running **v0.4.2**, run:

```bash
herdr-mcp update apply
```

The v0.4.2 binary treats bare `herdr-mcp update` as a read-only update check. Starting with v0.4.3, the normal one-step command is `herdr-mcp update`, while `herdr-mcp update check` is the explicit read-only check. See [PR #262](https://github.com/whshang/herdr-mcp/pull/262).

A successful upgrade preserves the existing configuration, device credential and Worker pairing, and reconciles the managed service, production Link and owned Native Messaging runtime transactionally. Do not re-pair the device or delete/recreate the ChatGPT Connector just to upgrade the workstation runtime.

Verify after upgrading:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

Expected runtime version: `herdr-mcp 0.4.3`.

## Main changes

### Multi-device Worker

- One Worker / one Connector can route to multiple authenticated devices; `herdr_devices` is Edge-local while workstation execution remains epoch 2 / 18 tools. [PR #228](https://github.com/whshang/herdr-mcp/pull/228)
- Explicit device routing is deterministic, ambiguity fails closed, and opaque workspace/pane refs retain device affinity. [PR #234](https://github.com/whshang/herdr-mcp/pull/234)
- Revocation closes the live route and blocks reconnect without weakening cross-device isolation. [PR #250](https://github.com/whshang/herdr-mcp/pull/250)

### Secure device enrollment

- Added short-lived pairing with a 6-digit verification code plus high-entropy pairing identity; each device receives its own credential bound to immutable device identity. [PR #235](https://github.com/whshang/herdr-mcp/pull/235), [PR #248](https://github.com/whshang/herdr-mcp/pull/248)
- `herdr-mcp worker connect <pairing-address>` activates the local service and production Link after enrollment. [PR #258](https://github.com/whshang/herdr-mcp/pull/258)
- Added stable device display names and explicit device rename support. [PR #260](https://github.com/whshang/herdr-mcp/pull/260)

### Safer runtime updates and DEV / PROD workflow

- Added explicit DEV / PROD runtime channels for dogfood without treating source-development state as the production release. [PR #224](https://github.com/whshang/herdr-mcp/pull/224)
- Runtime generation activation and Link convergence are evidence-driven and recover from interrupted DEV syncs. [PR #249](https://github.com/whshang/herdr-mcp/pull/249), [PR #253](https://github.com/whshang/herdr-mcp/pull/253), [PR #259](https://github.com/whshang/herdr-mcp/pull/259)
- Safe read-only calls can recover across generation switches without replaying mutations. [PR #263](https://github.com/whshang/herdr-mcp/pull/263)
- Stable-channel daily auto-update uses the existing provenance-checked, rollback-aware updater. [PR #240](https://github.com/whshang/herdr-mcp/pull/240)
- Added product `reinstall` / `uninstall` lifecycle commands while preserving independent Herdr and the documented configuration/credential boundaries. [PR #243](https://github.com/whshang/herdr-mcp/pull/243)

### Link and workstation reliability

- Added bounded recovery for prolonged `workstation_offline` and machine-readable retry guidance. [PR #220](https://github.com/whshang/herdr-mcp/pull/220), [PR #222](https://github.com/whshang/herdr-mcp/pull/222)
- Oversized result payloads are contained instead of taking the Link loop offline. [PR #216](https://github.com/whshang/herdr-mcp/pull/216)
- Generation switches keep Link ownership fenced and online where possible. [PR #237](https://github.com/whshang/herdr-mcp/pull/237)
- Added local Link health watchdog coverage for server-healthy / Link-unhealthy incidents. [PR #246](https://github.com/whshang/herdr-mcp/pull/246)
- Launchd startup and health validation use separate bounded phases; stale loaded Link generation can be reloaded with the correct environment. [PR #261](https://github.com/whshang/herdr-mcp/pull/261), [PR #269](https://github.com/whshang/herdr-mcp/pull/269)

### macOS permissions and credential stability

- Stable TCC broker onboarding reduces repeated Full Disk Access authorization across rotating runtime generations. [PR #268](https://github.com/whshang/herdr-mcp/pull/268)
- Stable Keychain credential helper prevents each runtime generation from appearing as a new credential client. [PR #270](https://github.com/whshang/herdr-mcp/pull/270)

### Browser extension and long-conversation work

- Reduced ChatGPT long-conversation DOM work without removing React-managed conversation content. [PR #239](https://github.com/whshang/herdr-mcp/pull/239)
- Improved panel-state persistence and made Auto outcomes visible. [PR #255](https://github.com/whshang/herdr-mcp/pull/255)
- Reduced manual-control latency and false composer-busy behavior. [PR #227](https://github.com/whshang/herdr-mcp/pull/227), [PR #225](https://github.com/whshang/herdr-mcp/pull/225)
- Added configurable Continue-message preset. [PR #256](https://github.com/whshang/herdr-mcp/pull/256)
- Added image-only ChatGPT turn capture. [PR #213](https://github.com/whshang/herdr-mcp/pull/213)
- Added fixed-identity STANDALONE extension distribution alongside DEV / STORE. [PR #244](https://github.com/whshang/herdr-mcp/pull/244)

### Connector compatibility

- Added generic HTTPS Client ID Metadata Document support, including Claude-compatible OAuth metadata handling. [PR #266](https://github.com/whshang/herdr-mcp/pull/266), [PR #267](https://github.com/whshang/herdr-mcp/pull/267)
- Runtime upgrades do not require deleting/recreating the ChatGPT Connector; refresh/review/publish the action catalog to expose the new public `herdr_devices` action. [PR #262](https://github.com/whshang/herdr-mcp/pull/262)

## Known issues

- On macOS, `herdr-mcp uninstall` can transiently report that an owned launchd job is still loaded immediately after a successful `bootout`. v0.4.3 fails closed rather than deleting the corresponding plist/config while launchd still reports the job as loaded; waiting briefly and running uninstall again is the practical workaround. The bounded-wait fix was merged after the v0.4.3 tag in [PR #272](https://github.com/whshang/herdr-mcp/pull/272), so it is not included in the v0.4.3 binary.
- The immutable v0.4.2 updater can remain silent in the terminal while it validates release metadata/attestations and downloads the candidate during the one-time `herdr-mcp update apply` transition to v0.4.3. Do not start a second updater merely because no progress has printed; after the command returns, verify with the commands above. Live phase/download/install progress is a post-v0.4.3 updater improvement and cannot be retrofitted into the already-published v0.4.2 binary.

## Compatibility

- v0.4.2 workstations remain compatible with the epoch-2 / 18-tool workstation execution surface, but do not receive the v0.4.3 multi-device and reliability features until upgraded.
- Public ChatGPT contract is epoch 3 / 19 actions; the additional `herdr_devices` action is Edge-local and does not change the workstation Runtime Execution Contract.
- Upgrading the workstation does not change the device credential or Worker pairing and does not require rebuilding the ChatGPT Connector.
- The v0.4.3 tag and release assets remain immutable release evidence. The macOS ARM64 asset SHA-256 is `9d973285cc08504027f112fac1dfab5ba102fbbc7343e965f8e5b4a306a0924e`.
