# Herdr MCP v1.1.0-rc.5

v1.1.0-rc.5 是 1.1 的第五个预发布，仅面向 **preview** 更新通道。它修复 MacBook Pro PROD 升级验收（[#728](https://github.com/whshang/herdr-mcp/issues/728)）中发现的 `@herdr-mcp` 提及时 dispatch 父会话绑定失败（[#741](https://github.com/whshang/herdr-mcp/issues/741)）与同一会话重复 locator（[#740](https://github.com/whshang/herdr-mcp/issues/740)），是 #728 重新验收使用的候选版本。stable 用户继续留在 1.0.x。

## 升级

已处于 epoch 5 的 v1.1.0-rc.1 / rc.2 / rc.3 / rc.4 用户，在 preview 通道使用 `herdr-mcp update` 升级到 v1.1.0-rc.5。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

从 v1.0.x（epoch 4）出发的路径仍为两步（与 rc.4 相同）：

```text
v1.0.x（epoch 4）
  → v1.0.4 bridge（epoch 4，stable 通道，同一 contract identity）
  → v1.1.0-rc.5（epoch 5，preview 通道，签名清单声明 contract_migration）
```

**浏览器扩展升级顺序：** 先升级或重载浏览器扩展到 **0.1.228**（或更新），再切换 Runtime。本 RC 的 inline-mention 采样与精确 Project 推断在扩展中，Runtime 自更新不会更新扩展。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
```

确认 Runtime 为 1.1.0-rc.5、Runtime contract epoch 5 / 18 tools、state schema 15，service / local MCP 健康且 Link 在线。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **@提及的 dispatch 能绑定来源轮次（#741）：** Runtime 在所有来源轮次哈希点先规范化文本（NFC、去掉整词 `herdr` / `herdr-mcp` / `herdr_mcp` App 提及、折叠空白后 trim）再计算域分隔的摘要，扩展与模型对提及芯片的不同渲染不再导致 `source_turn_not_found`。旧摘要行不再作为证据（fail-closed），重新观察后恢复；该列为可追加列，旧二进制仍可打开数据库。 [PR #742](https://github.com/whshang/herdr-mcp/pull/742)
- **同一 ChatGPT 会话只保留一个当前 locator（#740）：** 会话在同一 generation 内被重新归属父级（Project → 账号）时，较新的观察胜出并退役兄弟 locator，消除 `browser_canonical_url_ambiguous`；扩展只从精确 project id（`/g/g-p-<id>` 路由或会话锚点 href）推断 Project，不再按标题子串归入 Project。 [PR #743](https://github.com/whshang/herdr-mcp/pull/743)
- **退役 locator 时迁移来源轮次证据：** 被退役会话的最新来源轮次在同一事务内迁移到存活会话，避免同一摘要落在两个会话上导致 `source_turn_ambiguous`。 [PR #744](https://github.com/whshang/herdr-mcp/pull/744)
- **浏览器扩展 0.1.228：** 携带 ChatGPT `inline-mention` 提及芯片采样（#742）与精确 Project 推断（#743）。 [PR #745](https://github.com/whshang/herdr-mcp/pull/745)

## 已知限制

- 本版本仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 仍需完成 MacBook Pro PROD 升级/回滚验收（#728）。
- 升级前观察到的来源轮次摘要不再作为绑定证据；升级后需在会话中重新发送一轮消息，再执行 dispatch。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。
- 设备重新注册后，旧 device id 的过期 browser endpoint 无法被正式退役，同一会话 URL 可能持续 `browser_canonical_url_ambiguous`；换新会话可规避（1.1.x，#734）。
- 设备级 WebChat 授权（#713 / #730）推迟到 1.1.x。
- Browser Extension 独立发布；本 Runtime RC 不发布 Store/Standalone 扩展。

## 兼容性

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**。
- First-party Public Edge contract：epoch **8 / 19 actions**。发版 PR 只改变 Edge 报告的 MCP server 版本字符串。
- Durable Runtime state：schema **15**（#741 只追加一个可空列，不是编号迁移）。
- 浏览器扩展：0.1.228。Runtime 自更新不更新 Browser Extension。
