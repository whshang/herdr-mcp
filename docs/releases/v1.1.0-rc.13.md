# Herdr MCP v1.1.0-rc.13

v1.1.0-rc.13（2026-11-02）是 1.1 的第十三个预发布，仅面向 **preview** 更新通道。相对 rc.12，它合入四项修复：扩展忽略过期的按标签页 handoff 转移，「接力」恢复不再把新会话导航走（#835/#836）；通过 dispatch / late-bind 绑定 ChatGPT 会话时自动创建 continuity 链，恢复「接力」（#834/#837）；`herdr-mcp update apply` 从所安装的发布重新暂存 STANDALONE 扩展副本（目录 `0700` / 文件 `0600`），扩展版本字符串升到 **0.1.240**，`doctor` 报告 `reload_pending` / `extension_stale`（#833/#838）；受管 HANDOFF 块通过本地 git clean filter 不再进入提交（#839/#840）。本版本没有新的 state 迁移（schema 16），Runtime contract epoch 5 / 18 tools、Edge epoch 8 / 19 actions 与 Herdr TUI 固定版本 0.9.5 均不变。这是**预发布**，stable 用户继续留在 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。

## 升级

已处于 schema 16 的 v1.1.0-rc.6 – v1.1.0-rc.12 用户，在 preview 通道前台执行 `herdr-mcp update` 升级到 v1.1.0-rc.13（本版本没有新的 state 迁移）。源码 dogfood 机器继续用 `herdr-mcp dev sync`。

v1.1.0-rc.1 – rc.5（schema 15）的 updater 不接纳 schema 迁移，需按 [安装文档](../i18n/zh-CN/install.md) 第 1 步用已验证二进制的 `install` 命令手动安装（与 rc.5 → rc.6 相同）。

从 v1.0.x（epoch 4）出发的路径为 v1.0.4 → v1.0.5 → v1.1.0：

```text
v1.0.x（epoch 4，含 v1.0.4）
  → v1.0.5 bridge（epoch 4，stable 通道，同一 contract identity；updater 接纳 schema 15 → 16）
  → v1.1.0（epoch 5，签名清单声明 contract_migration 与 state_schema_from 15）
```

v1.0.4 的 updater 只接纳与本机相同的 state schema，无法直接升级到 schema 16，必须先通过 stable 通道的 `herdr-mcp update` 到达 [v1.0.5](https://github.com/whshang/herdr-mcp/releases/tag/v1.0.5)。正式 v1.1.0 发布前，本 RC 仅用于 preview 验证。

**⚠️ 浏览器扩展：升级后必须重载扩展。** 本 RC 改动了 `extension/**`，扩展版本字符串从 0.1.229 升到 **0.1.240**。已有 STANDALONE 安装（`~/.config/herdr-mcp/extensions/standalone/current`）的机器，`update apply` 会由新下载的 rc.13 二进制把该副本重新暂存为 0.1.240（保持 manifest `key` 与扩展 ID 不变，目录 `0700`、文件含 `state.json` 均为 `0600`），但浏览器仍运行已加载的旧代码：**升级后请在 `chrome://extensions` 对 Herdr MCP 扩展点击「重新加载（Reload）」**。在重载之前 `herdr-mcp doctor` 显示 `reload_pending`；若暂存副本不属于当前 Runtime 发布则显示 `extension_stale`，执行 `herdr-mcp extension standalone install` 修复。没有 STANDALONE 安装的机器（DEV 源码目录以「加载已解压」方式载入，或 STORE 版本）不会被创建或改写，DEV 用户请从自己的源码目录更新并重载。

**⚠️ 状态库迁移不可降级：** 从 schema 15 首次启动 rc.6 及以上会迁移到 schema **16**（rc.6 引入；rc.7 – rc.13 无新迁移）；迁移后 rc.5 及更早的二进制（含 v1.0.x）拒绝打开该数据库。升级前请备份 Runtime state 目录；回退到 schema 15 版本必须先恢复迁移前的 state 备份。

**Worker 更新是独立步骤：** `herdr-mcp update` / `update apply` / `update auto` 只更新 Runtime；只有在交互式终端显式传 `update apply --with-worker` 才会串联 Worker 更新。Worker 落后时保留成功的 Runtime 结果并输出非致命提示，下一步是单独执行 `herdr-mcp worker update`（需要交互式 Cloudflare 授权）。

升级后验证：

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp doctor
herdr-mcp update status
```

确认 Runtime 为 1.1.0-rc.13、Runtime contract epoch 5 / 18 tools、state schema 16，service / local MCP 健康且 Link 在线；`doctor` 的 `standalone-extension-version` 在重载扩展后应为 `current`。验证实际 active generation 和受管服务，源码版本与构建产物不能证明生产 Runtime 已升级。

## 主要变更

- **「接力」恢复忽略过期的按标签页 handoff 转移（#835）：** 手动 ChatGPT Project handoff 复用来源标签页，未完成的转移按 tab id 持久化，旧转移可能在同一标签页开启同一 Project 的新会话后被恢复并把页面导航到 Project 首页。新增纯函数 `handoffSourceNavigationBlock` 与 15 分钟 `HANDOFF_TAB_RESUME_TTL_MS`：只有标签页仍显示转移的来源会话、记录的目标会话、进行中状态下转移自身的 Project 首页，或页面本身确认了该转移的 seed 标记时，转移才拥有该标签页；否则以 `stale_handoff_conversation_mismatch` / `stale_handoff_expired` 失败且绝不导航。在 `launchHandoffTarget`、`resumeHandoffForCurrentTab` 与 `startHandoffForTab` 三处执行；已送达的 seed 通过只读 `h2w_handoff_probe` 仍可被采纳。 [PR #836](https://github.com/whshang/herdr-mcp/pull/836)
- **dispatch / late-bind 绑定会话时自动创建 continuity 链（#834）：** 过去只有扩展显式绑定或日志轮次会写 continuity 行，`agent.task.dispatch` 绑定的会话在 `/extension/continuity/resolve` 一律 `continuity_not_found`，在 #812 的闸门下「接力」几乎处处不可用。新增幂等的 `StateStore::attach_continuity_for_conversation`（复用已有唯一 owner，否则按 provider + 会话身份生成确定性的 `hc:auto:<digest>` 链，归属歧义时 fail-closed 为 `continuity_binding_ambiguous`）；dispatch 在结果同时带已绑定父会话与持久 `task.workspace_id` 时尽力附加该链，绝不让 dispatch 失败。扩展日志在回答 `continuity_unbound` 前先解析 Runtime 拥有的链，轮次以 provider 会话 id 记录，handoff 包可接受该链作为来源。`herdr-mcp doctor` 新增只读的 `continuity-journal` 层。无 schema 变化。 [PR #837](https://github.com/whshang/herdr-mcp/pull/837)
- **`update apply` 重新暂存 STANDALONE 扩展、扩展版本 0.1.240、doctor 报告重载待办（#833）：** detached 更新任务（新下载的发布二进制）在服务安装提交后立即暂存匹配的 STANDALONE 副本，交互式前台与 `update_current` 路径用目标发布 commit 重跑同一幂等步骤；复用 `extension standalone install` 的原子 staging → rename 切换与 manifest `key` 注入，只在已有 STANDALONE 安装时执行，从不创建或修复 `~/Documents` 别名（不触发 TCC），暂存失败只输出非致命 `extension_stale` 提示。受管树改为私有（目录 `0700`、文件与 `state.json` `0600`），重新暂存会修复旧版本留下的 `0755`/`0644`。扩展版本 0.1.229 → **0.1.240**（大于所有已观测到的候选构建），新增 `scripts/check-extension-version.mjs` 版本守卫。`doctor` 新增 `standalone-extension-version` 层：`current` / `reload_pending` / `extension_stale` / `extension_ahead` / `not_installed` / `unknown`，`update apply` 同步输出 `extension_reload_required` / `extension_stale` 非致命提示。 [PR #838](https://github.com/whshang/herdr-mcp/pull/838)
- **受管 HANDOFF 块不再进入提交（#839）：** `write_handoff` 向已被跟踪的 `AGENTS.md` / `CLAUDE.md` 注入的 `<!-- herdr:handoff:start -->` 块过去是普通本地修改，容易被误提交。现在对已跟踪文档只写本地 git 状态：`<git-common-dir>/info/attributes` 中的 `filter=herdr-handoff`，以及仓库本地 `filter.herdr-handoff.clean`（内部子命令 `herdr-mcp git-filter strip-handoff`）/ `smudge=cat`，刻意不设置 `required`，filter 缺失时 git 退回未过滤内容。从不读取、创建或编辑被跟踪的 `.gitattributes`；`git status` / `git diff` 在只有该块不同时保持干净，`git diff --cached` 在 handoff tick 后始终为空，真实编辑仍是未暂存修改。未跟踪、由 herdr 创建的文档仍用 `info/exclude`。 [PR #840](https://github.com/whshang/herdr-mcp/pull/840)

## 人工 UAT（切 tag 前需逐项完成）

以下步骤**没有**在写本稿时执行，因此本稿不声称任何实时设备验收已完成。需由 release owner 逐项完成并留证：

- 扩展重新暂存（#833/#838）：在有 STANDALONE 安装的 PROD 机器上 `update apply` 后确认 `standalone/current/manifest.json` 版本为 0.1.240、manifest `key`（扩展 ID）不变、目录 `0700` / 文件 `0600`，`doctor` 在重载前报告 `reload_pending`、重载后为 `current`。
- 「接力」（#834/#837、#835/#836）：对经 dispatch 绑定的 ChatGPT 会话确认 continuity resolve 成功、接力可用，且同一 Project 新会话不会被导航到 Project 首页。
- HANDOFF 块（#839/#840）：在跟踪 `AGENTS.md` 的仓库里确认 handoff tick 后 `git status` 干净、`git diff --cached` 为空。
- 重跑 `herdr-mcp doctor`，确认 service / Link / local MCP 全绿。

## 已知限制

- 本版本是预发布，仅供 preview 验证，stable 用户继续使用 1.0.x；正式 v1.1.0 GA 标签需 owner 另行批准。本 RC 自身的 PROD 复验仍需执行。
- Runtime 更新只重新暂存 STANDALONE 文件，浏览器不会自动重载扩展；必须手动在 `chrome://extensions` 点击 Reload。DEV（加载已解压的源码目录）与 STORE 安装不会被 Runtime 更新改动。
- 从 rc.12 或更早升级时，执行重新暂存的是新下载的 rc.13 detached 任务；若该步骤失败，Runtime 更新仍成功，`doctor` 报告 `extension_stale`，需手动执行 `herdr-mcp extension standalone install`。
- `Chrome Web Store package` 工作流的严格版本守卫在 `6ccd3ea4` 上因浅克隆中无可解析的 `v*` tag 而失败（`extension-version-guard: FAIL · no v* release tag resolves`）；本 RC 不发布 Store/Standalone 扩展包，Runtime 发布不受影响。
- 跨设备来源轮次绑定（chat 在 A 设备、派发到 B 设备）仍不支持，只给出 `caller_browser_on_other_device` 原因（#775）。
- schema 16 迁移后 rc.5 及更早的二进制无法打开 state；回退需先恢复迁移前的 state 备份。
- Runtime 更新不执行 Worker 更新；Worker 落后时只报告 `worker_update_required`，必须由操作员单独执行 `herdr-mcp worker update`。
- 成功升级后的 `herdr-mcp rollback` 仅限 macOS。

- Workstation Runtime Execution Contract：epoch **5 / 18 tools**（`contracts/` 未修改）。
- First-party Public Edge contract：epoch **8 / 19 actions**（未修改；Edge 只更新 `MCP_SERVER_VERSION` 字符串）。

- CI / release gate 固定 Herdr TUI：**0.9.5**（未变）。
