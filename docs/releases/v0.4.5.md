# Herdr MCP v0.4.5

v0.4.5 focuses on installation smoothness, Link resilience, multi-device browser visibility, and macOS runtime reliability without expanding the frozen workstation MCP contract. It keeps the user's Cloudflare Worker as the public MCP/OAuth control plane, prefers a dedicated Custom Domain when an existing Cloudflare zone makes that practical, and makes the no-domain path resilient through direct `workers.dev`, an already-configured local proxy, and a qualified shared Relay fallback.

## Upgrade

From v0.4.4:

```bash
herdr-mcp update
```

The upgrade preserves the existing Worker, OAuth/Connector identity, device credentials, production Link ownership, Native Messaging integration, and configuration. It does not require re-pairing an existing workstation.

Verify after upgrading:

```bash
herdr-mcp version
herdr-mcp status
herdr-mcp service status
herdr-mcp link status
```

The expected runtime version is v0.4.5. On a maintainer machine using the DEV channel, use `herdr-mcp dev status` to distinguish the source-dogfood runtime from the published PROD release.

## Main changes

- First-install and existing-fleet onboarding now share one explicit decision path. The Agent bootstraps a Worker without requiring a domain or R2, recommends a dedicated Cloudflare Custom Domain before Connector/OAuth registration when the selected account already has a suitable active zone, and otherwise completes installation on `workers.dev` instead of blocking. Existing fleets can create a short-lived pairing directly from the OAuth-authorized ChatGPT conversation; the response includes the pairing address, one-time 6-digit code, exact expiry, and copyable `worker connect` command. The same owner conversation can permanently revoke an old enrolled device by immutable `device_id` without requiring that workstation to be online; CLI `worker pair` / `worker revoke` remain fallbacks. [PR #295](https://github.com/whshang/herdr-mcp/pull/295)
- The Rust Link now separates stable public MCP/OAuth identity from outbound Link transport. Without a Custom Domain it can try direct `workers.dev`, a validated local HTTP/HTTPS/SOCKS5 proxy, then a qualified shared Relay without changing the Connector URL or replaying a mutation across routes. The release admits the mainland-China-qualified Deno/Supabase baseline with stable capacity-weighted per-device selection, signed remote pool replacement, monotonic revision/expiry validation, atomic last-known-good cache, and fail-closed handling for reachable-but-incompatible Edge contracts. [PR #295](https://github.com/whshang/herdr-mcp/pull/295)
- Browser extension 0.1.90 and the native runtime are aligned for fleet visibility. The existing Side Panel Control Center reads a sanitized owner-authorized device inventory through tokenless Native Messaging, shows authorization/connection/health/runtime-generation freshness, explains disabled actions, keeps Worker/OAuth credentials out of Chrome, makes the device region independently collapsible, and hides revoked authorization tombstones from normal fleet views while retaining the internal tombstone that prevents credential resurrection. The Store package carries the concise `Herdr MCP - Workspace Connector` name and monochrome ram/terminal connector icon; extension versioning remains independent from runtime v0.4.5. [PR #295](https://github.com/whshang/herdr-mcp/pull/295) [PR #296](https://github.com/whshang/herdr-mcp/pull/296)
- Runtime and planner reliability fixes reduce false completion and stale-state decisions: fresh GitHub PR/check status is available through the existing local method, DEV activation waits for health convergence, watchdog/event-cache health remains non-blocking, and protected macOS repository probes stay on the stable TCC identity. [PR #287](https://github.com/whshang/herdr-mcp/pull/287) [PR #289](https://github.com/whshang/herdr-mcp/pull/289) [PR #290](https://github.com/whshang/herdr-mcp/pull/290) [PR #291](https://github.com/whshang/herdr-mcp/pull/291) [PR #292](https://github.com/whshang/herdr-mcp/pull/292)
- macOS TCC broker launches now disclaim responsibility from the rotating runtime so Full Disk Access remains attached to the stable broker identity; Linux CI also keeps the macOS-only process/test paths correctly fenced. [PR #293](https://github.com/whshang/herdr-mcp/pull/293)
- `herdr_fs_patch` no longer reports a successful-looking patch result when the transactional apply did not commit. The failure path stays fail-closed and leaves deterministic evidence for the planner instead of silently implying a mutation occurred. [PR #288](https://github.com/whshang/herdr-mcp/pull/288)

## Known issues

- Shared Relay is intentionally an outbound fallback only for the no-Custom-Domain Link path. When a Custom Domain is configured, the Link does not silently bypass that chosen origin through the shared Relay; verify that the selected Custom Domain is reachable from the workstation network.
- The Supabase Relay fallback runs on a hosted Edge Function with a bounded execution lifetime. v0.4.5 was qualified across multiple lifecycle windows and reconnects without duplicate mutation delivery, but reconnects are expected rather than a permanently pinned WebSocket process.
- Browser extension distribution is independent from the runtime GitHub Release. Runtime v0.4.5 does not install or update the Chrome extension; ordinary users receive extension 0.1.90 through the Store when that Store review/update is available.

## Compatibility

- Workstation Runtime Execution Contract remains epoch 2 / 18 public tools. v0.4.5 adds no new public workstation tool and no new required workstation parameter.
- Public ChatGPT contract remains epoch 3 / 19 actions. Conversational pairing and owner revoke both use Edge-local methods under the existing `herdr_call` surface rather than adding public actions.
- Existing v0.4.4 device credentials, Worker registrations, OAuth/Connector identity, Custom Domain, Native Messaging ownership, production Link, and rollback state remain compatible.
- `workers.dev` remains a fully supported public MCP/OAuth origin. Custom Domain selection is a recommended installation default when a suitable zone exists, not a forced migration of existing installations.
- R2 remains optional for core installation. The shared Deno/Supabase Relay is outbound Link transport only and never becomes the user's public MCP/OAuth endpoint or a generic proxy.
- Browser extension STORE/STANDALONE/DEV identities and versioning remain independent from the runtime release plane.
