# 1.1 feature list — living GO checklist

This is the working checklist for declaring **Herdr MCP 1.1 stable**. It
condenses what 1.1 ships, how it compares with adjacent tools, and exactly
what remains before a stable GO. Keep every row's status honest: `TODO`,
`PARTIAL`, `DONE`, or `DEFERRED` (tracked past 1.1 GA and explicitly not a 1.1
GO criterion), each with a one-line acceptance condition. Update this
file as gates close; the tagged release notes stay frozen in
[`v1.1.0.md`](v1.1.0.md).

## 1. Goal and non-goals

Goal: a **three-layer browser capability** for MCP clients —

1. **Chrome extension** — owns tabs, content observation, and page actions in
   the user's real browser.
2. **Local host (Runtime)** — exposes those capabilities to local MCP clients
   with idempotency, delivery states (`applied` / `uncertain` / `not_applied`),
   and per-caller grants.
3. **Site adapters** — optional, reviewed layers on the *same* BrowserPage API
   that turn proven page operations into reliable site operations (Bilibili,
   X, Doubao today; any site via the skill-adapter model).

Priority within 1.1 web control (asu, 2026-10-23):

- **P0 — core: WebChat self-control.** On the same BrowserPage / control
  plane, 1.1 qualifies **ChatGPT** signed-in create, send, stop, archive and
  settle, plus grants and parent_session/inbox (rows 5–6) and Chrome MV3
  recovery (row 7). **Claude and Grok ship only the shared operations** —
  dispatch submit, dispatch stop, and delivery settlement — because their
  adapters declare `browserActuation` + `stopGeneration` only
  (`CLAUDE_ADAPTER_CAPABILITIES` in `extension/content/injector/claude.js`,
  `GROK_ADAPTER_CAPABILITIES` in `grok.js`) while ChatGPT also declares
  `sessionCreate` / `sessionOpen` / `titleProjection`
  (`CHATGPT_ADAPTER_CAPABILITIES` in `chatgpt.js`).
- **P0 — user-visible loss in 1.1**
  ([owner scope decision, 2026-11-06](https://github.com/whshang/herdr-mcp/pull/861#issuecomment-6679882630)).
  Claude and Grok create, open and archive are **refused, not shipped**:
  non-ChatGPT `session.open` / `session.archive` return `unsupported` (the
  mutation-scope block in `crates/herdr-mcp/src/mcp.rs`), and non-ChatGPT
  `session.create` fails the support matrix (same file,
  `browser_operation_alpha4_supported`) and source routing
  (`browser_create_source_provider_unavailable`). Full three-provider
  create/open/archive parity — #692 phases 1–3 — is **tracked for 1.1.x rather
  than 1.1 GA**, is explicitly **not a 1.1 GO criterion**, and does not
  authorize tagging `v1.1.0`.
- **P1 — secondary: site adapters.** Bilibili / X / Doubao adapters and the
  skill author→replay path (rows 10–11) come clearly after P0: they must not
  outrank or delay WebChat self-control work. Site adapters are examples of
  the *same* unified adapter model, not a separate mechanism.

### Operating model (product intent, not a gate)

WebChat clients act as the **main brain**: they plan, dispatch, and supervise.
They should prefer driving coding agents through herdr over self-executing
heavy implementation work — while the full tool surface stays available, so a
client can still execute directly when that is genuinely the right move.
Coding agents (pi / omp / …) implement and verify; herdr coordinates the
multi-agent flow. This describes intended 1.1 usage; it adds no new GO row.

Non-goals (explicitly **not** 1.1 GO criteria):

- **Full site/command catalog parity with OpenCLI.** OpenCLI ships a very
  large hand-curated site catalog; Herdr ships a small set of reviewed
  adapters plus the authoring model. Parity in breadth is not a gate.
- Unrestricted page eval / arbitrary CDP exposure to model callers (the
  runtime deliberately keeps mutation fenced and observable).
- Social-write automation, cross-frame trees, generic upload/download, and
  hover/drag gestures.
- **Claude / Grok create, open and archive parity** (#692 phases 1–3, tracked
  for 1.1.x rather than 1.1 GA). 1.1 keeps the narrower shipped surface
  described in the P0 bullets above and states the loss instead of widening
  the gate.
- **The new Herdr app and `herdr-core` (`hc`).** 1.1 supports **only Herdr TUI**
  (`herdr` CLI and `herdr server`, pinned to `0.9.5` in CI and the release
  gate). The new Herdr app and `herdr-core` (`hc`) are separate runtimes that
  do not share agents with the TUI, and supporting them is not a 1.1 GO
  criterion.

## 2. Architecture (one paragraph + pointer)

MCP clients (local or via Edge/WebChat) call the Runtime; the Runtime fences
every mutation behind caller grants and idempotency, forwards browser
operations to the extension over the trusted native channel; the extension
executes them against owned or claimed tabs and reports postcondition
evidence; the Runtime settles delivery state from that evidence — never from
optimistic success. WebChat (ChatGPT/Grok/Claude sessions) rides the same
extension boundary with per-endpoint control grants instead of a parallel
automation path. Adapters are skills over BrowserPage, not plugins inside a
page VM. Details: [`../_wip/v1.1-browser-adapter-platform.md`](../_wip/v1.1-browser-adapter-platform.md),
[`../_wip/browser-control-plane.md`](../_wip/browser-control-plane.md).

## 7. Known limitations (mirrored from v1.1.0.md)

- `press` synthesizes untrusted key events; browser defaults are not
  guaranteed — prefer explicit click. Live-confirmed 2026-11-07 on the MacBook
  Air (extension 0.1.243): `press` `Enter` applied with `isTrusted=false` and
  left the fixture `unsubmitted`; `click` applied and changed the page.
  [#617](https://github.com/whshang/herdr-mcp/issues/617)
- `decision-vercel` routes return 403 (`RestrictedModelsError`) on the Vercel
  free tier, so `jev-vercel` is removed from the default route pool; the
  protocol remains opt-in with paid credits. [#621](https://github.com/whshang/herdr-mcp/issues/621)
- Semantic fast-path calibration margin vs fixed threshold contract
  inconsistency. [#622](https://github.com/whshang/herdr-mcp/issues/622)
- Edge/Link `create` beyond ~60s ends in request timeout; retry with the same
  idempotency key (never rotate it).
- Created-session title may be overwritten by ChatGPT auto-title;
  `title_projection` reflects creation-time projection only. [#624](https://github.com/whshang/herdr-mcp/issues/624)
- Archive requires the session tab open, else `browser_session_target_unavailable`. [#623](https://github.com/whshang/herdr-mcp/issues/623)
- Claude / Grok WebChat currently support only submit / stop / settle; create /
  open / archive are refused as `unsupported` and tracked for 1.1.x / 1.2
  rather than 1.1 GA. [#692](https://github.com/whshang/herdr-mcp/pull/692)
- Extension 0.1.214+ with a matching Runtime pages `observe` with `element_offset` (0..4096) and `next_element_offset` (null at the end); live Chrome page-0/page-128 UAT recorded on [#691](https://github.com/whshang/herdr-mcp/pull/691) head `1def6e68` with the 0.1.214 build from that commit. Extensions older than 0.1.214 still cap at the first 128 elements in document order, and the Runtime rejects `element_offset` for them. Released 1.1.0 notes stay frozen. [#615](https://github.com/whshang/herdr-mcp/issues/615)
- Device-wide (`scope: "device"`, `*/*/*`) WebChat grants and owner-only
  `platform_account` labels are deployed on Edge PROD ([#713](https://github.com/whshang/herdr-mcp/pull/713));
  DEV API UAT covered allow/deny/cleanup ([#730](https://github.com/whshang/herdr-mcp/issues/730)).
  Edge stores and audits them, but the Runtime does not yet honor them for
  WebChat dispatch (it drops `*/*/*` rows; consumption is follow-up work); the
  qualified 1.1 dispatch path uses per-endpoint + provider grants
  ([#589](https://github.com/whshang/herdr-mcp/pull/589)).
- Post-upgrade `rollback` is macOS-only for the service path; Windows
  x86_64/ARM64 remain Candidate support.
- Herdr terminal Pane events carry no task-specific `state_change_seq`; an
  ambiguous `final_excerpt` is therefore omitted instead of risking
  cross-task leakage. Task terminal state, Inbox, notifications and ACK are
  unaffected. [#675](https://github.com/whshang/herdr-mcp/issues/675)
- **Only Herdr TUI is supported.** Herdr integration in 1.1 covers the Herdr
  TUI only (`herdr` CLI and `herdr server`, pinned to `0.9.5` in CI and the
  release gate). The new Herdr app and `herdr-core` (`hc`) are separate
  runtimes that do not share agents with the TUI and are **not supported** in
  1.1; the same statement is repeated in [`v1.1.0.md`](v1.1.0.md)
  (`## 兼容性`) so neither surface implies support that does not exist.

- `connector page-assist allow` derives an any-provider (`*`) webchat-control grant
  on the same endpoint at forward time (PR #595, `mcp.rs:8417-8460`); neither the
  command name nor the UI surfaces this effect — a transparency follow-up, not an
  overreach (2026-11-09 GA6G audit). The two D1-written grant rows are also
  classified orphan rows by `list_orphans` (record pointer `conn_Zxg2V0873…` ≠
  row owner `conn_uGpF…`) with zero functional impact; disposition pending owner.
- A fresh tab whose content loads slower than the 15-s load gate fails with
  `browser_page_storage_unavailable`, a name that points at page storage instead
  of the load-gate timeout (2026-11-09 GA7 correction; the earlier
  persistence-poisoning theory was withdrawn — the single-threaded local fixture
  was occupied 600 s by `/hang`).
- The 2048 pending+unknown operations cap has no write-off path before
  [#869](https://github.com/whshang/herdr-mcp/issues/869): a production endpoint
  that hits the cap permanently fails closed for new browser_page actions. Owner
  decision B: no live destructive run; the target unit test ran green on
  `9d84bf83`.
- Under a provider rate-limit window, create-with-message and
  send-to-existing-session behaved as two distinct submission surfaces (three
  creates applied→settled while three sends were all refused
  `browser_dispatch_submit_failed`, zero delivery) — surfaced 2026-11-09; a
  refused send in the window does not mean the create path fails too.
- A stale offline DEV connector on the ChatGPT side adds per-call routing noise
  (and an unbound main connector resolves `device_ambiguous`); owner cleanup in
  the GUI connector surface suggested.
- After a runtime cutover that does not change `extension/`, `doctor` keeps
  reporting `extension_stale` because staged `state.json` still records the old
  runtime's source commit (2026-11-09 GA3 audit: byte-identical tree except the
  injected manifest `"key"`). The literal state cannot distinguish "no extension
  change" from a real content change until staged provenance is refreshed —
  masking risk; refresh decision pending owner.
