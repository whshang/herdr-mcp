# Herdr-MCP 1.0 Alpha 3 — Browser Endpoint and Resource Registry

Status: implemented and merged in PR #315 (`6e99bb7`).

Planning SSOT: [`docs/history/architecture/v1.0-architecture-plan.md`](../history/architecture/v1.0-architecture-plan.md), restored from `47a6f80:docs/_wip/v1.0-architecture-plan.md`.

## Goal

Alpha 3 adds the minimum provider-neutral browser identity layer needed before any provider adapter may actuate a WebChat session.

It establishes stable browser endpoint/account/space/session refs, fenced capability snapshots, local-only consent, and fail-closed resource resolution while reusing the existing Chrome Native Messaging -> mode-0600 Unix socket -> Rust runtime path.

Alpha 3 does **not** dispatch messages or reserve browser resources.

## Existing boundaries reused

- Browser transport/auth: existing Chrome Native Messaging origin admission and `extension.sock`; no browser bearer/token.
- Trusted local mutation path: the existing `trusted_extension_ipc=true` Axum router. Browser registry writes are accepted only there and require the caller profile seed to derive the authoritative endpoint ref, preventing cross-profile mutations.
- Remote read path: the existing `herdr_call` workstation routing; no new public MCP tool/action or contract epoch.
- Device identity: the enrolled `edge.device_id` from local runtime configuration; the extension cannot supply or override it.
- Local durable state: the existing `StateStore` SQLite/WAL database and migration chain.
- Fleet routing/revocation: existing Edge device routing and revocation; Alpha 3 adds no second device registry.
- Planner Lease / Execution Lane: unchanged. Browser Resource Reservation is a separate later ownership mechanism.

## Milestone boundary

The architecture plan places browser resource reservation/failover in `1.0.0-beta.2`, not Alpha 3. Therefore Alpha 3 intentionally has:

- no browser reservation table;
- no reservation Durable Object keys;
- no acquire/renew/release/takeover state machine;
- no multi-device endpoint scheduler/failover;
- no Edge browser registry projection.

Cross-device calls continue to select the workstation through the existing explicit device-routing layer. Fleet-wide reservation arrives in beta.2 after endpoint/resource identity is proven.

## Identity model

Canonical hierarchy:

```text
device
  -> browser_endpoint
       -> provider_account
            -> space?        # only for providers with a native grouping object
                 -> session
                      -> view* # local observation only; never durable identity
```

### Endpoint ref

The extension owns a random browser-profile instance seed in `chrome.storage.local`. The seed survives tab/window/browser restart but is regenerated by a real extension-profile reinstall/reset.

The trusted runtime derives the externally returned endpoint ref from that seed and the locally authoritative device identity. The raw seed is never persisted in SQLite or returned through remote inspection.

Endpoint refs are opaque and must not encode a URL, tab id, workspace id, absolute path, account id, or selector.

### Provider resource refs

The trusted extension observes provider-native identity material locally. It sends that material only through trusted Extension IPC. The runtime derives an opaque resource ref from the endpoint/provider/kind/parent/native identity tuple and persists only a digest, not the raw provider-native key.

Kinds are exactly:

- `account`
- `space`
- `session`

`space` is optional. No fake provider grouping object is synthesized.

## Minimal local storage

Alpha 3 adds exactly three logical tables to the existing `state.db` schema:

1. `browser_endpoints`
   - endpoint ref
   - authoritative local device id
   - browser family
   - extension version
   - monotonic `consent_revision` for CAS concurrency control
   - first/last observed timestamps
   - three local permission bits, all default OFF:
     - WebChat Control
     - WebChat Tool Bridge
     - Tool Bridge workstation mutation
2. `browser_provider_state`
   - endpoint ref + provider
   - adapter protocol version
   - monotonic observation generation
   - bounded capabilities JSON
   - observed timestamp
3. `browser_resources`
   - opaque resource ref
   - endpoint ref + provider + kind + optional parent ref
   - digest of local provider-native identity
   - optional bounded display label
   - observation generation
   - first/last observed timestamps

No second SQLite file, resident daemon, alarm, timer, browser state service, or Edge persistence is introduced.

## Capability snapshot fencing

For each `(endpoint_ref, provider)` snapshot:

- capabilities must adhere to a strict provider-neutral allowlist (`{"operations":[...]}` with semantic operations from the 1.0 architecture plan); arbitrary JSON, unknown keys, and credentials/native IDs are rejected;
- generation must be a positive monotonic integer;
- a strictly newer generation replaces the current snapshot;
- the same generation with the same protocol/capability payload is idempotent;
- a same/older generation with different state fails `stale_capability_generation`;
- resource observations must name the current capability generation or fail closed.

A future mutation planned against generation N must never silently run against N+1.

## Local consent

All three permission bits default OFF.

Only trusted Extension IPC may mutate these bits. Remote MCP/Edge callers receive read-only inspection and resolution methods and have no method that enables or widens local permissions.

The three gates are independent and narrowing:

- WebChat Control permission does not imply Tool Bridge permission.
- Tool Bridge permission does not imply workstation mutation permission.
- workstation mutation cannot be true unless Tool Bridge is true.

Alpha 3 stores and enforces this contract; provider actuation is still absent.

## Private method surface

Remote workstation private methods are read-only:

```text
herdr_mcp.browser_endpoint.list
herdr_mcp.browser_endpoint.inspect
herdr_mcp.browser_resource.list
herdr_mcp.browser_resource.inspect
herdr_mcp.browser_resource.resolve
```

They remain behind `herdr_call`; workstation Runtime Execution stays epoch 2 / 18 tools and public Edge stays epoch 3 / 19 actions. Calls routed through Edge require an explicit non-empty `device` selector or fail closed with `device_required` before forwarding.

Trusted Extension IPC receives one bounded local route for registry observations/consent. It is not reachable over ordinary TCP without the existing extension bearer boundary and registry mutations specifically require `trusted_extension_ipc=true`.

## Fail-closed resolution

`browser_resource.resolve` accepts only provider-neutral filters and stable refs. It never accepts URL, tab id, title, CSS/XPath, JavaScript, CDP, cookie/token, keyboard/mouse macro, or arbitrary navigation input.

Resolution outcomes:

- exactly one current match -> return it with endpoint local consent snapshot and `actuation_available:false` (Alpha 3 establishes identity resolution only; resolution does not authorize execution or provider actuation);
- zero -> `browser_resource_not_found`;
- multiple -> `browser_resource_ambiguous`;
- stale observation generation -> `stale_capability_generation`;
- missing/disabled endpoint consent is reported explicitly and never silently widened.

## Explicit non-goals

Alpha 3 does not add:

- ChatGPT/Gemini/Claude DOM adapters;
- composer/model/reasoning actuation;
- message append/submit;
- external conversation dispatch;
- generation stop/status execution;
- Browser Resource Reservation/failover;
- Playwright, CDP, OpenCLI, external browser automation;
- raw URL/selector/JavaScript contracts;
- OAuth scope/grant widening;
- GitLab/GitHub/Feishu/Jira policy;
- a new public MCP tool or contract epoch.

## Acceptance matrix

### Storage / Rust

- schema v6 -> v7 migration and fresh DB creation;
- existing v5 -> v6 -> v7 migration path remains valid;
- endpoint registration derives opaque ref and never persists raw profile seed;
- endpoint registration is idempotent and preserves consent;
- provider capability generation monotonicity/idempotent replay;
- resource account/space/session hierarchy validation;
- resource observation rejects stale generation and fake/mismatched parent hierarchy;
- raw provider-native identity is absent from persisted rows and returned payloads;
- exact/ambiguous/not-found resolution;
- permission hierarchy and default-off behavior.

### Trusted Extension IPC

- registry mutation succeeds only with `trusted_extension_ipc=true`;
- TCP request to the same route is unauthorized/fail-closed;
- extension cannot provide/override device id;
- unknown fields, oversized bodies and invalid kinds fail closed.

### MCP private read surface

- read-only endpoint/resource list/inspect/resolve route through existing `herdr_call` local dispatch;
- no remote consent mutation method exists;
- public runtime catalog remains epoch 2 / 18 tools;
- public Edge catalog remains epoch 3 / 19 actions.

### Extension

- stable profile seed is generated once per extension profile and reused;
- registry registration travels through existing `localHerdrFetch` Native Messaging path;
- no Herdr bearer or provider credential is stored/sent;
- extension smoke remains green.
