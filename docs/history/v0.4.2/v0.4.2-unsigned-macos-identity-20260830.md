# v0.4.2 unsigned macOS identity — 2026-08-30

## Decision

Developer ID signing and notarization are **optional hardening**, not a v0.4.2 release gate.

macOS TCC grants Files and Folders / Full Disk Access to a stable code identity. An unsigned binary that is replaced on every runtime generation is a new identity. v0.4.2 therefore ships a **stable local broker** at `~/.config/herdr-mcp/tcc-broker/herdr-mcp-broker`, outside `runtime/generations/`. Service install and update apply preserve that path and those bytes. If the current runtime bytes differ from the installed broker, the updater/service path reports `broker_update_available` and does not replace the identity. Explicit full uninstall may remove the broker.

## User lifecycle

```bash
herdr-mcp permissions status
herdr-mcp permissions setup
herdr-mcp permissions verify
```

- `status` classifies `granted` / `denied` / `needs_setup` / `unknown` / `timeout` with an actionable hint.
- `setup` installs the broker if missing and may open macOS Privacy & Security. It never claims to grant permission.
- `verify` runs a bounded (≤2s, kill/reap) broker-based protected-path probe, plus `git rev-parse --git-common-dir` / `git status` and a mutation-free write gate (`access(W_OK)` only).
- `doctor` prints a distinct `LAYER macos-permissions` line. Denied or timed-out probes fail doctor; missing broker is `needs_setup`, not a silent pass disguised as Herdr transport health.

## MCP mapping

Public contract remains epoch 2 / **18 tools**. `herdr_fs_*` and `herdr_git` map EPERM/EACCES and protected-path/broker timeouts to `macos_tcc_access_blocked`. Unrelated IO (`not_found`, `outside_managed_roots`, ordinary git timeouts) is not remapped.

## What this is not

- Not a claim that unsigned binaries are equivalent to Developer ID for every TCC prompt.
- Not a v0.4.2 requirement to obtain or configure a paid Developer ID in CI.
- Not a new MCP tool.
