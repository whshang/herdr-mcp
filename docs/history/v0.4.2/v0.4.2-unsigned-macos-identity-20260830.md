# v0.4.2 unsigned macOS identity — 2026-08-30

## Decision

Developer ID signing and notarization are **optional hardening**, not a v0.4.2 release gate.

macOS TCC grants Files and Folders / Full Disk Access to a stable code identity. An ad-hoc runtime binary that is replaced on every generation has a cdhash-bound designated requirement and must not be the long-lived TCC client. v0.4.2 therefore ships a **stable local broker** at `~/.config/herdr-mcp/tcc-broker/herdr-mcp-broker`, outside `runtime/generations/`. Service install and update apply preserve that path and those bytes. Broker update eligibility is keyed to an explicit broker compatibility revision, **not** to the surrounding `herdr-mcp` runtime bytes, so ordinary runtime rebuilds/upgrades do not replace the granted broker identity or report a false broker update. Explicit full uninstall may remove the broker.

## User lifecycle

```bash
herdr-mcp permissions status
herdr-mcp permissions setup
herdr-mcp permissions verify
```

- `status` classifies `granted` / `denied` / `needs_setup` / `unknown` / `timeout` with an actionable hint.
- `setup` installs the broker if missing and may open macOS Privacy & Security. It never claims to grant permission.
- `verify` runs a bounded (≤2s, kill/reap) broker-based protected-path probe that performs both `read_dir` and a mutation-free `access(W_OK)` check under the broker identity. It deliberately does **not** launch `git` or probe `~/Documents` from the rotating runtime; real Git access is verified through the broker-routed `herdr_git` path.
- `doctor` always runs its Documents probe through the installed broker on macOS, including when invoked directly from a user shell that does not inherit LaunchAgent environment variables. If the broker is missing, it fails closed and points to permission setup; the rotating runtime is never selected as a fallback TCC client.
- `doctor` prints distinct `LAYER macos-permissions` and `LAYER tcc-broker-identity` lines. The latter reports identity mode, signing identifier/team when available, installed/candidate compatibility revisions, identity compatibility, and whether a future broker replacement would require reauthorization.

## Stable identity and broker upgrades

The broker wire protocol and the broker compatibility revision are separate contracts. Runtime releases may change freely while `BROKER_COMPAT_REVISION` stays unchanged. In that case the installed broker bytes are preserved even if the new runtime executable has different bytes.

A real broker implementation upgrade must bump the compatibility revision. Before replacing an existing broker, v0.4.2 verifies that the candidate satisfies the installed broker's stable designated requirement. A legacy ad-hoc broker has a cdhash-bound requirement, so it cannot be replaced transparently: the automatic upgrade is refused and reports `update_requires_reauthorization=true`. Moving such an installation to a certificate-based broker is an explicit one-time identity migration followed by one macOS permission grant.

The preferred long-lived signing identifier is `cc.agentforme.herdr.tcc-broker`. `scripts/sign-macos-tcc-broker.sh` supports either the existing optional Developer ID release credentials or an already-installed **persistent** local code-signing identity. The script never creates/rotates a local identity automatically. Developer ID remains optional hardening and is not a v0.4.2 release gate.

Current dogfood evidence on 2026-08-30 still shows the installed broker as ad-hoc signed. This change does not silently replace that working broker or reset TCC. It first stops ordinary runtime upgrades from changing the responsible client; a future intentional signed-broker migration is separately operator-visible.

## MCP mapping

Public contract remains epoch 2 / **18 tools**. `herdr_fs_*` and `herdr_git` map EPERM/EACCES and protected-path/broker timeouts to `macos_tcc_access_blocked`. Unrelated IO (`not_found`, `outside_managed_roots`, ordinary git timeouts) is not remapped.

## What this is not

- Not a claim that unsigned binaries are equivalent to Developer ID for every TCC prompt.
- Not a v0.4.2 requirement to obtain or configure a paid Developer ID in CI.
- Not a new MCP tool.
