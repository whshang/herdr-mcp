# v0.4.2 multimodal artifact ingress — 2026-08-29

## Scope decision

The original v0.4.2 plan froze the public epoch-2 MCP catalog at 18 tools and treated generated-image ingress as out of scope. On 2026-08-29 the release scope was explicitly expanded to close the missing ChatGPT image-generation → managed local project path before v0.4.2.

The implementation keeps the frozen public MCP contract unchanged. Generated artifacts use a transport-neutral ingress owned by the Rust runtime. Cloudflare R2 is the temporary relay. The browser extension has no generated-image transport responsibility and must not be added to this path.

The R2 bucket is provisioned together with the existing Cloudflare Worker deployment. It is not a permanent asset store: objects use randomized keys, short-lived access, bounded size, and automated expiry/deletion. There is no nineteenth MCP tool.

## Edge relay (this slice)

Worker routes, all private, never a public r2.dev domain:

| Method | Path | Auth |
| --- | --- | --- |
| `POST` | `/artifacts` | existing Edge MCP/OAuth bearer **or** `LINK_SHARED_SECRET` |
| `GET` | `/artifacts/:id` | one-time object capability **or** the same upload principal |
| `DELETE` | `/artifacts/:id` | same as GET |

Constraints enforced by `edge/cloudflare/src/artifact-relay.ts`:

- random 128-bit object IDs (`[a-f0-9]{32}`), never caller-chosen keys;
- PNG/JPEG/GIF/WebP MIME allowlist plus matching file magic;
- 8 MiB streaming byte ceiling;
- SHA-256 stored on the object;
- 15-minute expiry metadata; GET after expiry deletes the object;
- 10-minute cron sweep of leftover expired keys;
- capability shown once at upload; only its SHA-256 is stored.

Auth reuses `authenticateMcpRequest` (dev/static MCP bearer + OAuth JWT/Edge token) and the existing Link shared secret. No second long-lived Worker secret is introduced.

Provisioning: `edge/cloudflare/provision-r2.mjs` creates the wrangler `[[r2_buckets]]` name idempotently (`already exists` is success) **before** `wrangler deploy`. Production CI does this for `wrangler.prod.toml`. User/dev deploys do the same against `wrangler.user.toml` / `wrangler.toml`. Local `wrangler dev` uses Miniflare R2 and does not need a real bucket.

## Closed loop

1. `herdr_fs_image` reads PNG/JPEG/GIF/WebP under managed Git roots and returns native MCP image content to the Web AI.
2. Preferred ingress order: direct bytes/file reference when the client exposes one; otherwise a short-lived R2 object via `POST /artifacts`.
3. R2 relay objects are uploaded under randomized keys and exposed only through the Worker + object capability. The Worker and bucket are provisioned together.
4. Rust imports the relay with `herdr-mcp artifact import --url HTTPS_URL --path ABSOLUTE_MANAGED_PATH`. The object capability is read from `HERDR_ARTIFACT_CAPABILITY` (or an explicitly named environment variable), never from a CLI argument. Fetching is HTTPS-only, rejects URL credentials and non-public DNS/IP targets, disables automatic redirects, accepts only bounded same-origin redirects, pins the validated DNS result for the request, applies connect/request timeouts and an 8 MiB streaming ceiling, and validates MIME/file signature plus relay/expected SHA-256 before any filesystem mutation. It does not go through the browser extension.
5. Rust artifact admission caps file size and validates declared length, SHA-256, MIME, extension, and image file signature.
6. Commit reuses `fs_mutation::write_bytes`, which re-applies managed-root, read-only/write-root, busy-agent, explicit overwrite, dirty-file, secret-path, traversal, symlink-escape, and atomic-write protections.
7. The saved asset can be read back by `herdr_fs_image` for visual verification.

## Trust boundary

R2 is an ephemeral relay, not an authority and not a permanent asset store. Upload authorization is the existing Edge MCP/Link credential. Download/delete authorization is object-scoped and short-lived. The Rust runtime independently validates the fetched object before writing it into a managed project. Browser extension permissions, Native Messaging, and browser origins are outside this data path.

## Failure semantics

- multiple bindings or multiple roots: reject; never guess a repository;
- destination is not an absolute path inside a currently managed Git root, escapes through traversal/symlink resolution, or violates existing write-root policy: reject;
- unsupported MIME or bytes inconsistent with MIME magic: reject;
- incomplete, oversized, out-of-order, or digest-mismatched upload: reject;
- parent directory absent: reject through existing filesystem target validation;
- destination exists: require the existing explicit overwrite contract;
- destination is dirty: require the existing explicit dirty confirmation contract;
- project is busy: preserve the existing mutation busy gate;
- missing R2 binding or Cloudflare token without R2 write: fail closed; do not deploy a Worker that advertises a missing bucket;
- relay transfer failure: fail without filesystem mutation; object expiry/deletion bounds residual relay state.

## Targeted validation

Edge-focused checks for this slice:

- `edge/cloudflare/tests/artifact-relay.test.mjs` — auth, MIME/magic, size, random IDs, capability download, expiry/delete, no extension coupling;
- `edge/cloudflare/tests/provision-r2.test.mjs` — wrangler bucket parse + idempotent create;
- `edge/cloudflare/tests/payload.test.mjs` — bounded binary body read;
- `crates/herdr-mcp/src/artifact_import.rs` — HTTPS/credential/IP policy, same-origin redirect contract, image signature, digest and redacted evidence tests;
- `crates/herdr-mcp/src/cli.rs` — `artifact import` parsing and fail-closed argument tests;
- `tests/cloudflare-token.test.mjs` — generated long-lived deployment token includes `Workers R2 Storage Write` and verifies R2 bucket-list access;
- epoch 2 remains 18 public MCP tools.

The local Rust fetch/SSRF policy and managed-root write path are implemented and pass focused tests. Full v0.4.2 release gates and a real Cloudflare R2 deploy/import/read-back UAT remain required before calling the closed loop done. The deployment-token helper now requests the Cloudflare API permission-group **Workers R2 Storage Write** (some Cloudflare UI surfaces label the capability Workers R2 Storage:Edit) so Worker setup can create the private bucket before deploy.

> **Superseded/current policy note (2026-08-30):** this entry records the original generated-image scope decision. The shipped v0.4.2 policy generalizes the relay to a generic short-lived private artifact relay (conservative MIME allowlist plus `application/octet-stream`, strict magic for images, active-content MIME rejection) and adds the built-in shortest-safe-path routing ladder (managed local file → direct `herdr_fs_*`; safe signed HTTPS URL → direct `herdr-mcp artifact import --signed-url`; directly consumable MCP/Connector file reference → direct; otherwise private R2 cross-boundary relay).
