# Cross-device mutation lease visibility

Status: design proposal for #332 A-3. Baseline: `83176c7b846c38b6397c7007bc76bf5951539782`. This document does not authorize a runtime, Edge, contract, or database change. A-1 landed in #965; A-2 and [D-1](https://github.com/whshang/herdr-mcp/pull/963) remain separate work.

## Goal and present boundary

Before starting a write lane, an authorized caller can inspect fresh, read-only lease observations from the enrolled devices in its fleet. A reachable device reporting no leases is distinguishable from a device that could not be queried. The caller sees known writers even when another device is unavailable. No failure may be rendered as an empty fleet or as proof that no writer exists.

At the baseline, `herdr_mcp.orchestration.lease.list` reads the local `StateStore` only (`crates/herdr-mcp/src/mcp.rs:3168-3218`). Its active-row query filters expiry using the local clock and returns a `MutationLeaseRecord`, excluding the token and its digest (`crates/herdr-mcp/src/state_store/mutation_leases.rs:260-272,860-895`). A-1 obtains the attribution from the runtime's local configuration (`crates/herdr-mcp/src/mcp_http.rs:275-281`), not from a lease request. It is nullable configuration attribution, not proof that a device is online or that its state is current. The existing write fence is local and only checks root leases (`crates/herdr-mcp/src/state_store/mutation_leases.rs:897-921`); it does not enforce a fleet-wide single writer.

The enrolled-device directory resolves immutable device identities (`edge/cloudflare/src/device-directory.ts:362-397`), and the existing Edge route waits for an active Link (`edge/cloudflare/src/workstation-do.ts:792,1097`). Neither fact is evidence of a successful lease read. The in-memory S2 request ledger is process-local (`crates/herdr-mcp/src/state_store.rs:820-823,878`); it is not a cross-device lease authority.

## Proposed read path

1. Add an explicitly read-only fleet projection at the existing authenticated Edge/Runtime boundary. Resolve the eligible enrolled device set through the authoritative device directory, then route a bounded `lease.list` read to each immutable `device_id` using the existing device routing and grant checks. A local caller must use the same authenticated fleet boundary; it must not read another device's database, secrets, SSH profile, or hostname to infer identity.
2. Each device reads its own active lease store. Return only `device_id`, `project_root`, `lane_key`, `workspace_id`, `pane_id`, `branch`, `holder_id`, `lease_epoch`, and `expires_at`, together with the source device identity. Never return lease tokens, token digests, credentials, prompt content, or arbitrary database rows. A null A-1 `device_id` stays null and is labelled unattributed; the transport source must not silently replace it with an asserted owner.
3. Include per-device `status: available | unavailable`, source identity, observation time and freshness deadline. `available` requires a successful, authorized response for that exact device, including a valid empty list. Timeout, offline, denied, malformed, incompatible or missing response is `unavailable` with a bounded reason. Directory enumeration failure makes fleet completeness unavailable, not an empty device set.
4. Aggregate as `complete` only when directory enumeration and every eligible device read are successful and fresh. Otherwise return `partial` or `unavailable`, preserve any successfully observed writers, and identify unavailable devices. A cached result may be displayed only with its original observation time and explicit `stale` state; it cannot count towards `complete` or “no known writers”. Never refresh a timestamp merely by reading a cache.

The output is an observation, not an atomic distributed snapshot. Different devices can change leases while reads are in flight; local expiry is interpreted by the source device's clock. An `expires_at` value is not a global guarantee. UI and clients must not call `complete` a lock, a reservation, or proof that a subsequent mutation is safe. A-3 does not acquire, renew, release, override or replay a lease.

## Scope matching and dependencies

Absolute checkout paths and branch names are device-local. Do not equate two paths, hostnames, labels, bare pane IDs or branch names across machines. Until a separately approved repository/task/branch-family identity contract exists, return per-device claims and require an explicit, validated mapping before calling two claims overlapping. Missing or ambiguous identity yields `unknown_overlap`, not “no conflict”. The product acceptance criterion of mechanically rejecting a second overlapping cross-device writer requires a separate authoritative arbitration design; this read-only slice alone does not meet it.

A-2 owns `intent: read | write` semantics and compatibility. A-3 must not invent intent for rows written before A-2 or when a remote runtime cannot supply it: expose `intent: unknown`, with capability/version evidence. Do not hide an unknown-intent claim or treat it as read-only. A-3 may consume A-2's public read projection once that contract is agreed, but does not change local lease enforcement or make a read claim imply fleet ownership.

D-1 owns durable mutation request identity, delivery evidence and restart-safe replay. A fleet lease observation is neither an idempotency receipt nor evidence that a write was not delivered. `unavailable`, stale data, or a lost response never permits blind retry, a cross-transport fallback, or a new mutation. A-3 introduces no second request ledger, and must not weaken D-1's `pending`/`unknown` handling.

## Compatibility, failure and rollback

The preferred A-3 implementation is an on-demand read projection over existing local lease data, without persisting fleet snapshots or adding a database table. Keep `SCHEMA_VERSION = 16` (`crates/herdr-mcp/src/state_store.rs:67`). If a future implementation needs local metadata, use an independently reviewed forward-additive auxiliary field/table; old schema-16 readers must continue to read old columns, and rollback must not delete new or unknown data. No migration, version increment, installation, activation, or service restart is part of this design.

Mixed-version fleets are normal. Feature-detect the projection and per-device capability. An old runtime, missing `device_id`, malformed response, revoked authorization or unavailable Link must be represented explicitly; none implies an empty lease set. After rollback to an older runtime, local legacy behavior remains available, while the fleet projection reports that device as unsupported/unavailable rather than fabricating a fresh empty response. Preserve the A-1 epoch-change trigger (`crates/herdr-mcp/src/state_store/mutation_leases.rs:47-87`): an old writer advancing an epoch clears stale device attribution. Rollback does not grant cross-device exclusion or make unobserved writes safe.

## Acceptance criteria for implementation

- Given two enrolled devices and an authorized caller, a fresh list includes the second device's active write claim and its source, nullable owner attribution, scope fields and expiry. It contains no token or digest. A valid empty response is explicitly `available` with zero claims.
- Given one reachable writer and one offline, denied, malformed, incompatible or timed-out device, retain the writer and return `partial` plus the affected device's `unavailable` reason. Given directory failure, report fleet completeness `unavailable`; never report “no writer”. Test every failure class and ensure no write operation is triggered.
- Given a cached response past its deadline, expose its original timestamp as `stale`; it cannot make the aggregate complete. Test expiry and source-clock skew using a fake clock, and an update arriving during aggregation without claiming atomicity.
- Given old rows with null device attribution and older runtimes without A-3/A-2, preserve null/unknown and mark unsupported responses unavailable. Test current → old → current schema-16 rollback, including old-writer epoch advancement and preservation of unknown fields, with an actual prior binary where available.
- Given unrelated worktrees with matching names, do not merge identities; given an ambiguous repository mapping, report `unknown_overlap`. No positive conflict claim may depend solely on a hostname, path spelling or display label.
- Test access using authorized and unauthorized callers and enrolled/revoked devices. No secret, token digest, lease mutation or cross-device fallback may appear in results or logs. Existing local acquire/renew/release and A-2/D-1 behavior must regress green.
- Exercise the actual client entrypoint and default routing with at least two isolated enrolled test devices, one offline case, and a legacy runtime. Document observed timestamps and limitations; live production devices and destructive rollback are not prerequisites for ordinary CI.
