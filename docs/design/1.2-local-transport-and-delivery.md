### Reconnect detail (P1 companion)

- WebSocket ping every **30s** (`daemon.rs:69` `DAEMON_TRANSPORT_PING_MS`); application heartbeat every **300s** (`daemon.rs:73`), max silence **90s** (`transport.rs:29-31`, `heartbeat.rs:15-31`) — heartbeat 300s > silence 90s guarantees a silence-induced close even on a healthy link. Node used a matching 30s heartbeat (`src/link/client.ts:93-180`). *[Verified at review time; #958 restored the heartbeat to 30s — see S6 landing notes.]*
- Backoff base 1000ms / max 60000ms / factor 2 / full jitter (`backoff.rs:30-43`); `max_reconnect_attempts = None` — unlimited, one reconnect per generation (`lifecycle.rs:158-166`,`:289-303`).
- During a reconnect window: link-side requests queue up to `linkReconnectGraceMs = 15000` then `offline` (`runner.rs:213-235`); Edge settles every in-flight request immediately — reads get `not_delivered`, writes get `delivery_uncertain` (`workstation-do.ts:1893-1926`, `pending.ts:429-446`, `errors.ts:264`). `workstation_offline` is returned only when no active link exists after failure or grace expiry (`workstation-do.ts:127-139`,`:1087-1105`), not per attempt — there is no "give up" since attempts are unbounded.
- 2297 reconnects ≈ real link re-establishments (counted only after a previous disconnect completes a new hello, `workstation-do.ts:1630-1658`). Plausible code-level causes in descending order: duplicate/competing Link processes for the same workstation (4409 superseded close, `workstation-do.ts:1618-1626` → `policy.rs:74-79`), the 300s-vs-90s heartbeat/silence mismatch, `ProlongedOffline` 300s process recycle (`io_loop.rs:474-489`), watchdog restarts (`bin/watchdog.sh:34-37`), Wi-Fi/NAT. Exact attribution needs runtime telemetry (S0).

### Diagnostics detail (P9 companion)

Present: runtime probe (TCP 8772 health only), herdr socket reachability, CLI/server versions, update channel, TCC, `link status` JSON with `production_owner`, agents[] plist/loaded flags, `transport` evidence block, `runtime_generation` (`status.rs`, `ownership.rs:538-700`,`:737-751`). Missing: live link state, reconnect count/last-reconnect duration, per-call route evidence, link process PID/uptime/restarts, whitelisted process/port/config snapshot.

### Local baseline measurement

`herdr workspace list` via local socket, 10 runs: 14,11,10,10,9,9,10,10,9,10 ms → median 10ms, P90 11ms. Relay-path timing on the same device could not be measured read-only without touching other workspaces; code evidence above stands in for it.

## 2. Design deltas from the original proposal

- **P6 scope shrinks.** Because all three parsers already accept objects, S1 becomes *schema + error hygiene only*: a v6 contract descriptor widening `herdr_call.params` to a union plus redacting position info in `invalid_params_json`. The Edge side needs only the companion constant in `contracts/runtime.ts` (`COMPATIBLE_RUNTIME_CONTRACTS`), which is a stop-condition file under the #775 boundary — flagged for the coordinator, not implemented here.
- **P5 reinterpreted.** `repair_budget_exhausted` is already per-lane and advisory (`prompt.rs:1956-1972`); S4's ask becomes per-receipt terminal states plus an archive view, not a new budget.
- **P3 split.** The pane-parent push path already works (`maybe_notify_parent`); S3 only needs the WebChat/browser-parent path — an event the extension can poll precisely by `receipt_id`/`task_id`, not a new push transport.
- **Reconnect.** The runtime-side fix for P1's 2297 reconnects is not keepalive tuning (heartbeat 300s already exceeds the 90s silence budget — fixing that is a separate correctness bug worth its own slice note in S6), but **telemetry** (S0) plus making writes fail `not_delivered` instead of queuing during reconnect windows — already the Edge behavior for settled requests, needs the link-side queue to distinguish reads from writes (`runner.rs:213-235` queues all).

## 3. Global principles

1. Governance above transport: lease, audit, delivery receipt, and security routing checks live once, above the transport choice. Local and relay paths share identical governance code.
2. Every response carries `transport: "local" | "relay"` and `timing_ms` (`queue`, `connect`, `execute`; never params content).
3. Write fallback: only when zero bytes may have been written (e.g. connect failure) may a call fall back to the other transport; once possibly-written, return a result-pending receipt with `request_id` — never auto-retry. Error style follows #935: `not_delivered`, `fallback_allowed`.
4. Any single synchronous server-side deadline must end at least 5s before the gateway deadline; on expiry return `still_running` + receipt, never let the gateway cut first.

## 4. Slices

### S0 — Observability baseline (small)

Solves: makes P1/P2 numbers product-verifiable.

- Add `transport`, `timing_ms{queue,connect,execute}`, `request_id` to every tool result envelope and to structured logs. `request_id` already exists at Edge (`pending.ts:214-218`); propagate it through the wire frame into the runtime response.
- Link-level counters in the daemon: `reconnect_count`, `last_reconnect_duration_ms`, `connected_since_ms`, current `transport_state` — the fields Edge already tracks (`state.ts:274-277`) but nothing local exposes. Surface in `status`/`doctor`.
- Security: no params/secret content in `timing_ms` or counters.
- Tests: fields present with stable types across a local and a forwarded call; counters monotonic across an injected reconnect.
- Effort: ~2 files Rust (result envelope, status), wire field passthrough. Depends on nothing.

### S1 — `params` accepts object (this round)

Solves: P6.

- New `contracts/runtime-exec-v6.json` descriptor: base epoch2 + shape on `herdr_call` — `params` becomes `anyOf:[{"type":"object"},{"type":"string"}]`, description recommends the object form. Keep v5 pinned as the rollback baseline (`PREVIOUS_PUBLIC_CONTRACT_*` = v5, `LEGACY_EPOCH2` retained).
- `crates/herdr-mcp/src/contract.rs`: generalize `shaped_tool_catalog` to apply a `shapes[]` array (v6 shapes two tools: `herdr_exec` unchanged + `herdr_call` params). Epoch constant → 6, `DESCRIPTOR_NAME` → `runtime-exec-v6`; previous-descriptor accessor → v5.
- `mcp.rs:1348-1353`: `invalid_params_json` message — keep position (serde already gives line/col) but strip any echoed source text; add explicit `field: "params"`. Non-object non-string params → `invalid_params` already correct at `:1358`.
- Constants sweep: `link/daemon.rs` `PUBLIC_CONTRACT_EPOCH/HASH`, `src/link/daemon.ts:11-19`, `contracts/runtime-parity.json`, `local_agent_cli.rs` contract echo, `worker_bootstrap.rs` epoch preflights, tests pinning epoch 5/hash.
- Docs: `assets/herdr-mcp-SKILL.md:28`, `assets/herdr/skills/workstation-control/SKILL.md:18`, `skill.rs:710` test string — object preferred, string still accepted verbatim.
- Edge companion (stop-condition boundary): `edge/cloudflare/src/contracts/runtime.ts` needs `RUNTIME_EXECUTION_CONTRACT` → epoch 6 entry and v5 moved into `COMPATIBLE_RUNTIME_CONTRACTS`; `epoch8.ts`/`epoch3.ts` public catalogs optionally advertise the union — **#775-adjacent; documented for the coordinator, not changed in PR-2**. Deploy order: Edge constant must ship before/with the runtime generation that advertises v6, or the workstation hello is refused (`isCompatibleRuntimeContract`, `runtime.ts:50-54`).
- ChatGPT catalog risk: docs/i18n warns free-object/`additionalProperties` shapes have made whole catalogs rejected; `anyOf` with a plain `{"type":"object"}` branch is the risk-mitigated form but needs a real ChatGPT UAT before release.
- Safety: `herdr_prompt` already bypasses params encoding (`server.ts:2939`) — unchanged. No security surface weakened: this only widens accepted wire shape; all downstream method validation is unchanged.
- Tests (per coordinator): object form delivers `""`, `\n`, tabs, CJK, emoji, ≥64KB verbatim with byte-compare; legacy string form regresses green; malformed string → `invalid_params_json` with line/col and no echoed body; non-object non-string → `invalid_params`; existing suite incl. #944/#945 green.
- Effort: ~6 files + 1 new contract + tests. Blocks nothing; S0 parallel-safe.

### S2 — Write idempotency and result query (medium)

Solves: P2's "unknown outcome", duplicate submissions.

- Every write method accepts optional `client_request_id` (caller-generated, ≤256 chars, same hygiene rules as `idempotency_key` at `mcp-handler.ts:1434-1442`).
- Runtime keeps a bounded, TTL'd operation ledger: `client_request_id → {state, result digest, ts}`. Resubmit returns the recorded outcome without re-executing. The existing `state_store.rs` operation ledger (`reserve_operation`/`put_operation_ledger`, `:1089-1705`) is the substrate — in-memory with cap+TTL per spec; if durable cross-restart semantics are required and that means a `state.db` schema change, stop and document only.
- New read-only `request.status` (naming per existing style — candidate `herdr_mcp.request.status` local method): lookup by `request_id` or `client_request_id` → `pending|applied|rejected|not_delivered|unknown`.
- `request_timeout` responses carry `request_id` + a hint pointing at `request.status`.
- Security: digest-only storage (no prompt text/file bodies); queries inherit the original operation's permission scope.
- Tests: duplicate submit executes once; simulated timeout resolves to `applied` via `request.status`; connect failure → `not_delivered`; ledger evicts at cap, never unbounded.
- Effort: medium; state_store + prompt/exec write paths. After S0 (needs `request_id` propagation) is preferred but not required — the Edge `request_id` exists today.

### S3 — Long ops async + parent wake (medium–large)

Solves: P3, P2's wait-collision.

- `dispatch` / `agent prompt --wait` return `receipt_id` immediately; result via event or bounded wait. Wait methods (`herdr_since`, inbox `wait_ms`) cap below gateway deadline; expiry returns `still_running`, never `request_timeout`.
- Fix `parent_session_ref` end-to-end: record at dispatch (already done), carry to child task, and emit a directed event to the parent session on `worker_done`. Browser/WebChat parents: no new push transport — emit the event into the inbox with a `receipt_id` so the extension's existing poll (`background.js:5380-5455`) can match it precisely instead of scanning; pane parents keep `maybe_notify_parent`.
- `chat_semantic`-class Edge-dependent calls past deadline: return explicit degradation reason (`edge_proxy_unavailable` already exists at `semantic.rs:2073`), never a vague "unavailable".
- Tests: `worker_done` wakes a waiting parent in <1s locally; `wait_ms` expiry → `still_running` not `request_timeout`; `parent_session_ref` non-null end-to-end; parentless tasks unchanged.
- Effort: prompt.rs inbox/notification + mcp_http event surface. Depends on S2's receipt vocabulary.

### S4 — Spawn atomicity + inbox governance (medium)

Solves: P4, P5.

- Server-side `spawn` = create workspace → start agent → wait ready → deliver, returning one `receipt_id`. "Ready" needs a defined criterion: candidate = `interactive_ready` plus a post-start settle delay or agent handshake; document whichever ships. Readiness timeout → `agent_not_ready` with `not_delivered:true` — never `delivery_uncertain`.
- `delivery_uncertain` reserved for genuinely-maybe-delivered cases only, carrying a confirm hint (e.g. pane echo cursor).
- Repair redispatch: per-receipt budget → terminal state on exhaustion (today the signal is advisory per-lane, `prompt.rs:1956-1972`).
- Inbox filters add `receipt_id`, `status`, `since`; terminal records past retention (configurable) move to a queryable archive, not delete; read-only stats view.
- Tests: slow-start agent doesn't get early delivery; readiness timeout → `not_delivered`; `receipt_id` wait hits only its task; archived records leave default queries but stay queryable.
- Effort: prompt.rs spawn chain + inbox. After S3 (receipt vocabulary shared).

### S5 — Model alias validation + run bounds (medium)

Solves: P7, P8.

- `agent start` with a model alias: validate against a per-agent obtainable list → `model_alias_unknown` + available list, no silent fallback. Agents with no obtainable list (everything but pi today, `capability_scan.rs:272-275`) return `validated:false`.
- Post-start early-exit detection (configurable ~10s): if the agent exited, return `agent_start_failed` + sanitized last pane lines.
- Optional `max_runtime_ms`, `stall_after_ms` (exists): expiry emits `agent_budget_exceeded`/`agent_stalled` events to the parent — notify only by default; `on_budget:"interrupt"` sends the interrupt explicitly.
- Tests: unknown alias rejected; dead-on-start alias → `agent_start_failed`; expiry notifies without terminating; no caps → behavior unchanged.
- Effort: spawn/start path + probe inventory. Independent of S1–S4 ordering; listed after them only for review-bandwidth reasons.

### S6 — Same-machine direct transport (large; folds into #768 Phase 2)

Solves: P1 (latency + reconnect surface).

- Trigger: herdr-mcp runs locally (stdio or local HTTP) **and** target device == this machine. Skip Edge; use the local herdr socket or Core backend.
- Same-machine predicate — all must hold, else relay with a stated reason:
  1. request `device_id` == this runtime's `device_id` (never hostname/display name — `daemon.rs` device identity);
  2. local socket passes the #941 peer UID check (`verify_hc_peer_uid`);
  3. if Core backend selected, #943/#944/#945 target-consistency checks pass (`admit_public_tool`, `with_negotiated_session_budget`, `expected_core_target`).
- Governance identical on both transports — lease/audit/receipt records must be cross-comparable; write fallback per global principle 3.
- Cross-machine behavior and remote coordinators unchanged.
- #768 Phase 2 relationship: S6 is the local special case of Phase 2's "route tools through Core" — same backend-selection logic (`public_tool_route_for_selection`), with the additional same-machine predicate gating a *local* admission rather than a Core socket admission. Conflicts with the Phase 2 design draft (`~/herdr-wt-archive/design-768/768-phase2-design.md`; a same-named copy may also sit under `~/.herdr/worktrees/herdr-mcp/design-768-phase2-20261116` — authoritative location per coordinator): none found at the routing layer — Phase 2 slices 4–6 remain refusal-first and are unaffected; S6 only changes *which local client* a same-machine call uses, not Core authorization.
- Reconnect companion (P1's 2297): on the runtime side — fix the 300s heartbeat vs 90s silence mismatch (either heartbeat ≤ silence/3 or explicit app-level ping alignment; `daemon.rs:73`, `transport.rs:29-31`); queue reads briefly during reconnect windows (already, `runner.rs:213-235`); make **writes** return `not_delivered` immediately in the window instead of queuing — today link queues all requests for the 15s grace.
- Tests: positive same-machine match; each predicate's counterexample; governance records identical across both transports; local-write fallback rules; cross-machine regression.
- Effort: large; waits for coordinator confirmation after #768 Phase 2.


**S6 landing notes (heartbeat companion, #958 + follow-up):**

- **Shipped.** `DAEMON_HEARTBEAT_MS` / `LINK_DEFAULT_HEARTBEAT_MS` 300s → 30s
  (#958), restoring the Node default (`src/link/client.ts:79`) and the design's
  `heartbeat ≤ silence/3` remedy against the 90s silence budget.
- **Attribution is bounded, not proven.** The mismatch is *a plausible
  contributing cause* of P1's 2297 reconnects — it guarantees a silence-recycle
  every 90s window on an otherwise healthy link — but exact attribution still
  needs S0 telemetry (duplicate/competing Links, `ProlongedOffline` recycle,
  watchdog restarts, and Wi-Fi/NAT remain on the list in §2). This is a
  correctness fix that happens to remove one suspect, not the confirmed root
  cause of 2297.
- **Edge-side cost of the faster heartbeat.** Edge has no
  `setWebSocketAutoResponse`/`WebSocketRequestResponsePair`, so every
  application heartbeat is a real Durable Object message
  (`workstation-do.ts:1697-1730`); with heartbeat = 30s =
  `EDGE_STATUS_REPLY_INTERVAL_MS` (`limits.ts:72`), **every** heartbeat now
  satisfies the reply interval → one inbound status frame plus one
  `ws.heartbeat` log line every 30s per workstation (10× the 300s cadence).
  `HEARTBEAT_PERSIST_THROTTLE_MS = 300s` (`limits.ts:65`) throttles only
  `state.storage.put`, not DO message/reply/log volume. Accepted: it matches
  the cadence the production Node Link has always run; reverting to 300s to
  save DO traffic would re-break the silence invariant.
- **Guard.** `heartbeat < silence` (and the stricter `heartbeat*3 ≤ silence`)
  is now pinned by tests in `link/transport.rs`, `link/daemon.rs` and
  `link/heartbeat.rs`, including the 300s+90s → recycle counterexample.
