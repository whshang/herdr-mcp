# Herdr-MCP 1.0 Phase 1 — Fleet Control Kernel

> Status: implementation specification
> Branch: `feat/v1.0-control-kernel-phase1-20260904`
> Scope: Work Chain identity, transferable exclusive Planner Lease, Execution Lane identity, trusted controller provenance, and authoritative Edge persistence.

## Goal

Deliver one minimal vertical slice at the trusted credential-principal boundary:

```text
authenticated operator credential principal
  -> herdr_call private method
  -> create/inspect work chain
  -> acquire exclusive planner lease
  -> create explicit execution lane
  -> renew/release/take over lease
  -> stale generation is fenced
  -> authoritative compact state survives Durable Object reconstruction
```

Phase 1 does not implement full Work Memory replication, checkpoint mutation, a task-graph scheduler, automatic Agent dispatch, WebChat adapters, Extension DOM work, a new browser runtime, a plugin ABI, a new database, or a new daemon.

This slice follows the settled 1.0 planning decisions at `47a6f80`: D1-C hybrid fleet checkpoint/local detailed evidence, D2-A transferable exclusive planner lease, D3-A public Edge epoch 3 / 19 actions plus workstation Runtime Execution epoch 2 / 18 tools, D4-A API/CLI-first browser boundary, and D5 Browser Control / External Conversation Dispatch remaining outside Phase 1.

## Authority map

`DEVICE_REGISTRY_DO` (`devices-v1`) is the single authoritative owner of compact fleet coordination state. It already owns enrolled device authorization, so lane creation and device validity checks share one Durable Object transaction boundary.

The DO stores three additive v1 key families:

- `fleet:chain:v1:*` — Work Chain record and current planner lease.
- `fleet:lane:v1:*` — Execution Lane metadata.
- `fleet:lane-reservation:v1:*` — hashed canonical `repo_id + branch_ref` reservation for non-terminal lanes.
- `fleet:idempotency:v1:*` — principal-scoped mutation replay records.

Existing `device:*`, pairing, credential, workstation, OAuth, and workstation-local StateStore records remain unchanged. No migration rewrites or clears existing data. Workstation StateStore continues to own detailed local execution evidence; Phase 1 adds no local fleet-state table.

## Trusted controller provenance

Fleet mutation principal is derived by the Edge request path after MCP authentication. Request payloads cannot provide or override it.

- Phase 1 permits the already-authenticated dev/static operator identities only: `operator:dev_bearer` and `operator:static_bearer`.
- OAuth JWT / Edge tokens, including legacy tokens and newly approved ordinary MCP Connectors, remain fail-closed for Fleet Control in alpha.1.
- `params.principal`, `client_id`, `holder_principal`, `can_control_fleet`, `can_force_takeover`, or similar self-declared authority fields are rejected as unknown Fleet Control parameters.
- The internal Device Registry request receives a canonical authority object only from the Worker request path. The corresponding DO URL is not a public Worker route.

Phase 1 does not modify OAuth scope, approval UI, or the Connector grant schema. Ordinary `mcp` access and `can_approve_connectors` do not imply Fleet Control. An explicit owner-mediated OAuth Fleet Control grant/revoke contract is a separate security gate and remains deferred; until it exists, OAuth Fleet Control mutation stays unavailable.

Alpha.1 principal identity is intentionally credential-granular. Every caller using the same dev bearer is `operator:dev_bearer`; every caller using the same static bearer is `operator:static_bearer`. Separate conversations, processes, or future WebChat controllers that share one credential are therefore the same lease principal. Alpha.1 does **not** claim provider/conversation-level controller isolation or arbitrary multi-controller exclusivity. A stable per-controller authenticated principal plus owner-mediated grant/revoke and multi-controller UAT is a later security gate; request-supplied controller/conversation identifiers remain untrusted and rejected.

## Work Chain model

```text
schema_version = 1
work_chain_id = globally random wc_* id
revision = monotonic CAS revision, starts at 1
status = active | completed | cancelled
creator_principal = trusted Edge-derived principal
checkpoint_schema_version = 1
checkpoint_revision = 0 in Phase 1
portable_evidence_refs = [] in Alpha.1
planner_lease_generation = monotonic fencing generation
planner_lease = current lease or null
last_planner_takeover = latest forced-takeover evidence snapshot or null
created_at_ms / updated_at_ms
```

Phase 1 initializes the checkpoint version boundary but does not expose checkpoint mutation. `work_chain.create` does not accept portable evidence references in Alpha.1; the stored field is initialized to an empty array. Missing/empty ref fields from the pre-fix Alpha.1 record shape normalize to the same empty representation. A structured/opaque PortableEvidenceRef contract is deferred to alpha.2 instead of accepting paths, URLs, or free text into fleet authority.

Work Chain is provider- and repository-neutral in alpha.1. It does not own `title`, `repo_id`, `root_branch`, provider identity, or browser/conversation identity. Repository/base/branch ownership belongs to individual Execution Lanes, so one chain can later coordinate lanes from more than one repository.

## Planner Lease model and state transitions

A lease contains `holder_principal`, `generation`, `acquired_at_ms`, `renewed_at_ms`, and `expires_at_ms`.

Mutating transitions require `idempotency_key` and `expected_chain_revision`. Renew/release/lane mutations also require `expected_lease_generation`.

- `acquire`: succeeds only when no unexpired lease exists. First generation is 1. Acquiring after expiry is an atomic reclaim and increments generation.
- `renew`: requires current holder and generation; generation stays unchanged.
- `release`: requires current holder and generation; clears the active lease while preserving the monotonic generation counter.
- `takeover`: is the privileged forced-takeover path. It requires an unexpired lease held by another principal, current chain revision/generation, a bounded non-empty `reason` (max 512 characters), and trusted `can_force_takeover` authority derived outside request params. It increments generation exactly once and persists previous/new holder, previous/new generation, reason, and timestamp as `last_planner_takeover`.
- an expired or released lease is reclaimed through ordinary `acquire`; forced `takeover` does not substitute for expiry reclaim.
- any stale generation, wrong holder, or stale chain revision fails closed.

Default lease TTL is 5 minutes; accepted TTL range is 30 seconds through 30 minutes.

`last_planner_takeover` is only the most recent takeover evidence snapshot. A later forced takeover replaces it. Alpha.1 does not provide an append-only takeover audit ledger; historical audit evidence, if required, needs a separately bounded append-oriented design in a later phase.

## Execution Lane model

```text
schema_version = 1
lane_id = globally random lane_* id
work_chain_id
lane_generation = monotonic, starts at 1
device_id = explicit enrolled device; never inferred
repo_id = normalized remote identity, e.g. github.com/whshang/herdr-mcp
base_commit = complete Git object id (40-char SHA-1 or 64-char SHA-256)
branch_ref
file_scope = bounded repo-relative path prefixes only; no glob/shell syntax
runtime_scope = bounded `runtime:<id>` / `service:<id>` identifiers
owner_principal = trusted lease holder
agent_ref = optional descriptive ref, never authorization identity
status = planned | active | blocked | completed | cancelled
validation_summary
validation_refs = [] in Alpha.1
created_at_ms / updated_at_ms
```

Lane create/update requires the current valid planner lease and matching chain revision/generation. New lanes reject unknown, suspended, or revoked devices. `repo_id` is a canonical remote identity with non-empty non-dot path segments. `base_commit` must be a complete 40-character SHA-1 or 64-character SHA-256 object id; abbreviated SHA is rejected. `branch_ref` is canonicalized to the short branch form (`refs/heads/main` becomes `main`) and applies the portable `git check-ref-format --branch` safety subset: no whitespace/control characters, `~ ^ : ? * [ \\`, double slash, `..`, `@{`, leading dot/dash, trailing dot/slash, or `.lock` component. The same canonical `repo_id + branch_ref` cannot be held by two non-terminal lanes.

Alpha.1 stores scopes as bounded metadata with deliberately narrow syntax. `file_scope` contains repo-relative path prefixes only: no URL scheme, absolute/local-home form, backslash, empty/`.`/`..` segment, glob syntax, control characters, or shell metacharacters. `runtime_scope` accepts only semantic `runtime:<id>` or `service:<id>` identifiers using ASCII alphanumeric/`._-` payloads. Alpha.1 does not define a glob DSL or scope-overlap scheduler; the concrete reservation boundary remains canonical `repo_id + branch_ref`.

`validation_refs` is not an Alpha.1 mutation input and is stored as an empty array; missing/empty pre-fix fields normalize to the same representation. Structured validation/evidence reference inputs remain deferred with the evidence registry contract.

Minimal lane transition matrix:

```text
planned -> planned | active | cancelled
active  -> active | blocked | completed | cancelled
blocked -> blocked | active | completed | cancelled
completed -> completed
cancelled -> cancelled
```

Every accepted lane update increments `lane_generation`. Reassignment is explicit: the current planner must pass `reassign: true`; an optional new `device_id` must resolve to an active enrolled device; ownership moves to the authenticated current planner and the new generation fences the old owner. Terminal lanes cannot be reassigned or reactivated. Entering a terminal state releases the `repo_id + branch_ref` reservation for a later lane.

## Private method contract

No public tool is added. Fleet Control is exposed through the existing public `herdr_call` gateway and is handled Edge-local; the request is not forwarded to a workstation.

Typed private methods:

- `herdr_mcp.work_chain.create`
- `herdr_mcp.work_chain.inspect`
- `herdr_mcp.planner_lease.acquire`
- `herdr_mcp.planner_lease.inspect`
- `herdr_mcp.planner_lease.renew`
- `herdr_mcp.planner_lease.release`
- `herdr_mcp.planner_lease.takeover`
- `herdr_mcp.execution_lane.create`
- `herdr_mcp.execution_lane.inspect`
- `herdr_mcp.execution_lane.update`

`herdr_methods(query=...)` returns Edge-local schemas for queries matching `work_chain`, `planner_lease`, `execution_lane`, or `fleet`. Other discovery calls continue to the workstation runtime.

Mutation schemas require:

| Method | Required mutation fields |
| --- | --- |
| work_chain.create | `idempotency_key`; no portable evidence-ref input in Alpha.1 |
| planner_lease.acquire | `work_chain_id`, `expected_chain_revision`, `idempotency_key` |
| planner_lease.renew | above + `expected_lease_generation` |
| planner_lease.release | above + `expected_lease_generation` |
| planner_lease.takeover | above + `expected_lease_generation`, `reason` |
| execution_lane.create | chain/revision/lease generation/idempotency + `device_id`, `repo_id`, full `base_commit`, `branch_ref`; optional narrow `file_scope` / `runtime_scope`, no `validation_refs` |
| execution_lane.update | chain/revision/lease generation/idempotency + `lane_id`, `expected_lane_generation`; optional `reassign`, `device_id`; no `validation_refs` |

Inspect methods are read-only and require only the stable object id.

A public `device` routing selector is rejected on Fleet Control methods because the authority is fleet-scoped and must not be guessed or routed to one workstation.

## Idempotency and atomicity

All mutations run inside `DurableObjectStorage.transaction()`.

The idempotency storage key hashes `trusted principal + idempotency_key`. Successful committed mutations store method, canonical request hash, a hash of the trusted principal for quota accounting, result, creation timestamp, and `expires_at_ms`.

- same principal + same key + same payload returns the original result with `replayed: true`.
- same principal + same key + different method/payload returns `idempotency_key_payload_mismatch`.
- different principals may independently reuse the same textual key.
- records expire after 24 hours; an expired key is treated as a fresh mutation.
- storage remains capped at 512 live records without evicting any unexpired replay guarantee. Alpha.1 splits that bound into a 256-record admission quota (`work_chain.create`, `execution_lane.create`) and a 256-record existing-resource control reserve (lease acquire/renew/release/takeover and lane update). Because Alpha.1 has exactly two trusted credential principals, each credential may consume at most 128 live control records; one credential therefore cannot consume the other credential's control reserve. A later per-controller principal model must revisit this partition instead of assuming an arbitrary number of controllers behind these two credential classes.
- quota checks happen after same-key replay/mismatch resolution and lazy expiry cleanup. Admission saturation rejects new chain/lane admission while existing leases and lanes retain their control reserve for renew, release, privileged takeover, reassign/fencing, and terminal updates. `idempotency_capacity_exceeded` reports only `quota_scope`, current `live_records`, `limit`, and bounded `recover_after_ms`; it does not expose another principal's keys or request payloads.
- expired/invalid records are removed lazily inside the same DO transaction. There is no timer, alarm, daemon, polling loop, or second state service.
- validation/state-conflict errors are not cached. Outer Edge availability/uncertain failures are also not written to the authority idempotency ledger.
- a successful retry cannot create a second chain, duplicate takeover, or duplicate lane.

## Controlled errors

The kernel uses bounded codes including:

`controller_principal_unavailable`, `invalid_params`, `idempotency_key_required`, `idempotency_key_payload_mismatch`, `idempotency_capacity_exceeded`, `work_chain_not_found`, `chain_revision_conflict`, `planner_lease_conflict`, `planner_lease_holder_mismatch`, `planner_lease_missing_or_expired`, `planner_lease_takeover_forbidden`, `planner_lease_takeover_not_needed`, `takeover_reason_required`, `stale_lease_generation`, `device_id_required`, `device_not_found`, `device_not_authorized`, `invalid_lane_identity`, `branch_lane_conflict`, `execution_lane_not_found`, `execution_lane_owner_mismatch`, `execution_lane_reassign_required`, `execution_lane_terminal`, `lane_generation_conflict`, `lane_transition_invalid`, `fleet_control_authorization_required`, `fleet_control_unsupported`, and `fleet_control_unavailable`.

Internal exception strings are not persisted as fleet status or returned as state fields.

## Public contract compatibility

Phase 1 does not modify `contracts/public.ts`, epoch contract fixtures, tool definitions, OAuth scope strings, or workstation runtime method registries.

The live 0.4.5 workstation runtime observed at the start of this work still reports runtime contract epoch 2 / 18 tools. The current `origin/main` Edge source already exposes device-aware public `EPOCH3_CONTRACT` / 19 tools (`herdr_devices` added at Edge while workstation execution remains epoch 2). Therefore the Phase 1 compatibility gate is: **the public contract must be byte-for-byte/fixture-equivalent to its current main baseline**. Phase 1 must not add another public tool or bump the Edge contract epoch.

## Validation

Targeted tests cover:

- chain create/inspect and revision CAS;
- acquire conflict, renew, release, expiry reclaim, ordinary-controller takeover denial, owner/operator-authorized forced takeover, takeover audit, and generation fencing;
- idempotent replay, payload mismatch, principal isolation, 24-hour expiry, admission/control quota separation, per-credential control reserve, lazy recovery, and same-transaction mutation/idempotency evidence;
- successful chain/lane records remain readable after DO reconstruction; missing/empty pre-fix ref fields normalize safely and caller-supplied evidence/validation refs are rejected in Alpha.1;
- explicit device/repo/branch/full-object-id lane identity and narrow file/runtime scope syntax;
- same repo across different devices without path identity;
- same branch conflict;
- lane transition matrix, explicit reassign, lane-generation fencing, terminal non-reactivation, and reservation release;
- revoked/unknown/missing device rejection;
- DO reconstruction persistence and legacy device readability;
- private method discovery through `herdr_methods`;
- public `/mcp -> herdr_call -> Edge authority -> Device Registry DO` routing with no workstation forward;
- rejection of caller-supplied principal/client/capability fields and absence of a public Device Registry internal-route bypass;
- legacy and ordinary OAuth tokens fail closed for Fleet Control; ordinary Connector approval does not gain a Fleet Control field;
- unchanged public Edge epoch 3 / 19-action contract and unchanged workstation Runtime Execution epoch 2 / 18-tool contract.

Repository gates remain the existing Rust, Node, and Edge build/test commands. Phase 1 does not require runtime install/restart/link cutover.

## Explicitly deferred from alpha.1

- Work Chain `title`, repository/root-branch ownership, provider identity, and browser/conversation identity.
- compact checkpoint mutation / `work_chain.checkpoint`; alpha.1 keeps only the revision/evidence foundation required by D1-C.
- workstation SQLite v6 fleet/checkpoint cache; there is no alpha.1 runtime caller that needs it.
- full file-scope/runtime-scope overlap scheduling; alpha.1 stores scopes and reserves canonical repo+branch ownership only.
- an OAuth Fleet Control capability grant/revoke UI, scope, or grant contract. Until an explicit owner-mediated security surface exists, OAuth Fleet Control mutation remains fail-closed.
- stable per-controller authenticated principal identity, owner-mediated grant/revoke, and arbitrary multi-controller lease UAT. Alpha.1 exclusivity is only between trusted credential principals.
- structured PortableEvidenceRef / validation-ref mutation inputs and any append-oriented takeover audit ledger. Alpha.1 stores empty ref arrays and only the latest takeover evidence snapshot.
- automatic Agent dispatch, task graphs, execution wake/settlement, browser endpoints, WebChat/provider adapters, ChatGPT Project/Conversation identity, Extension DOM work, GitLab consumer policy, or external conversation dispatch.

## Phase 2 boundary

Alpha.2 may add compact checkpoint mutation/task-graph semantics, local StateStore checkpoint cache when there is a real consumer, execution dispatch/wake transitions, structured portable evidence references, bounded historical audit evidence, and a separately reviewed stable per-controller principal/grant model with multi-controller UAT. Those capabilities must reuse this authority/lease/lane identity rather than introduce a second coordination store.
