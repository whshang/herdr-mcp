### 1.0 cross-cutting — Herdr 0.9.1 native multi-machine/recovery boundary

- Herdr 0.9.1 native `herdr --machine <label-or-id> <command>` is the preferred saved-machine maintenance/UAT/recovery path for supported API command families; Edge `device_id` remains the Web-AI routing identity. 1.0 does **not** add a second `machine` selector to the 18 Runtime tools and does not infer equivalence between the two namespaces.
- `herdr_inspect` keeps historical `herdr_version` as the running server version and adds explicit `herdr_server_version` plus `herdr_native`: installed CLI version, feature-detected machine-forwarding support, bounded saved-machine inventory, client/server version state, and safe-handoff blocking evidence. This closes the silent-wrongness case where CLI 0.9.1 is installed while a compatible 0.9.0 server is still preserving live panes.
- `version_state=server_restart_pending` is diagnostic only. It must not stop/restart Herdr or close panes automatically. `handoff_blocked_reason=legacy_sender_pane_limit` means the older sender still exceeds its first-upgrade 64-pane handoff limit; existing user/other-task panes are preserved until a safe convergence window exists.
- Recovery transport is fail-closed: Edge stays primary; native `--machine` may be used after `delivery_state=not_delivered` or live proof that the earlier mutation was not applied, while the target Herdr server is reachable; raw SSH is the final bootstrap/recovery path when the server/forwarder itself is unavailable. Generic transport failure, uncertain/delivered state, or missing delivery evidence never authorizes cross-transport replay.
- Acceptance before GA: focused Rust regression must distinguish CLI-new/server-old, older CLI capability=false, unavailable CLI capability=unknown, and preserve the cross-transport retry fence; public Runtime tool count/hash stays unchanged; EN/zh-CN multi-machine docs and remote-planner Skill remain aligned. Real device evidence should include at least one successful read-only `--machine` command and one observed client/server divergence without destructive restart.

## Browser Auto semantic policy — 0.1.103 candidate

- PR [#499](https://github.com/whshang/herdr-mcp/pull/499) carries the current browser semantic-judgment candidate; it is development/candidate state until merged and released.
- Ordinary ChatGPT post-turn Auto has one fixed progressive policy: deterministic browser/runtime safety gates → TypeSafe Jev/System One when configured → OpenAI-compatible LLM judge when configured → bounded mechanical script fallback. Script fallback exists for users without either API and never overrides a semantic-provider decision.
- Goal-aware Auto reuses the existing Goal Supervisor. Jev supplies one bounded five-signal advisory prior (`can_continue`, `needs_human`, `waiting_external`, `task_completed`, `needs_handoff`); the LLM Supervisor may use that prior, while Work Memory/TODO evidence and deterministic guards remain authoritative for completion, waiting, handoff, human boundaries, generation fencing and uncertain delivery.
- Options exposes only endpoint/model/API key for Jev and the LLM provider. Semantic policy, probability boundaries, judge prompts and completion tokens are product-owned; startup removes the retired policy-control storage keys.
- The native Rust runtime now exposes a provider-neutral bounded semantic service. `TYPESAFE_API_KEY` makes the TypeSafe/Jev provider available; absence, timeout, HTTP failure, or malformed output preserves the previous behavior. The first consumers are planning task-profile enrichment plus Skill/private-method relevance ranking, and same-page Work Memory relevance ranking. Those results are advisory: they do not own permissions, delivery state, generation fencing, browser/account identity, idempotency, cleanup safety, or completion. Provider-specific code stays behind the `SemanticProvider` boundary so future fast-judgment models can be added without changing business-tool authority.
- Current candidate qualification: exact standalone Extension 0.1.103 UAT passed on MacBook Air; focused Jev + Goal tests 41/41, extension smoke/background bind and 34-case benchmark fixture passed. Real Goal-state UAT identified the then-running CI wait with `waiting_external=0.77` as the only Jev signal above the fixed 0.70 boundary, while `task_completed=0.09`; the configured LLM judge independently returned continue.
- No second scheduler, task database or planning authority is introduced.
