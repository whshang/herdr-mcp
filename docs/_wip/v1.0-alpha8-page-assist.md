# Herdr-MCP 1.0 Alpha 8 — Page Assist vertical

Status: implementation candidate on `feat/v1.0-extension-page-assist-alpha8-20260907`.

Base: Alpha 6 implementation HEAD `91fb8cdcc70d2d5b63c29c4423efb68c1fb0c433`. Alpha 7 Grok is developed in parallel in PR #346; Alpha 8 does not depend on Grok provider code.

## Goal

Add a bounded generic page-inspection and interaction vertical to the Herdr browser extension without turning Herdr into an unrestricted browser automation or script-execution surface.

Page Assist is intentionally narrower than a general browser driver. It exposes visible page text plus short-lived opaque element references, and permits only three typed actions:

- `inspect`;
- `click`;
- `fill`.

The design has two independent gates. A remote caller must hold an exact Connector Page Assist grant for the selected device/browser endpoint, and the local browser must have an explicit user-approved origin in Extension Options with the corresponding Chrome host permission. Either missing gate fails closed.

## Scope

Alpha 8 includes:

- explicit per-origin Page Assist configuration in Extension Options;
- dynamic, top-frame-only Page Assist content injection for `inspect` recovery;
- bounded visible text and interactable-element discovery;
- opaque generation-bound element references;
- typed `click` and `fill` using only refs produced by a prior inspection;
- sensitive-field exclusion and stale-ref/origin fencing;
- a Connector Page Assist caller grant stored inside the existing OAuth Connector grant record;
- an enrolled-owner CLI/REST mutation path for the exact `(client_id, device_id, endpoint_ref)` authority;
- Edge routing that filters grants to the explicitly selected device;
- trusted Edge → Link → runtime propagation over the existing Unix IPC trust boundary;
- regression coverage for extension behavior, owner-only grant mutation, grant normalization/revoke, routed grant filtering, TCP spoof rejection, and runtime actuation gating.

Alpha 8 does not include:

- arbitrary CSS selectors, XPath, JavaScript, `eval`, CDP, cookies, local/session storage, or caller-provided scripts;
- password, file-upload, one-time-code, or payment-card field interaction;
- cross-origin iframe traversal;
- automatic retries for `click` or `fill`;
- Tool Bridge consent changes or Control Center Tool Bridge UI;
- static `<all_urls>` access or a new always-on host permission;
- production Edge deployment from this Alpha 6-based branch;
- changes to the public Workstation epoch 2 / 18-tool contract, public Edge epoch 3 / 19-action contract, or SQLite schema v8;
- v0.4.8 Connector implementation changes.

## Local origin permission model

Page Assist is default-off because `pageAssistOrigins` defaults to an empty list. The extension manifest already carries broad HTTP/HTTPS patterns only as optional host permissions; Alpha 8 does not add an always-on broad host permission.

When a user saves Page Assist origins in Options, each entry is normalized to its exact HTTP/HTTPS origin and Chrome is asked for the corresponding origin pattern only, for example:

```text
https://example.com/*
```

Removing an origin removes the corresponding optional host permission when it is no longer required by another configured feature.

Before every Page Assist operation, the background worker verifies all of the following:

1. the requested origin is present in `pageAssistOrigins`;
2. Chrome reports the exact origin permission as granted;
3. the target tab still exists;
4. the target tab's current origin exactly matches the requested origin.

`content/page-assist.js` is not a static content script. If no listener is present, only `inspect` may perform one bounded isolated-world injection. `click` and `fill` never reinject and fail as `page_assist_unavailable` when the prior page context is gone.

## Inspection and opaque refs

Inspection reads bounded page-visible text and up to 128 interactable elements from semantic element families such as buttons, links, inputs, textareas, selects, textbox/checkbox roles, and content-editable controls.

It returns only bounded metadata:

```text
ref
role
type
text
```

It does not return selectors, DOM paths, XPath, arbitrary attributes, cookies, storage values, or executable page code.

Each inspection creates a new opaque generation token and an in-memory mapping:

```text
ref_<generation>_<index> -> DOM element
```

The mapping exists only in that content-script document. A successful `click` or `fill` invalidates the entire generation, so the same ref cannot be replayed. Navigation, listener loss, detached elements, changed origins, or a mismatched generation fail closed.

## Sensitive-field boundary

Inspection excludes hidden/disabled elements and the following input types:

- `password`;
- `file`;
- `hidden`.

It also excludes fields whose `autocomplete` token set contains:

- `current-password`;
- `new-password`;
- `one-time-code`;
- `cc-number`;
- `cc-csc`.

The same sensitive-field check is repeated before mutation. Cross-origin iframe execution is rejected. Alpha 8 does not provide iframe traversal or frame selection.

## Mutation semantics

`click` and `fill` require both the generation and ref returned by a prior inspection. They re-check origin, generation, element attachment, visibility, disabled/read-only state, and field sensitivity immediately before mutation.

`fill` accepts at most 10,000 characters. `inspect` defaults to 16,384 visible-text characters; the remote runtime contract caps caller-requested `max_chars` at 16,384.

There is no selector fallback, search-and-click fallback, script evaluation, reload retry, or automatic second mutation attempt.

## Remote caller authority

Page Assist authority extends the existing `OAuthConnectorGrantRecord`; it does not create a second OAuth authority store.

The grant is intentionally endpoint-scoped rather than origin-scoped:

```text
{
  device_id,
  endpoint_ref
}
```

Origin approval remains a local browser/user decision and is not copied into Edge authority. This creates an AND gate:

```text
remote Connector exact device+endpoint grant
+
local Extension exact-origin permission/configuration
```

A new Connector approval starts with `page_assist: []`. Legacy records normalize to the same empty default. Grants are deduplicated, bounded, and can be removed by the same owner path.

The enrolled-owner command is:

```text
herdr-mcp connector page-assist <allow|deny> <client-id> <device-id> <endpoint-ref> --confirm
```

The corresponding Worker route accepts only enrolled owner-device authentication. A generic MCP/operator bearer cannot widen this authority. A WebChat OAuth caller attempting `herdr_mcp.connector.page_assist.set` is rejected before workstation routing with `connector_owner_device_required`.

## Edge → workstation trust boundary

`herdr_mcp.page_assist` is a private workstation-routed method and requires an explicit enrolled device selector at Edge.

For a valid Connector call, Edge filters `page_assist` grants to the selected device and forwards only:

```text
page_assist_grants: [
  { endpoint_ref }
]
```

The Link serializes this authority into the reserved `x-herdr-edge-page-assist-grants` header only when dispatching through trusted local Unix IPC. Grant-bearing IPC also carries the expected runtime generation fence.

A bearer-authenticated TCP client cannot opt into Page Assist by spoofing the reserved header: TCP state ignores it. Trusted IPC validates the exact one-field grant shape and rejects malformed or widened tuples.

At runtime, `page_assist_call` rejects a request before browser actuation unless its `endpoint_ref` exactly matches one trusted caller grant. The extension then independently verifies that the command targets its current browser endpoint before applying the local origin gate and DOM operation.

## Acceptance

Local acceptance requires:

1. Page Assist is default-off and never statically injected;
2. exact user-configured origin permission is required for every operation;
3. inspection exposes only bounded visible text and opaque refs;
4. password/file/OTP/payment-card fields and cross-origin iframes fail closed;
5. `click`/`fill` require a fresh generation/ref and cannot auto-reinject or retry;
6. caller-supplied selectors/XPath/JS/CDP/cookie/storage controls are rejected;
7. Connector grants default empty, add/remove idempotently, and require enrolled-owner authentication;
8. WebChat callers cannot self-grant Page Assist;
9. Edge forwards only the selected device's endpoint grants;
10. TCP cannot spoof the reserved grant header and trusted IPC requires the runtime generation fence;
11. existing extension, Edge, Connector, and Rust regressions remain green;
12. `cargo fmt --check`, clippy with `-D warnings`, `cargo test --workspace`, `scripts/release-gate.sh node`, `scripts/release-gate.sh hygiene`, and `git diff --check` pass.

## Integration and real-browser UAT

Alpha 8 stays Draft after local qualification. It must not deploy this Alpha 6-based Edge bundle to production while v0.4.8 Connector work is active.

Before production UAT, the Page Assist remote-authority/Edge slice must be rebased or ported onto the stabilized v0.4.8 Connector caller-grant baseline and the combined Connector/Edge regression suite must pass. That integration must preserve the exact owner-device authority boundary and must not regress Connector approval/revoke semantics.

Real-browser acceptance then requires an explicitly user-approved non-sensitive test origin, a current browser endpoint, one owner-issued Connector Page Assist grant, and bounded `inspect` plus harmless `click`/`fill` verification. No production deployment, runtime activation, merge, tag, or release is part of this Alpha 8 implementation branch.
