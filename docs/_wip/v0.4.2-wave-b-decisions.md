# v0.4.2 Wave B evidence-backed decisions

Date: 2026-08-29

## Measured decisions

- The original three-sample production `scan --probe` set had a `3493.63 ms` maximum, so its `51.87 ms` median was not sufficient evidence to dismiss probe tail latency.
- Isolated cold-cache A/B on 22 Agent records measured sequential deep-probe median/p95 `2753.14/3648.92 ms` versus bounded-4 miss probing `2175.50/3047.39 ms`: about 21.0% median and 16.5% p95 improvement. Warm 22/22 cache-hit median stayed effectively flat (`171.43 -> 169.94 ms`). Keep bounded parallelism only on cache misses; keep deep probing explicit and off hot paths.
- Direct Git median is `7.79 ms`; direct rg median is `5.74 ms`. No broad direct-tool performance refactor is justified by this baseline.
- Largest bundled Skill payload is `21158` bytes / `183` lines. Current-version candidate MCP measurement reconfirmed the progressive advantage: 5,724-byte bootstrap versus 23,493-byte legacy tool text, with representative bootstrap+domain totals still 36.7%–69.1% smaller.
- **Progressive default-on: NO for v0.4.2.** The frozen epoch-2 public `herdr_skill` schema exposes `refresh` / `include_native_reference` and describes the legacy full response; the working `legacy_full` escape hatch is internal and absent from that schema. Making progressive the default would silently change the public default shape or require changing the frozen contract/hash. Keep `HERDR_MCP_PROGRESSIVE_SKILLS` opt-in in v0.4.2 and preserve the candidate for a future explicit contract migration.
- Independent audit evidence agrees with this boundary: PI returned `BLOCKED`; Grok independently identified the same public-schema/contract-hash blocker before its long-form audit was cancelled during cleanup. Neither audit modified the repository.

## Scope decisions

- Capability inventory change: `YES`, limited to cache-miss probes with a hard parallelism cap of 4; cache-hit and normal inspect/tool hot paths stay unchanged.
- Broad direct-tool refactor: `NO`.
- Progressive Skills feature: `KEEP OPT-IN`; default-on migration: `NO` for v0.4.2 because of the frozen public-contract blocker above.
- Agent/model single-sample latency is excluded from hard thresholds because provider/queue variance dominates. Dispatch quality is reviewed semantically for unnecessary delegation.
- Cleanup/observability changes require ownership evidence and bounded state; Wave A already established this invariant, so Wave B should avoid a second process-supervision redesign.
