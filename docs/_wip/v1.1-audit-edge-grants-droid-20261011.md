# Edge relay caller-grant forwarding security audit (2026-10-11)

Scope: `feat/v11-t9f-audit-droid-20261011` at `c44dc7cb`; static review of `edge/cloudflare/src` and the Rust Link/runtime grant handoff, with the browser-side endpoint check traced where needed. No code, service, deployment, or browser changes. Severity order: critical (0), high (1), medium (0), low (0).

## High

### [P1] [security] Bind relay idempotency replays to the authenticated caller and request

- **Evidence:** `edge/cloudflare/src/mcp-handler.ts:1233-1236` accepts a caller-supplied **top-level** `idempotency_key` for `herdr_call`, and `:1290-1314` forwards it separately from the connector identity, route, arguments, and page-assist grants. The handler validates the tool name and arguments object at `:567-589` but does not reject this additional key, even though the published `herdr_call` input schema lists only `method` and `params` (`edge/cloudflare/src/contracts/epoch2.ts:63-81`). `edge/cloudflare/src/workstation-do.ts:798-803` returns a previous mutating completion before delivering to Link/Rust; `:840-853` has a second replay path. Both call `edge/cloudflare/src/pending.ts:149-164`, which matches only the outer operation (`herdr_call`) and the key, not `resourcePrincipalRef`, connector/generation, page grant, endpoint, inner method, or arguments. That principal is used for capacity accounting (`workstation-do.ts:818-827`), not replay authorization. The replay window defaults to ten minutes (`edge/cloudflare/src/limits.ts:30-33`).
- **Impact / trigger:** An authenticated connector that knows or reuses a top-level key previously used by another connector on the same routed device can ask for a page-scoped `herdr_call` with no current Page Assist grant (or a different endpoint/inner method) and receive the other caller's cached result without reaching the Rust `caller_grant_missing` check. A connector whose Page Assist grant was revoked can likewise recover its own cached result. Browser observations, extracted text, or generated-operation results may contain sensitive content. The key must be known or collide; this does not enable arbitrary live browser actuation after revocation. This also affects non-page `herdr_call` results.
- **Suggested fix:** Scope the relay idempotency identity to the authenticated principal/connector generation, routed device, exact inner method and canonical request identity, and never replay a page-scoped completion unless the current grant for its endpoint is still authorized. Reject unrecognized top-level `herdr_call` fields if relay-level idempotency is not part of its contract. Preserve durable retry semantics for a genuinely identical authorized mutation.
- **Suggested test:** Through the authenticated Edge `tools/call` route and a real WorkstationDO replay ledger, settle a page-scoped `herdr_call` with a top-level key under connector A; then request with the same key under connector B (no grant), under A after exact-tuple revocation, and under A with a different endpoint/inner method. Assert no cached content is returned and unauthorized requests do not reach browser actuation. Assert a same-principal, same-grant, same-request retry returns its original completion.

## Verified boundaries and coverage

- **Connector and revocation:** The owner-device route authenticates before grant updates (`edge/cloudflare/src/index.ts:451-483`); the store mutates the exact connector/generation/device/endpoint tuple (`oauth-store-do.ts:860-933`). Every token verification reads the current active grant and filters by exact connector ID and generation (`oauth-store-do.ts:1610-1635,1673-1692,1707-1718`). A new request after revocation normally receives no Page Assist grant; the replay finding above is the exception for previously settled results.
- **Device and endpoint:** The Edge requires an explicit device for page-scoped calls (`mcp-handler.ts:1105-1125`), filters grants against that routed device (`:1217-1249`), and WorkstationDO checks the device execution fence (`workstation-do.ts:616-659`). Rust accepts grant headers only on trusted Unix IPC, rejects malformed grant arrays, and treats absence as empty (`crates/herdr-mcp/src/mcp_http.rs:2547-2559,2827-2864`; `crates/herdr-mcp/src/link/local_mcp.rs:385-411,617-622`). The page methods check `endpoint_ref` against the caller grants before actuation (for example `crates/herdr-mcp/src/mcp.rs:7985-8009`). Actuation targets the endpoint (`mcp_http/actuation.rs:304-323`); the extension also rejects page references belonging to a different endpoint (`extension/background.js:8389-8419`). The older `herdr_mcp.page_assist` dispatch checks the endpoint in the extension (`extension/background.js:3619-3628`).
- **Method inventory:** All nine methods in `edge/cloudflare/src/page-scoped-methods.ts:7-17` match the Rust `caller_page_assist_grants` dispatch sites (`crates/herdr-mcp/src/mcp.rs:365-417`): Page Assist, BrowserPage lifecycle/action/fast_path, Bilibili transcript, X search/thread, and Doubao generate/status. The `press` and `extract_table` names are not implemented as separate page-scoped runtime methods or BrowserPage action variants in this revision (`mcp.rs:8034-8043`; `extension/background.js:8371-8376`); there is no forwarding-list omission for them at this commit. The list-drift test is in `edge/cloudflare/tests/mcp-handler.test.mjs:1859-1874`.
- **Response/log surface:** The normal MCP forward log contains routing and grant-generation metadata, not grant tuples (`mcp-handler.ts:1316-1329`); the structured logger redacts credential-shaped fields (`edge/cloudflare/src/logger.ts:17-43`). The Edge relay returns the runtime completion/error, not the forwarding trace (`mcp-handler.ts:1475-1504`). The owner-only grant update response deliberately includes that connector's grants (`edge/cloudflare/src/index.ts:485-494`). No independent grant-value leakage was established.

Validation: Source-path and test-coverage inspection only. `npm run test:edge` was not run: this worktree has neither `node_modules` nor `edge/cloudflare/dist`, and the audit did not install dependencies or create build artifacts. No live revocation race, browser session, production service, or device was exercised.
