1. Designate **`feat/v11-webchat-app-activation-20261009` (`19416ae0`)** as the single branch for the one PR to `main`.

3. `#591` (T3) needs no retarget — it is already forked from the survivor; `#592` (T8) cannot be retargeted and must be
   **re-cut** on the survivor, because it forked from the retired branch.

   `needless_borrow`, and one non-conforming Grok test title. Both are identical on both heads, so choosing a branch
   does not fix them.
5. Merge `main` into the survivor before the final gate so the PR keeps `main`'s epoch-8 work, then run the full Rust,
   Node/Edge and Windows gates listed in §9.

## 5. Which branch is the single PR to `main`

**`feat/v11-webchat-app-activation-20261009` (`19416ae0`).** Reasons, in order of weight:

1. **Its tree is a strict superset.** `git diff --numstat W O` is exactly `0 2 docs/herdr-architecture-roadmap.md` with
   no added or deleted file. Everything `O` has, `W` has byte-for-byte; `W` additionally carries the 2026-10-10
   Phase 1/2 roadmap record. A PR from `W` therefore delivers the union of both branches with **zero commits carried**.
2. **Retiring `O` discards less distinct authored history.** By patch-id, `W` is unique on 16 commits and `O` on 5,
   and all 5 `O`-only commits are twins of commits `W` already has. Retiring `O` discards no unique content; retiring
   `W` would discard 16 patch-unique commits.
3. **`O`'s only distinguishing property is a loss.** Its differentiator is the two missing roadmap lines, an artifact
   of a cherry-pick that dropped one hunk of `17f5d0ef`. Keeping `W` preserves the record without adding a restoration
   commit; keeping `O` requires manufacturing one.
4. **Neither branch has a proximity advantage to `main`** (§4), so the usual "the branch with the smaller diff wins"
   tie-break does not apply.

The one real cost of this choice is administrative: `O` is the head of draft PR **#587**, so retiring `O` means closing
`#587` and opening the equivalent PR from `W` to `main`. `#587` holds 12 comments and 0 reviews. §11 records the
mirror option for a team that values that thread more than the two-line record; it is not recommended, because it
solves a bookkeeping problem by adding content debt.

renders exactly T3's 7 commits. **Retarget: none.** Its base has simply advanced 12 commits since the fork

overlap between T3's changes and W's post-fork changes is **empty**, so the refresh should be conflict-free:

```bash
comm -12 <(git diff --name-only 7a07abdd T3 | sort) <(git diff --name-only 7a07abdd W | sort)   # → no output
```

`#592` (T8) **cannot be fixed by retargeting.** `git merge-base W T8` = `01f9e1e9`, so a base change from `O` to `W`
would make the PR display **58** commits, i.e. the whole duplicate opencli lineage, as if it were new work. Treat it
as a **re-cut**, not a retarget:

1. Branch afresh from the survivor: `git switch -c feat/v11-t8-opencli-parity-recut <W>`.
2. Cherry-pick the two T8 commits only — `7a913e2b` ("feat(browser): add bounded single-key press action") and

## 8. Blocking defects that must be fixed before any gate can pass

Both heads fail CI **identically**, because the responsible blobs are byte-identical on `W` and `O`. Choosing a
survivor does not fix either one.

Evidence: CI run `38130881387` (workflow `CI`, head `feat/v11-opencli-browser-controls-20261008`, PR #587) —
`rust` **FAILURE** (28s), `test` **FAILURE** (10s), `windows` success (9m4s), Deno relay build success. `main`'s CI is
green, so these are branch-introduced, not toolchain drift.

1. **`crates/herdr-mcp/src/mcp.rs:4124` — clippy `needless_borrow`, fatal under `-D warnings`.**

   ```
   error: this expression creates a reference which is immediately dereferenced by the compiler
       --> crates/herdr-mcp/src/mcp.rs:4124:62
   4124 |     let source_reference = browser_composer_source_reference(&source_url);
   ```

   Introduced by `053f0212` ("Reference ChatGPT source conversations by id in handoff composer text"). The symbol does
   not exist on `main`, so the error is branch-introduced. Blob `mcp.rs` = `3bf0314172eb8fc8074b1ec227a1862727a5c2b8`
   on **both** heads. Fix is to drop the `&`.
2. **`tests/grok-adapter.test.mjs:140` — new-test title policy violation.** The single violation reported by the
   `test` job:

   ```
   test-policy: FAIL
   - tests/grok-adapter.test.mjs: new test title must start with "user " and describe Given / When / Then in order:
     Grok idle composer is not busy when only an unrelated page region is aria-busy
   ```

   Introduced by `5baf4ccd` ("Grok: count aria-busy only on the latest assistant turn"). Blob
   `tests/grok-adapter.test.mjs` = `7008c6d52ea3930f80c63e06f21f013788289fb4` on **both** heads. The title must be
   rewritten as `user <outcome> | Given ... | When ... | Then ...`. Re-checked for the full `main..W` range: exactly
   **one** title violation and **zero** mocking-API violations, so this rename is the whole fix.

`main`-only workflows are not PR gates: `rust-release`, `rust-release-recover` and `extension-store` never run on a
pull request, and `cloudflare-edge` (`Cloudflare Edge production`) declares only `push` to `main` (with `paths`) and

`select-ci-tests.mjs` read `HEAD` against the PR's **base sha**: retargeting a stacked PR changes that sha, so a
"passing" stacked PR can fail after a retarget even with an identical tree.

## 10. Risks

1. **Two blocking failures are shared, not branch-specific.** The clippy error and the Grok title fail on both heads
   (§8). Any plan that "merges the good branch" without fixing them merges a red branch. Both fixes are small but are
   code/test changes, outside this document's scope.
2. **`main` has moved and the twins predate PR #588.** `edge/cloudflare/src/contracts/epoch8.ts` is PRESENT on `main`
   and **ABSENT** on both twins; `edge/cloudflare/src/contracts/public.ts` references epoch 8 on `main` and epoch 7 on
   both twins. A PR that does not merge `main` into the survivor risks presenting an epoch-7 regression. Merge `main`
   first and confirm the roadmap epoch bullet and the contract file after the merge.
3. **Concrete merge-conflict surface from `main`.** Of the 27 paths `main` changed since the fork, four overlap the
   twins' changed paths. Two are byte-identical to `main` and will not conflict —
   `edge/cloudflare/src/mcp-handler.ts` (`d6adf867`) and `edge/cloudflare/src/page-scoped-methods.ts` (`7110e6f4`) —
   because the twins independently carry patch-identical copies of PR #589's fix. Two genuinely differ and must be
   reconciled: `edge/cloudflare/tests/mcp-handler.test.mjs` (`main a1a99826` vs `W 16388928`) and
   `tests/relay-edge-compat.integration.mjs` (`main 3a8a63bb` vs `W 9a381951`). `docs/herdr-architecture-roadmap.md`
   also overlaps, but `main`'s edits are at the epoch bullets while `W`'s are the 2026-10-10 paragraph, so the hunks
   are disjoint.
4. **Duplicate content already on `main`.** `777b285f` ≡ branch `57aac7cd` and `1d0e8a27` ≡ branch `45cdfa61` are
   the same patches on both sides. Merging is normally clean for identical changes, but any version bump or line the
   two paths touch slightly differently in future re-opens the duplication hazard. Verify the extension version and
   the runtime tool count after the merge rather than trusting a conflict-free result.
5. **`#592` cannot be retargeted; a naive base change fabricates 58 commits of diff** (§7). Its 8-path conflict
   surface against the survivor makes a silent regression plausible, so the re-cut needs the §9 gates plus an explicit
   manifest/tool-count check.
6. **`#591` is 12 commits behind its own base.** `W..T3` = 7 and `T3..W` = 12; the PR is currently stale against the
   survivor. Path overlap is empty, so conflict risk is low, but CI must be re-run after the refresh and the
   `extension/manifest.json` version field must be re-checked (both the refresh and T3 touch it).
7. **Closing `#587` loses a discussion thread.** 12 comments, 0 reviews. No reviews are lost. Carry a link to the
   closed PR in the new PR description.
8. **Losing the roadmap paragraph is a silent documentation regression.** If anyone consolidates toward `O`, the
   2026-10-10 Phase 1/2 DEV record disappears from the roadmap. It survives only in
   `docs/_wip/v1.1-browser-adapter-platform.md`, which both heads already have. Prefer the survivor that keeps both.
9. **Extension version is identical on both twins (`0.1.191`, blob `5b008e82`).** There is no conflicting double bump
   between them, but `main` is at `0.1.133`, so the PR carries a very large version jump from `main`'s perspective.
   Confirm this is intended before the release lane reads it.
10. **The stack, not just the branch, needs retiring.** `#583` and `#585` target non-`main` bases and are fully
    contained in both twins. The single PR subsumes them; leaving them open risks someone retargeting one of them to
    `main` independently and re-creating the duplicate-lineage problem this plan exists to remove.

## 11. Rejected alternative (recorded for completeness)

Mirror choice: keep `O` (`c44dc7cb`) as the single PR, retire `W`, and carry the two roadmap lines as one new commit
reconstructed from the docs hunk of `17f5d0ef`.

- `#591` (T3) would have to be retargeted from `W` to `O`; `#592` and `#587` would keep their bases apart from
  `#587`'s base being changed to `main`.
- Advantage: `#587` (12 comments) survives as the PR of record, and only one stacked PR needs re-cutting instead of
  two re-cuts plus one PR closure.
- Why rejected: it is a strict superset/order inversion. `W` already contains every byte `O` has, so this option
  discards 16 patch-unique commits to preserve a review thread and then adds a manufactured commit to restore
  documentation that was never lost on the retained branch. It trades content debt for bookkeeping convenience. It is
  viable only if the team's binding constraint is preserving `#587`'s discussion, which §10.7 argues it is not.

- Analysis used read-only git only: `rev-parse`, `merge-base`, `merge-base --is-ancestor`, `rev-list --count`, `log`,

  was performed: no merge, rebase, cherry-pick, force-push, branch deletion, PR open/close/retarget, release,
  deploy, or tag.
- Non-goals: code or test changes (including the two blocking fixes in §8), browser/ChatGPT calls, PROD or runtime
  surfaces, and any change to `W`, `O`, `#583`, `#585`, `#587`, `#591` or `#592`.
- All facts above were captured on 2026-10-11 against the pinned revisions in §1. Re-run the commands before acting;
