# Herdr-MCP 1.0 Alpha 9 — Toolchain Efficiency

Status: active implementation stage.

Sequence: Alpha 8 Page Assist -> **Alpha 9 Toolchain Efficiency** -> Beta 1 reliability/postcondition.

Implementation branch: `perf/v1.0-exec-json-compaction-20260908`.

## Goal

Reduce user-visible latency, local process/IO overhead, repeated control-plane work, and model round trips across the existing MCP toolchain without weakening managed-root, secret-path, dirty/busy, delivery, generation, or idempotency safety.

Alpha 9 is a runtime/toolchain stage. It does not add user-facing WebChat capability. It exists before Beta 1 so reliability/postcondition work starts from the lighter execution path rather than stabilizing avoidable utility-pane and repeated-state overhead.

## Entry and merge boundary

- Alpha 9 implementation may proceed from the current Alpha 8 + v0.4.8 integration source boundary while Alpha 8 finishes isolated real-browser UAT.
- Alpha 9 must not merge ahead of the accepted Alpha 8 integration boundary.
- Existing `perf/v1.0-exec-json-compaction-20260908` work is reused; do not open a duplicate performance worktree.

## Non-goals

- no new MCP tool solely for performance;
- no second executor, queue, scheduler, daemon, or compatibility implementation;
- no broad API batching until measurements show model-visible contract changes are justified;
- no weakening of fail-closed routing or mutation ownership;
- no test-framework expansion;
- no Beta 1 late-settlement/reload-postcondition behavior in this stage.

## Acceptance

1. all existing epoch-2 tools receive a concrete efficiency disposition;
2. repeated Git/topology/schema/snapshot work is removed where existing cached/live state is authoritative;
3. short non-interactive shell work uses the lightest existing execution backend;
4. long/network work remains durable and incrementally readable;
5. before/after measurements cover the paths changed, and changes with no demonstrated benefit are dropped;
6. the public tool count/contract stays unchanged unless a later explicit contract decision proves otherwise;
7. Alpha 9 exits with focused existing tests plus the normal Rust gate for touched runtime code, without building a new benchmark/test framework.

## Priority work

### P0 — make native-default exec an explicit 1.0 contract evolution

Observed 0.4.8/1.0 behavior: synchronous `herdr_exec` normally prepares/reuses `herdr-mcp:utility`, writes a mode-0700 temporary `herdr-mcp-pane-exec-*.sh`, creates stdout/stderr/status spool files, sends `zsh <script>` through `pane.send_text`, then monitors the operation. This is robust for terminal delivery but imposes pane RPC, filesystem sync/spool, an extra shell launch boundary, and polling overhead on very short commands. The visible pane also mostly shows the wrapper script path rather than the actual command.

The repository already has the required lighter executor: `ExecRegistry::start_native` is used by `herdr_exec_start`, with cwd/PATH, stdout/stderr pipes, pid/process-group ownership, durable session state, restart fencing, incremental reads, kill, and final exit evidence.

The frozen epoch-2 catalog explicitly describes `herdr_exec` as running in the persistent **VISIBLE utility pane**, and the contract hash covers all supplied tool metadata including that description. A native-default implementation under the old hash would therefore be a contract violation even if the tool name and JSON schema stayed unchanged.

1. Do not silently change `herdr_exec` execution semantics under the epoch-2 hash.
2. Treat native-default `herdr_exec` as a deliberate 1.0 Runtime Execution contract evolution: update runtime contract identity/hash and Edge/runtime compatibility together, while keeping the same tool name and argument surface unless measurements prove another change necessary.
3. In the evolved contract, reuse the existing native `ExecRegistry` for ordinary non-interactive execution. Keep the public semantic distinction at the wait boundary: `herdr_exec` = start + bounded synchronous wait; `herdr_exec_start` = start + return session id immediately.
4. Retain the pane backend for cases that genuinely require a TTY, explicit human interaction/visibility, or macOS protected-path/TCC behavior that cannot safely use the native/stable-broker path.
5. Do not add another executor abstraction. Reuse the current backend selection and session registry.
6. Measure short-command wall time and local filesystem/RPC operations before and after. Representative probes: `pwd`, `git rev-parse HEAD`, `git status --short`, bounded `rg`.

### P1 — finish producer-side result compaction already in flight

Complete and verify the existing JSON/result compaction work in this branch. Keep it only where payload reduction is material and CPU cost is proportionate. Remove benchmark-only scaffolding from production tests after measurements are captured unless it protects an accepted behavior.

### P2 — remove repeated state derivation before adding new concurrency

Continue the existing performance work already documented in `docs/history/architecture/tool-performance-optimization.md`: reuse project topology, managed-root validation, EventCache/snapshot state, method schema cache, and Git facts instead of recomputing them within one request/wave. The optimization target is fewer operations, not merely parallel execution of duplicate operations.

### P3 — model scheduling remains part of the performance system

Maintain the current policy: inspect once, issue independent read-only operations as a wave, keep mutations ordered by default, start long/network operations once, and use `herdr_since` / `herdr_exec_read` incrementally. Do not add a server batch contract until measurements show the remaining model round trips dominate after P0-P2.

## Existing tool audit

The audit covers the current 18-tool epoch-2 workstation contract. `herdr_devices` is Edge-local fleet inventory and is reviewed separately below because it is outside the 18 workstation-routed tools.

| Tool | Current efficiency disposition | Alpha 9 action |
| --- | --- | --- |
| `herdr_methods` | Live schema reflection is cached for 60s; repeated discovery remains avoidable model/RPC work. | Keep schema cache/prewarm; do not rediscover known methods. Consider compact/exact lookup only if payload measurements justify contract change. |
| `herdr_inspect` | Broad result can be expensive; EventCache fast path already exists. | Keep cache-first snapshot; avoid full reconcile/Git enrichment unless stale or requested. Reuse one baseline per planning wave. |
| `herdr_call` | Generic escape hatch pays validation/schema lookup and can encourage repeated low-level calls. | Reuse cached schema and prefer dedicated tools for common fs/git/exec/agent paths. No generic batch yet. |
| `herdr_since` | Correct incremental primitive; duplicate state events and broad workspace payload can waste bytes. | Preserve coalescing/workspace filtering; add compact/max-events only if evidence shows current payload remains material. |
| `herdr_fs_read` | Native direct file IO is already the right path; topology/security validation can dominate small reads. | Reuse managed-root/topology state; do not run unrelated Git status. Keep bounded range/byte reads. |
| `herdr_fs_list` | Native traversal is appropriate; recursive metadata work can grow quickly. | Keep bounded traversal; avoid metadata/stat work not needed by requested output. No new listing API. |
| `herdr_fs_grep` | `rg` fast path is preferable when available; fallback must remain safe. | Benchmark Rust walker vs `rg`; use `rg` fast path where it wins, preserving bounded safe fallback. Avoid repeated scans for equivalent patterns. |
| `herdr_fs_image` | Direct managed-root read is appropriate; image bytes dominate. | Keep metadata cheap and avoid extra topology/status work. Thumbnail/metadata variants only with demonstrated transfer benefit. |
| `herdr_fs_edit` | Exact replacement is cheap; dirty/busy/root checks can repeat across a sequence. | Reuse topology/busy state per request; target-file dirty check only. Prefer `herdr_fs_patch` for coherent multi-file mutations. |
| `herdr_fs_write` | Atomic direct write is appropriate. | Same routing/check reuse as edit; no extra abstraction. |
| `herdr_fs_patch` | Best existing primitive for coherent multi-file edits; repeated per-file validation can be optimized internally. | Validate root/topology once and combine dirty-file queries while preserving per-target containment/safety. |
| `herdr_git` | Dedicated native Git path is correct; redundant project status/enrichment is the main overhead risk. | Ensure requested Git operation executes once and managed-root routing does not separately run full-repo status. Keep compact large outputs. |
| `herdr_exec_start` | Native durable session path is structurally correct. | Keep as the long/network execution primitive; reduce routing/busy overhead and preserve immediate return. |
| `herdr_exec_read` | Incremental API is correct; rereading offset 0 and internal clone/flatten work are wasteful. | Optimize direct offset reads and avoid rebuilding full history. Multi-session read only after measurement proves need. |
| `herdr_exec_kill` | Low-frequency, already narrow. | Keep simple; only remove unnecessary registry prune/state work if profiling shows it. |
| `herdr_exec` | Default utility-pane + temporary script/spool path is too heavy for ordinary short non-interactive commands, but epoch-2 metadata explicitly promises that visible-pane behavior. | **P0: native-default requires an intentional 1.0 Runtime Execution contract identity/hash transition; do not hide it under epoch 2.** |
| `herdr_prompt` | Earlier before/after probes and fixed sleep created avoidable latency; current path already moved toward response-state + bounded fallback. | Finish removal of redundant probes; use fire-and-forget + event/since evidence. Do not poll Agents through repeated full inspect. |
| `herdr_skill` | Large policy body can be expensive but is intentionally once-per-session/cached; repeated calls waste context. | Keep once-per-session/cache semantics; make live context compact and avoid appending unused native reference. Do not fragment policy into another runtime layer. |

### Edge-local `herdr_devices`

`herdr_devices` stays Edge-local and read-only. It should answer from already-maintained fleet/routability state without contacting every workstation. Keep payload bounded and do not introduce per-device health probes into an ordinary list call.

## Implementation order

1. Finish and simplify the already-started JSON/result compaction slice in this branch; retain it only when measurements justify the CPU cost. Table compaction remains string-valued and only accepts conservative scalar rows; unsafe large numeric literals and nested values stay raw.
2. Implement P0 only as an explicit 1.0 Runtime Execution contract evolution, changing contract identity/hash, Edge/runtime compatibility, and backend behavior together.
3. Re-measure the 18-tool paths and implement only remaining repeated-state hotspots with evidence.
4. Run the normal Rust validation for touched runtime code and record the accepted before/after evidence.
5. Evaluate model-visible batch/compact parameters only after the above. Keep them out when the remaining cost is insignificant.

## Exit gate to Beta 1

Alpha 9 is complete when the in-flight compaction slice is either accepted or removed on measurement evidence, native-default P0 either lands through an intentional 1.0 Runtime Execution contract transition or remains unshipped, the 18-tool audit has no unreviewed P0/P1 efficiency item, and the relevant existing tests and Rust gate pass. Beta 1 then owns reliability/postcondition behavior on top of this execution baseline.
