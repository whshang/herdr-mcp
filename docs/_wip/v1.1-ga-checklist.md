1. `crates/herdr-mcp/src/macos_permissions.rs`：受保护路径探测槽位只有一个布尔量，无法区分「仍在预算内正常执行」与「已超预算仍挂起在 TCC / system 调用里」。并发调用者见到 `swap(true) == true` 即零等待返回 `None`，被 fail-closed 判成 TCC 受保护目录，于是普通临时路径的 `run_durable` 改走 `utility_pane`；同一文件的 `canonicalize(home)` 对 `NotFound` fail-closed，在 HOME 指向尚未创建的目录（安装/并发测试的常见状态）时同样把普通路径判成受保护。修复把槽位改为 `ProbeSlot` 状态机（`Idle` / `Running(generation)` / `Parked(generation)`）+ generation：`Parked` 立即返回、不派生第二个 worker；`Running` 时并发调用者在自身剩余 budget 内等待后接力；迟到的 worker 不会释放新持有者的槽位；`HOME` 不存在（`NotFound`）时不再 fail-closed，HOME 存在但无法解析（权限 / TCC）仍保持 fail-closed。
2. `crates/herdr-mcp/src/utility_exec.rs`：`native_test_dir()` 原名 `herdr-native-exec-<pid>-<millis>-<seq>`，在 macOS 默认 `/var/folders/.../T/`（49 字节）下拼 `missing-herdr.sock` 达 **106 字节（+NUL = 107）**，超过 `sockaddr_un.sun_path` 的 104（含 NUL），socket 错误断言因此退化为 bind 失败。修复改为十六进制短名，并在 helper 内断言两个 socket 路径均 **≤ 92 字节**（104 减 NUL 留余量）。
