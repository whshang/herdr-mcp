## Step 4 — PROD 回滚验证与再次升级（需 Owner 明确批准；macOS 独立终端执行）

1. `herdr-mcp rollback`：确认重新激活上一已安装 generation（如 rc.15 的
   `rust-cbad5ce77ca06ce6`），并核对 `service status`、本地健康、contract epoch / tool
   count 与回滚状态。回滚不重建二进制，也不恢复数据库。
2. 若 schema 已前移到 16 且需要回到 schema 15 的二进制，必须先恢复 Step 2 的 state 备份，
   否则旧二进制拒绝打开数据库。
3. 再次 `herdr-mcp update` 回到 `v1.1.0`，确认 Step 3 的全部健康指标恢复。
4. 记录两次切换的 generation、SHA 与时间戳；只在 macOS 声明该回滚路径，Linux 不写入成功
   后的 service rollback 记录，不承诺此路径。

## Step 6 — 验收声明模板（Performance / Rollback / Real-usage / Not run）

```text

回滚测试（Rollback）：
  - 已执行：<rollback 命令 / 目标 generation / 验证字段>，或「不适用：<原因，例如纯文档改动，revert 即恢复>」

真实使用验证（Real-usage verification）：
  - 在 <主机 / 版本 / generation / 扩展版本> 上用真实入口执行了 <命令或流程>，观察到 <可复核结果>
  - 未在真实入口执行时写「不适用」并说明替代证据（单测/CI 不能替代实机验收）

未运行（Not run）：
```
