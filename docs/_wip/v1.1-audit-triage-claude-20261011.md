## Finding 7 — handoff preparation does not bind a stable idempotency key

**Grok severity:** Medium

**Verdict:** Partially confirmed — every cited fact is accurate, but the stated impact is overstated because the canonical CLI delivery path already binds a stable key.

**Evidence verified:**

- `crates/herdr-mcp/src/mcp.rs:4117-4123` — `handoff_id` is `hh_` + a sha256 digest of `continuity_id`, `source_url`, `objective`, `work_chain_id` unless the caller supplies one. Stable across retries. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:4152-4160` — `automatic_delivery.params` = `source_url`, `message`, `work_chain_id`. No `idempotency_key`. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:4164-4169` — `existing_session_delivery.params` = `message` only; no `idempotency_key`, `session_ref`, or `expected_generation`. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:5606` and `mcp.rs:5655` — `SessionCreate` and `DispatchSubmit` both call `browser_required_idempotency_key`; a body lacking the key is rejected. Confirmed.
- `crates/herdr-mcp/src/state_store.rs:4708-4735` — an existing dispatch row under the same key digest with any differing field (target session, request/message digest, apps, generation, caller, work chain, lane) is `browser_dispatch_idempotency_conflict`. Confirmed.
- **Missed mitigation:** `crates/herdr-mcp/src/local_agent_cli.rs:455-471` — the canonical local-agent entrypoint (`herdr-mcp webchat handoff`) does not replay the packet verbatim: it sets `idempotency_key` to the caller's key or falls back to `prepared.handoff.handoff_id` before calling `browser_session.create`. The replay test at `local_agent_cli.rs:1143-1152` asserts both attempts send byte-identical create params (`calls[0] == calls[1]`) and settle as `replayed: true`. The guidance text at `local_agent_cli.rs:554` also instructs key reuse for retries.

**Residual gap (real but narrow):** a caller that consumes `herdr_mcp.browser_handoff.prepare` directly over MCP and mints a fresh key per attempt gets no packet-level binding — two conversations / double append are possible, exactly as Grok describes. The `existing_session_delivery` packet additionally cannot be executed verbatim because `dispatch.submit` hard-requires `session_ref` and `expected_generation` (`mcp.rs:5650-5655`), so it is a template by construction.

**My severity:** Low — the supported handoff path (CLI) is idempotent today; the gap binds only direct MCP consumers who ignore the documented key-reuse instruction.

**Recommended action:** Defer — add `idempotency_key: <handoff_id>` (and `session_ref`/`expected_generation` where the route is known) to both delivery packets as cheap packet hardening; it removes reliance on caller discipline but fixes no live defect.

## Finding 8 — learned apps and pill-only composer state disagree with the Rust app list

**Grok severity:** Medium

**Verdict:** Confirmed — all three bullets reproduce; two wording slips noted below do not change the substance.

**Evidence verified:**

- `extension/content/wake.js:2340-2344` — the browser-actuation path builds `requiredApps` as a union `[...new Set([...observedHerdrApps, ...requestedApps])]` for ChatGPT. Confirmed. (Precision: `wake.js:1291-1299` in `performWake` is a fallback chain `explicit || learned || observed pills`, not a union; the union is the 2342-2344 line, which is the path MCP create/dispatch actually take.)
- `extension/content/wake.js:1036-1037` — `ensureRequiredComposerApps` returns `apps: ADAPTER.getSelectedComposerApps()`, i.e. every selected pill in DOM/insertion order (`extension/content/injector/chatgpt.js:120-130`), so a superset is reported as readback. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:2319-2334` — `browser_required_apps_match_evidence` returns `Ok(true)` immediately when the requested list is empty, otherwise requires equal length and element-for-element equality against the Rust-sorted requested list. Confirmed (`mcp.rs:2325-2326` empty-skip is the same fact Grok cites under finding 4).
- `extension/content/base.js:113-120` — `inputHasContent` is true when the editor's `innerText` is non-empty; the ChatGPT adapter does not override it, and pills live inside the ProseMirror editor (`chatgpt.js:124` queries them inside `getInputEl()`), so a leftover pill counts as content. Confirmed.
- `extension/content/wake.js:2403-2412` — the actuation busy gate is `ADAPTER.inputHasContent()` with no `composerHasOnlyAppPills` bypass (unlike `performWake`'s own gate at `wake.js:1306-1309`), so a composer holding only automation pills returns `browser_create_composer_busy` / `browser_dispatch_composer_busy`. Confirmed.
- `extension/content/wake.js:2458-2466` with `clearAutomationDraft` at `wake.js:891-905` — failure cleanup clears only draft text; the comment states "App pills ignored" and the implementation never removes pills. The app-selection failure return at `wake.js:2417-2426` does not clean up at all. Confirmed: one failed app selection can leave a pill that blocks all later create/dispatch actuations on that tab.
- `crates/herdr-mcp/src/mcp.rs:6274-6278` — requested apps are sorted, then **duplicates are rejected** (`apps.len() != items.len()` → `browser_required_apps_invalid`), not silently deduped as Grok worded it. Immaterial to the finding: the sorted, exact-order compare at `mcp.rs:2328-2333` is what the extension readback must satisfy.

**Impact check:** the union→superset→`Uncertain` chain requires a non-empty requested list that differs from the learned keyword. `currentHerdrRequiredApps()` (`wake.js:3346-3349`) yields at most the single registered keyword today, so with only the `herdr` app the mismatch is latent (requested `["herdr"]` unions to itself; empty requested skips the Rust check entirely). The pill-lockout half is live now. Grok's Medium holds overall because the lockout is a real availability defect and the union path is the exact surface finding 4's late acceptance then undermines.

**My severity:** Medium.

**Recommended action:** Fix now — the busy-gate half is a small targeted fix (let the 2403 gate accept `composerHasOnlyAppPills` state, and clear unexpected pills on selection failure); the readback half (requested-set readback, no union) should be folded into finding 4's rework of app-gate ownership.

## Finding 9 — failure evidence and logs can carry composer/DOM detail; cookies and access tokens do not

**Grok severity:** Low

**Verdict:** Confirmed — including the negative result (no credential exposure found on this path).

**Evidence verified:**

- `crates/herdr-mcp/src/mcp.rs:4616-4627` — the non-applied terminal create response returns `delivery_evidence: evidence.result` verbatim, with no allowlist. Confirmed.
- `extension/content/wake.js:2421-2425` — a rejected app selection places `app_selection_probe` on `evidence.result`, which reaches the passthrough above. Confirmed.
- `extension/content/injector/chatgpt.js:264-346` — the probe carries `inline_mention_names` (app keywords), `inline_mention_paths` (sanitized, ≤80 chars, `[a-z0-9_.:/-]`), `exact_keyword_ancestor_chain` (tag|role|testid), `exact_keyword_form_chain` (attribute names, ≤3 class tokens), and `editor_nodes` (tag, attribute names, sanitized data-attribute values). Confirmed as "DOM structure and app identifiers". No draft or page prose text is included — the only text-derived fields are equality booleans against the keyword (`kw`, `label=kw`), consistent with the probe's own doc comment (`chatgpt.js:260-263`).
- `crates/herdr-mcp/src/mcp.rs:3697-3736` — the uncertain-reconcile path forwards only allowlisted boolean/count keys and explicitly echoes no provider strings. Confirmed: the intended allowlist exists and simply is not applied on the `mcp.rs:4626` path.
- `extension/content/wake.js:435` — `console.warn` logs the first 30 characters of the inserted text on retry. Confirmed.
- `extension/background.js:10224` — the `h2w_insert_main` result includes `text: got.slice(0, 40)` (first 40 chars of the composer). Confirmed, with a nuance: no consumer reads `.text` (`wake.js:438-439`, `972-979` use only `.ok`), and the value never leaves the extension-internal `chrome.runtime` channel, so this is dead diagnostic data rather than an active disclosure.
- `extension/content/wake.js:4068-4089` and `3863-3885` — the access token is fetched into a local, used only as an `authorization: Bearer` header, bounded in length, and failures return fixed reason tokens (`auth`, `http-<status>`, `timeout`); not written to evidence, storage, or logs. Confirmed.
- `extension/content/wake.js:5919-5987` — the HUD `shadow.innerHTML` template is fully static (fixed style and skeleton, no interpolation). Confirmed. `composer_busy_probe` (`wake.js:1701-1719`) is booleans/counts only and is allowlisted again on the Rust side (`mcp.rs:2273-2293`), so the probe is the only string-bearing object on the refusal path.

**My severity:** Low — disclosure of page structure and app identifiers to the MCP client that already drives that page; hygiene, not a boundary break.

**Recommended action:** Fix now — routing `mcp.rs:4626` through the existing `BOOL_KEYS`/`COUNT_KEYS` allowlist is mechanical, and the 30/40-character log/message trims are one-liners.

## Finding 10 — an actuation throw is reported as command accepted

**Grok severity:** Low

**Verdict:** Confirmed — including Grok's nuanced impact framing (avoids duplicates, blocks clean retry).

**Evidence verified:**

- `extension/content/wake.js:2913-2923` — the `h2w_browser_actuation` `.catch` answers every throw with `{ ok: false, evidence: { ...browserActuationEvidence(...), command_accepted: true } }`, with no submit-attempted distinction and no error token. Confirmed verbatim.
- `crates/herdr-mcp/src/mcp.rs:2428-2431` — `command_accepted: true` with unmet postcondition settles `Uncertain`. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:4501-4513` — session create flips the reservation to `Uncertain` before actuation, so a throw before Enter lands on an already-uncertain row. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:2303-2317` and `4560-4565` — the only path back to `NotApplied` requires `!command_accepted` plus `message_submitted: false` plus `retry_safe: true`; the catch's `command_accepted: true` makes that unreachable. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:4475-4485` — a same-key replay of an `Uncertain` reservation goes to reconcile, not actuation; since nothing was sent, reconcile cannot promote, so the create key is consumed with no delivery. Confirmed.
- `crates/herdr-mcp/src/mcp.rs:2565-2576` — dispatch pre-claims `Uncertain` inside the store lock before any browser command; for dispatch the extension catch merely widens what the runtime already assumes. Confirmed.

**My severity:** Low — availability of a clean retry only; the fence errs in the safe direction (no duplicate provider mutation).

**Recommended action:** Defer — the fix needs a submit-attempted stage signal threaded from `performBrowserActuationCommand` through the extension→runtime evidence contract, plus cross-component coverage; bundle it with the finding 1–3 submit-path rework rather than patching the catch in isolation.

## Things Grok missed (noticed during verification)

1. **Canonical-CLI mitigation for finding 7** — `local_agent_cli.rs:455-471` already injects the stable `handoff_id` as the create `idempotency_key`, with a replay test asserting identical params across attempts (`local_agent_cli.rs:1143-1152`). Not a bug; it lowers finding 7's real-world severity.
2. **`ensureRequiredComposerApps` can reject with no error token** — the terminal return at `wake.js:1036-1037` computes `ok` but never sets `error`; if it fires (e.g. the provider drops a previously selected pill during multi-app selection), the rejection evidence at `wake.js:2421-2425` carries no machine-readable reason and the Rust side reports a missing/unknown machine reason. Narrow trigger, fixed-vocabulary contract hole. Low.
3. **Ordered multi-app readback can mismatch the Rust compare** — `mcp.rs:2328-2333` compares element-for-element against the Rust-sorted requested list, while the extension readback is `getSelectedComposerApps()` DOM/insertion order (`chatgpt.js:120-129`) and selection runs in union order (`wake.js:2342-2344`). A correct two-app selection can stay `Uncertain` purely on ordering. Latent while only the single `herdr` app exists. Low; adjacent to finding 8 but distinct from its superset point.
4. **Factual correction to finding 8's evidence** — `mcp.rs:6274-6278` rejects duplicate `required_apps` entries; it does not sort-and-dedupe as written. Immaterial to the conclusion.
5. **`h2w_insert_main`'s `text` field is dead data** — `background.js:10224` returns a 40-char composer prefix that no consumer reads (`wake.js:438-439`, `972-979` check `.ok` only); it can be dropped outright rather than merely truncated.
